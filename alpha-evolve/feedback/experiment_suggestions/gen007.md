## Experiment 1: Interleaved Triplet + Coord Descent Cycles (HIGHEST PRIORITY)

**What to test:**
Starting from gen007_explore_1_sol01 (C=1.5028628689):
1. Run 3 rounds of full-array coordinate descent (using standardized delta grid)
2. Run 50k triplet trials (with per-strategy logging)
3. Run 3 more rounds of coord descent
4. Run 50k more triplet trials
5. Repeat until both converge in the same cycle

**Hypothesis:** Each method unlocks improvements for the other. Triplet improvements change the
autoconvolution landscape, creating new single-element improvement opportunities. Conversely,
coord descent improvements may expose new triplet improvement directions. Neither method in
isolation can reach the joint minimum.

**Why not already tested:** Gen 7 agents ran either coord descent OR triplets but never both in
sequence within one session. The evaluator experiment list, all 4 agent debriefs, and the agent
gaps report all identify this as the highest-priority untested combination.

**Expected information gain:** If interleaving produces more improvements than the sum of
sequential runs, it confirms the landscape hypothesis and defines the standard exploit protocol
for gen 8+. If it produces no benefit, it rules out the most promising combination and forces
attention to higher-order perturbations (quadruplets).

**Estimated improvement:** -1e-8 to -1e-7 range, based on triplet finding 160 improvements after
coord descent convergence (suggesting headroom still exists).

**Assign to:** exploit_1 (focused session, 150 turns, use `coordinate_descent.py` helper once deployed)

## Experiment 2: Momentum-Enhanced Triplet Search

**What to test:**
After each accepted triplet move at (i, j, k, d1, d2):
1. Retry the SAME triplet with 2x step size, 4x step size, 8x step size
2. Try the SAME direction (d1, d2) on adjacent triplets: (i±1, j, k), (i, j±1, k), (i, j, k±1)
3. If still improving, continue in the same direction (momentum-style) up to 10 steps
4. Only fall back to random triplet selection when the momentum chain exhausts

**Hypothesis:** Improvements cluster spatially and directionally in the array. A single accepted
triplet suggests that nearby elements and similar mass redistribution moves will also improve C.
Exploiting this spatial coherence could find chains of improvements per accepted move rather than
single improvements.

**Why not already tested:** explore_1 noted the improvement rate dropped gradually (100 → 60 → 20
over 3 passes of 20k), suggesting the improvement landscape has structure rather than being
randomly distributed.

**Expected information gain:** If momentum chains exist, improvement rate per trial increases
significantly. If not, confirms the improvement landscape is spatially uncorrelated.

**Estimated improvement:** -1e-9 to -1e-8 additional, beyond standard triplet search.

**Assign to:** explore_1 in gen 8

## Experiment 3: Triplet Strategy A/B/C/D Breakdown (QUICK CALIBRATION)

**What to test:**
Run 4 separate sessions of 20k triplets each, one per strategy:
- Strategy 0: 3 random elements from nonzero elements
- Strategy 1: 1 large (top-10%) + 1 small (bottom-10%) + 1 random
- Strategy 2: 3 consecutive neighbors from a random nonzero element
- Strategy 3: 3 fully random elements from [0..N)

Log: improvement count, average delta C per improvement, and total delta C per strategy.

**Hypothesis:** Mass redistribution (Strategy 1: large→small) dominates the other strategies.
The TTT-Discover array has 25141 nonzero elements and ~4859 zeros; mass redistribution from
large to small elements may exploit the sparse structure more efficiently.

**Why not already tested:** explore_1 rotated strategies every 4 trials but didn't separate them.
The evaluator's Experiment 5 and agent_gaps Gap 1 both explicitly call for this breakdown.

**Expected information gain:** Identifies dominant strategy definitively. Enables all future
triplet work to skip the 3 inferior strategies (3-4x efficiency gain).

**Estimated improvement:** No direct improvement — pure calibration. But enables future sessions
to run 80k trials in the dominant strategy rather than 20k/strategy.

**Assign to:** explore_1 or full_1 in gen 8 (quick calibration before main triplet run)

## Experiment 4: LP Plateau Analysis at Intermediate Resolution

**What to test:**
Load population/best.py and count tight constraints at multiple resolutions:
1. Downsample to N=5000, 8000, 10000 using `interpolate_sparse` helper
2. For each N: compute autoconvolution, run `tight_constraint_indices` at eps=1e-6, 1e-5, 1e-4
3. Report: count at each epsilon, distribution of tight indices, and estimated LP matrix size
4. If count < 500 at N=5000 with eps=1e-5: attempt LP solve and report direction quality

**Hypothesis:** The plateau count grows superlinearly with N. At N=5000, the plateau may have
<200 near-max points (LP tractable), and the descent direction may transfer better to N=30k
than the N=2000 direction (which produced C=1.721 at N=2000 but found no improvement at N=30k).

**Why not already tested:** full_1 jumped between N=2000 (too coarse: different C structure)
and N=30k (too many tight constraints). The N=5000-10000 range is the only unexplored middle
ground. The evaluator's Experiment 4 explicitly identifies this as the remaining LP angle.

**Expected information gain:** Determines whether LP has any viable operating range. If plateau
count at N=5000 is also ~6500, LP is comprehensively closed. If it's ~200, a new attack angle
opens.

**Assign to:** experimentator in gen 8 (diagnostic only, no solution expected unless plateau is small)

## Experiment 5: Quadruplet Perturbation (d1+d2+d3+d4=0)

**What to test:**
4-element integral-preserving moves on the current best:
- Select quadruplets (i, j, k, l) with gradient-guided selection
- Solve for (d1, d2, d3) minimizing gradient of autoconv peak subject to d1+d2+d3+d4=0
  (3-dimensional subspace, use gradient projected onto constraint plane)
- Try 100k trials with step sizes [1e-7 to 5e-4]
- Log improvements per selection strategy

**Hypothesis:** Higher-order coordinated moves access directions in the improvement manifold
that lower-order moves cannot. Pairs failed where triplets succeeded; quadruplets may succeed
where triplets have exhausted. The mathematical argument is the same: optimality conditions for
k-element moves do not imply optimality for (k+1)-element moves.

**Why not already tested:** Logical extension of the triplet work. Not yet attempted. The
evaluator's Experiment 3 identifies this explicitly.

**Caveat:** Quadruplets have a 3-dimensional search space (vs triplets' 2D), making the gradient
calculation more complex. Implementation overhead is ~50% higher than triplets. Start with
gradient-guided selection in the 3D subspace.

**Expected information gain:** If quadruplets find improvements after triplet convergence, confirms
a general pattern of successive perturbation orders. If not, establishes that the current minimum
is robustly optimal under multi-element integral-preserving moves, which would be a meaningful
negative result.

**Assign to:** explore_1 in gen 8 or gen 9 (after triplet interleaving is exhausted)

## Experiment 6: New Starting Arrays at Different Resolution

**What to test:**
Generate fresh starting arrays at N=10000 and N=50000 using the same TTT-Discover structure
(if reproducible) or via coord descent from random init at those scales. Run full-array coord
descent on each to convergence.

**Hypothesis:** The TTT-Discover 30k array may be near the floor of its resolution basin. A
higher-resolution (N=50000) array might have more elements in the right places and achieve a
lower C. Resolution dependence is a documented phenomenon — the existing AlphaEvolve arrays
range from N=600 to N=5000+, and the TTT-Discover array at N=30000 currently dominates.

**Why not already tested:** The pipeline has focused on published arrays as starting points.
No agent has attempted to generate a fresh high-resolution array since gen 1-3, when gradient
methods hit the C~1.509 floor. With coord descent now the established improvement method, a
fresh array at N=50000 might respond better than the N=30000 array after it has been thoroughly
optimized.

**Assign to:** full_1 in gen 8 (if not assigned to LP plateau analysis)

```python
def coordinate_descent_round(f, autoconv, dx, M, delta_grid=None, safe_set=None):
    """
    One full-array pass of coordinate descent using incremental autoconv updates.

        delta_grid: list of delta values to try per element (default: standard 24-value grid)
        safe_set: optional set of tight autoconv indices for faster max computation

    Returns:
        f_new: improved array
        autoconv_new: updated autoconvolution
        n_improvements: number of accepted moves
        new_c: new C value
    """

def run_coordinate_descent(f, n_rounds=10, delta_grid=None, verbose=True):
    """Convenience wrapper: run n_rounds of full-array coord descent."""

DEFAULT_DELTA_GRID = (
    [(-1)**s * 10**e for e in range(-12, -1) for s in (0, 1)] +
    [(-1)**s * r * f[i] for r in (0.0001, 0.001, 0.01, 0.1) for s in (0, 1)]  # proportional
)
```

This single helper would eliminate the 40x improvement count inconsistency observed in gen 7
and save 15-30 minutes per coord descent agent in every future generation.
