## Experiment 1 — Per-Round FFT Resync Coordinate Descent (HIGHEST PRIORITY)

**Hypothesis:** Incremental autoconv drift (~1.4e-12/round, 3.5x real improvement over
5 rounds) is causing CD to accept phantom improvements and mis-track true C. Resynchronizing
via full FFT after every round will eliminate drift and produce more real improvement per
session budget.

**Expected information gain:**
- If per-round resync finds significantly more real improvement: adopt it as the standard
  algorithm for all agents
- If per-round resync finds similar real improvement but with fewer accepted moves:
  confirms that prior "improvements" were partially phantom; may explain why gen 8-9
  improvements were smaller than reported
- Either way: establishes the true CD floor, distinguishing real convergence from
  drift-masked convergence

**Implementation:** Start from gen010_explore_2/sol01.py (best known). Run:
```python
deltas = np.geomspace(1e-14, 1e-1, 60)
for round in range(max_rounds):
    # scan all N elements with top-K pre-filter
    n_improvements = cd_round(f, autoconv, deltas, K=30)
    # FFT resync EVERY round
    f_padded = np.zeros(M_fft); f_padded[:N] = f
    autoconv = np.real(np.fft.irfft(np.fft.rfft(f_padded)**2)) * dx**2
    C_verified = compute_c_f64(f)
    if time.time() > deadline: break
```

**Suggested agent type:** exploit
**Suggested time budget:** 500s
**Metric to track:** real C improvement per round (not incremental), n_improvements per round

## Experiment 2 — Adaptive Delta Range Focused on Productive Scales

**Hypothesis:** exploit_1 showed 99.6% of improvements are at 1e-13, with 0 from 1e-1
to 1e-9. Using a narrow delta grid (e.g., `np.geomspace(1e-14, 1e-11, 30)` instead of
200 values from 1e-14 to 1e-1) would give ~5x more CD rounds in the same time budget,
potentially more total real improvement.

**Expected information gain:**
- If focused grid produces more total improvement: adopt as standard; agents no longer
  need to try coarse deltas that are confirmed dead
- If focused grid produces similar total improvement with more rounds: confirms diminishing
  returns at each delta scale and informs future delta selection
- Directly tests: is the current CD bottleneck "not enough rounds" or "not enough delta coverage"?

**Implementation:** Two conditions within one session:
- Condition A: `geomspace(1e-14, 1e-11, 30)` × N elements × max_rounds, per-round resync
- Condition B: `geomspace(1e-14, 1e-1, 200)` × N elements, limited rounds (baseline)
- Compare real C improvement per 100 seconds of session time

**Suggested agent type:** exploit or experimentator
**Suggested time budget:** 500s

## Experiment 3 — Non-Integral-Preserving Multi-Element Moves

**Hypothesis:** All tested multi-element approaches (triplets, quadruplets, minimax LP)
required integral preservation (d1 + ... + dk = 0). CD works precisely because it
violates this constraint (changes the integral). Two-element non-integral-preserving
moves may find improvements that single-element CD cannot, by coordinating two elements
to jointly reduce C without the coupling constraint.

**Mathematical framing:** Instead of fixing d2 = -d1, optimize:
```
minimize C_new = max(autoconv_new) / (integral_new)^2
over (d1, d2) freely, with k=2 free variables
```
This is a small optimization problem (2D) per pair of elements. With top-K pre-screening
to select candidate (i, j) pairs, total cost could be manageable.

**Expected information gain:**
- If this finds improvements: opens a new optimization pathway that single-element CD
  cannot reach (different basin)
- If this finds zero improvements: confirms that the solution is locally optimal not just
  for integral-preserving moves but for all 2-element perturbations; stronger than current evidence
- Answers the open question flagged by explore_1, explore_2, and evaluator independently

**Suggested agent type:** explore (open-ended investigation)
**Suggested time budget:** 500s

## Experiment 4 — Seeded Multi-Trajectory Competition

**Hypothesis:** exploit_1 observed that different random orderings through the 30k-element
space find different CD improvement paths (baked solution at C=1.50286286818392 vs dynamic
run at C=1.50286286819877, difference ~1e-11 from trajectory randomness). Running 5 independent
trajectories for 100s each and continuing only the best for remaining time would exploit this
variance to find the best-performing local trajectory.

**Expected information gain:**
- If competition outperforms single trajectory: adopt as standard approach; quantifies
  the value of trajectory diversity
- Directly measures: what is the typical standard deviation in final C across different
  random trajectories? This determines whether multi-trajectory competition is worth the overhead

**Implementation:**
```python
import multiprocessing
seeds = [42, 123, 456, 789, 1337]
# Phase 1: 5 parallel trajectories × 100s each
results = [run_cd_trajectory(f_start, seed=s, deadline=time.time()+100) for s in seeds]
# Phase 2: continue best trajectory for remaining ~400s
best_f = min(results, key=lambda r: r.C_verified).f
final = run_cd_trajectory(best_f, seed=best_seed, deadline=time.time()+400)
```

Note: `multiprocessing` available to agents. If parallel execution is not feasible in
the session environment, run sequentially (5 × 90s + 1 × 50s).

**Suggested agent type:** exploit
**Suggested time budget:** 500s

## Experiment 5 — Plateau Structure Tracking Across Generations

**Hypothesis:** The plateau_analyzer.py helper (delivered gen 10) enables systematic
tracking of how many positions are near-maximal and how the gradient matrix changes as
the solution is refined. This structural data would help diagnose whether convergence
is approaching and whether any multi-element approach could still work.

**Expected information gain:**
- Track K (positions within eps of max) at the current gen 10 best vs prior bests
- Track rank of K×N gradient matrix: if rank < K, the minimax LP is provably infeasible
  regardless of implementation (mathematical proof that no integral-preserving move exists)
- Determine whether K is increasing or decreasing as solution is refined — critical for
  predicting whether further CD will create new plateau positions faster than it resolves them

**Implementation:** Short session (~50s) using plateau_analyzer.py on gen010_explore_2_sol01.py.
Run analysis at multiple eps thresholds (1e-10, 1e-11, 1e-12, 1e-13). Record K and
gradient matrix rank at each threshold.

**Suggested agent type:** experimentator
**Suggested time budget:** 200s (diagnostic only)
