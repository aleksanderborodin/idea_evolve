## Experiment 1 — Full Interleaved Multi-Order Cycle (HIGHEST PRIORITY)

**Type:** Exploit agent (single session, full budget)

**Protocol:**
Starting from gen008_explore_1/sol01.py (C = 1.5028628684790137):
1. Run `coordinate_descent_round` (full array, 1 pass). If ≥ 100 improvements: run 2 more rounds.
2. Run triplet perturbation (30k trials, strategies S0/S1/S3 — drop S2 as confirmed underperformer)
3. Run quadruplet perturbation (30k trials, strategies S0/S1/S3)
4. Repeat from step 1 until all three methods find 0 improvements in the same cycle.

**Implementation prerequisite:** Validate `coordinate_descent.py` at N=30k first (5–10 turns).
If validation fails, use inline coord descent from exploit_1's gen 7 implementation.

**What we expect to learn:** Whether the full cycle converges to a lower C than any single
method, and how many cycles are needed. Gen 8 confirmed all three one-directional unlocking
effects (triplet → coord, quadruplet → triplet, triplet → coord after quadruplet). The full
cycle is the logical completion.

**Expected result:** 2–4 additional C improvement cycles, each O(1e-10) or better, totaling
~5e-10 to 2e-9 improvement beyond gen 8 best. The cycle should converge when all methods
simultaneously find 0 improvements.

**Risk:** If coord descent finds 0 improvements in round 1 (already converged on gen 8's
starting point), skip to triplet immediately. Don't spend more than 2 rounds on coord descent
before moving to triplets.

## Experiment 2 — Vectorized Batch Trial Evaluator (HELPER BUILD)

**Type:** Experimentator agent (run BEFORE solution agents)

**Protocol:**
Build `problem/helpers/batch_trial_evaluator.py` with:

```python
def batch_predict_c(autoconv, f_padded, dx, M_fft, indices_batch, deltas_batch):
    """
    First-order prediction of C for K candidate moves simultaneously.
    indices_batch: (K, k) int array — index sets for each candidate
    deltas_batch: (K, k) float array — delta values (must satisfy row-sum = 0)
    Returns: (K,) float array of predicted new C values

    Uses linear approximation: delta_autoconv[m] += dx * sum(delta_j * f_padded[(n*-idx_j)%M])
    Exact for small deltas; use exact incremental_update for acceptance.
    """
```

Required tests:
1. Single-candidate output matches `incremental_update` to <1e-8 relative error
2. K=100 candidates: all within 1e-6 relative of individual calls
3. No candidate with batch_predict_c < current C should ever increase C when exact-evaluated
   (test with 1000 candidates on a known array)

**What we expect to learn:** Whether vectorized first-order approximation is accurate enough
to filter candidates (keep top 5% of K=100 for exact evaluation). If the approximation is
too noisy, the helper can still be used for strategy selection (identify which of S0/S1/S3
has most candidates below current C).

**Expected impact:** 10–50x throughput improvement for all perturbation methods. Transforms
the infeasible 19-min/round coord descent into a 1–2 min/round operation.

## Experiment 3 — Quintuple Perturbation (d1+...+d5=0)

**Type:** Explore agent

**Protocol:**
Starting from the best available solution (gen 8 or gen 9 interleaved result):
1. Implement 5-element integral-preserving moves using gradient projection onto sum=0 hyperplane
   (same pattern as quadruplets, 4 free variables)
2. Strategies: random-5-nonzero, 2-large+2-small+1-random, 5-consecutive (expect weak), mixed
3. Run 50k trials
4. If improvements found: run triplet follow-up (test unlocking hypothesis for quintuples)

**What we expect to learn:** Whether the landscape has 4D structure that quadruplets cannot
access. The pattern so far: pairs (1 improvement in gen 7), triplets (160 in gen 7), quadruplets
(8015 in gen 8). The improvement count increases but per-move delta decreases. If this pattern
continues, quintuples should find O(10k) improvements.

**Key hypothesis to test:** Does each higher-order perturbation unlock lower-order methods
again? After quintuples, run quadruplet + triplet follow-ups and measure improvement count.

**Expected result:** 5k–15k improvements, delta_C ~1e-11 to 1e-10. Even if small, this
completes the picture of the perturbation landscape structure.

## Experiment 4 — N=5000 Optimization from Scratch (LP Tractability Study)

**Type:** Explore agent (long session, 60+ minute compute budget)

**Protocol:**
1. Initialize N=5000 array using one of:
   - `init_smooth_f(5000)` if available (request from experimentator)
   - Direct port of initial_programs/optimize.py logic at N=5000
2. Run Adam + smooth-max gradient descent until C ~ 1.509–1.510 (10–20 min)
3. Run coord descent to convergence (20–30 min, using incremental_update)
4. Measure tight constraint counts: tight@1e-4, 1e-5, 1e-6, 1e-7
5. If tight@1e-5 < 500: run `scipy_lp_solve`, apply line search with 20 step sizes
6. Record: whether LP direction improves C, how many iterations until LP fails

**What we expect to learn:**
- Whether the ~300x lower tight constraint density at N=5000 (observed by explore_2 gen 8
  at C=1.679) persists at near-optimal C=1.503
- If tight@1e-5 < 500, LP at N=5000 is tractable and might find improvements
- Definitive answer on LP at intermediate N (closes the question either way)

**Key unknown:** Whether near-optimal N=5000 arrays even reach C=1.503. The TTT-Discover
N=30k array appears to be a special structure; N=5000 optimization may plateau at C~1.503–1.505.

**Expected duration:** 45–90 minutes total compute. This is the primary reason this experiment
hasn't been run — it exceeds typical session budgets for single-method agents. **Explicitly
allocate a long-running session with time budget 2× normal.**

## Experiment 5 — Momentum-After-Acceptance Quadruplet Protocol

**Type:** Exploit agent (can combine with Experiment 1)

**Protocol:**
For every accepted quadruplet move (indices i,j,k,l with deltas d1,d2,d3,d4):
1. Immediately retry the same 4 indices with step sizes 2x, 4x, 8x (3 extra candidates)
2. If any retry improves C, accept and continue the momentum chain (up to 5 steps)
3. Also try ±1 index shifts: (i±1, j, k, l), (i, j±1, k, l) — nearby quadruplets

**What we expect to learn:** Whether accepted moves cluster in space (momentum locality).
Gen 8 explore_1's quadruplet improvements were spatially distributed (strategies S0/S1/S3
roughly equal), but per-strategy time-resolved data was missing. Momentum may help if
improvements cluster by region after the landscape shifts.

**Expected result:** 10–30% more improvements per session if momentum chains are common.
Low implementation cost (3–5 additional numpy ops per accepted move). Can be tested
as an A/B variant within the same session.

## Experiment 6 — Per-Strategy Efficiency Profiling for Quadruplets

**Type:** Can be embedded in any gen 9 quadruplet experiment

**Protocol:**
For every quadruplet session, log:
```
by_strategy = {0: {attempts: 0, improvements: 0},
               1: {attempts: 0, improvements: 0},
               2: {attempts: 0, improvements: 0},
               3: {attempts: 0, improvements: 0}}
```
Report improvement_rate = improvements/attempts per strategy.

**What we expect to learn:** S2 (consecutive neighbors) showed 1135 improvements vs ~2300
for other strategies (gen 8 explore_1). But all strategies had equal attempt counts. If S2's
rate is ~50% of S0/S1/S3, replacing it with a 5th strategy (e.g., two large + two small)
could improve overall efficiency by ~12%.

**Expected impact:** Low individual value, but this is the same instrumentation gap that
slowed triplet strategy selection by 2 generations. Standardize it now.
