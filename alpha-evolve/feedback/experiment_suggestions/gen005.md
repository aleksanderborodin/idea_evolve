## Experiment 1: Float64 Coordinate Descent Extension (HIGHEST PRIORITY, LOW RISK)

**Hypothesis:** exploit_2 found 116 improvements in 10 passes of top-500 elements with
deltas 1e-6 to 1e-2. The improvements were real but diminishing (72 in pass 1). With a
wider scope (top-2000 elements, finer deltas, more passes), additional improvements exist.

**Method:**
1. Start from the TTT-Discover 30k array (current best, C=1.5028628894)
2. Float64 numpy compute_c for all accept/reject decisions (use helpers/compute_c_f64.py)
3. Pass 1: zero ALL elements < 1e-8 simultaneously (bulk LP residual cleanup) — check improvement
4. Pass 2+: coordinate descent on top-2000 sensitive elements, deltas [1e-8, 1e-7, 1e-6, 1e-5]
5. 30 passes with gradient recomputation each pass
6. Pass N (if improvements found): pair-wise perturbation of top-50 most sensitive pairs
7. BAKE final array as literal — no optimization in entrypoint()

**Expected outcome (positive):** C improves from 1.5028628894 by 1e-8 to 1e-7.
**Expected outcome (negative):** Confirms coordinate descent is at a coordinate-wise
local minimum — closes this approach and strengthens the case for LP refinement.
**Information gain:** High either way. Direct continuation of the only method that has worked.

## Experiment 3: Bulk LP Residual Cleanup (LOW EFFORT, QUICK TEST)

**Hypothesis:** The TTT-Discover array was produced by an LP solver. LP solvers leave many
elements at near-zero residuals (~1e-13) rather than exactly zero. Zeroing all elements
below a threshold simultaneously (not element-by-element) may reduce C more than coordinate
descent because it changes the integral normalization favorably.

**Method:**
1. Load TTT-Discover 30k array (C=1.5028628894)
2. Test thresholds: 1e-8, 1e-9, 1e-10, 1e-11, 1e-12, 1e-13
3. For each threshold: zero all elements below it, rescale to preserve integral, compute C with float64
4. Save the best result as a solution

**Expected outcome (positive):** Some threshold produces C < 1.5028628894 (by more than the
8.82e-9 from exploit_2's coordinate descent).
**Expected outcome (negative):** All thresholds worsen C or give negligible improvement.
Confirms the LP residuals are not a source of slack — array is tight.
**Information gain:** High value per compute: this is a 10-minute test that directly tests
whether LP residuals are exploitable. Should be run as part of Experiment 1 above.

## Experiment 4: LP-Based Constraint Relaxation (HIGH PRIORITY, HIGH EFFORT)

**Hypothesis:** The autocorrelation inequality C(f) = max(f★f) / integral(f)² is a ratio
minimization. Near the optimum, many autoconvolution values are near the max value — these
are "near-tight" constraints. An LP can find a descent direction in this constraint space
that gradient methods cannot, because LP avoids the scale-invariance problem that makes
gradient descent ineffective.

**Background:** Both AlphaEvolve (1.5032) and TTT-Discover (1.5029) were produced by
LP-based methods. No other optimization method has ever improved these solutions. The
algorithm appears to be: identify top-K tightest constraints, formulate an LP to reduce
the max constraint while preserving the integral, solve for the step direction, apply.

**Method:**
1. Start from TTT-Discover 30k array
2. Compute autoconvolution f★f using FFT (N=30000 → length 29999 output)
3. Identify constraints near-tight: indices where (f★f)[i] > max(f★f) * 0.999
4. Formulate an LP: minimize delta such that (f + delta★f)[i] < max(f★f) for tight indices,
   subject to: sum(f + delta) >= sum(f), all(f + delta >= 0)
5. Solve with scipy.optimize.linprog
6. Apply update, check C improvement with float64

**Expected outcome (positive):** C improves by ~0.0001 or more (in the range AlphaEvolve
improvements achieved).
**Expected outcome (negative):** LP produces no descent direction → confirms the array is
at a global optimum in the LP sense. This would be a major result — the bound is tight.
**Information gain:** Maximum. LP is the only untested method that has ever worked.

**Note:** This is engineering-intensive. The research agent needs 60-80 turns. Should be
assigned to a research or full agent with high max_turns.

## Experiment 5: Structural Analysis of Research_1 Arrays vs TTT-Discover

**Hypothesis:** The 5 extracted AlphaEvolve intermediate arrays (N=600 to N=5000) and
TTT-Discover (N=30000) were produced by the same LP-guided method. They likely share
structural features (sparse, multi-peaked, specific autoconvolution peak locations) that
reveal what the LP optimizer converges toward. Understanding this structure could inform
both LP refinement (what constraints are tight) and construction-based approaches.

**Method:**
1. For each of the 6 arrays: compute sparsity (fraction of elements > 1e-4), number of peaks
   (local maxima above mean), peak positions as fraction of [0,1], autoconvolution peak
   position and value, integral value
2. Compare structural features across N=600, 984, 1444, 5000, 30000
3. Identify convergent features as N increases (features that stabilize suggest they're
   optimal, not resolution-dependent)

**Expected outcome:** Reveal whether there is a canonical function shape that LP converges
toward as N→∞. If so, this shape can be used as a construction target.
**Information gain:** Moderate. This is analysis, not optimization — but informs what
the LP and construction experiments should target.

**Cost:** Low. All arrays are already extracted. This is ~20 turns for a research agent.

## Experiment 6: Warm-Start From Research_1 N=600 Arrays (MODERATE PRIORITY)

**Hypothesis:** research_1/sol01 (C=1.5053, N=600) and research_1/sol02 (C=1.5040, N=600)
are LP-optimized arrays at the same resolution as the gradient pipeline. Starting gradient
descent from these arrays (which are already near-optimal LP solutions) may find a different
attractor than random initialization — one that gradient descent cannot reach from scratch.

**Method:**
1. Take research_1/sol02 (C=1.5039, N=600) as warm-start (lower starting C than sol01)
2. Convert to raw_params via inv_softplus_safe
3. Run smooth-max Adam T=0.005→0.0001 (standard pipeline) with float64 accept/reject
4. Compare final C to: (a) C=1.5040 starting value, (b) C=1.5090 gradient baseline

**Expected outcome (positive):** Final C < 1.5039 → gradient descent can improve LP-optimized N=600 arrays.
**Expected outcome (negative):** Final C stays at ~1.509 → confirms gradient attractor dominates
regardless of warm-start quality. Both results are important.
**Information gain:** Moderate. Determines whether the N=600 LP arrays are in a different
basin or the same gradient attractor. Informs warm-start strategy for all future experiments.

**Note:** This experiment depends on the outcome of Experiment 2 (Pattern_007 float64 re-test).
If Experiment 2 confirms Pattern_007, this experiment is lower priority.
