# Agent Gaps — Generation 11

## 1. exploit_1 produced no scored solution

exploit_1 ran 3 separate scripts but none produced a final sol01.py with a .score file.
Only observations.md was written. The agent spent significant time on diagnostics
(non-reproducibility confirmation, single-pass vs multi-pass comparison) but didn't
ship a result. The 490s entrypoint load time consumed over half the available budget.

**Gap:** Agents need a baked array checkpoint to avoid wasting 490s on entrypoint loading.
This has been requested by 3+ agents across 2 generations.

## 2. explore_1 started from gen009 array, not gen010 best

explore_1 loaded gen009/exploit_1 (C=1.5028628682228971) instead of gen010/explore_2
(C=1.5028628681165177). The gap is 1.06e-9 — an entire generation's improvement lost.
The agent chose gen009 because it had a baked inline array (instant load), while gen010
required running a 490s entrypoint.

**Gap:** Best-in-population array is not available in baked format. Despite producing
the NEW OVERALL BEST, explore_1 started from a worse position. Starting from gen010
best would have yielded even better results.

## 3. exploit_2's multi-trajectory experiment was invalidated by drift

All 3 Phase 3 trajectories ended at worse verified C than Phase 2 starting point.
The experiment was designed correctly (comparing trajectory diversity) but the
implementation didn't account for intra-round drift at 2000+ mods/round.

**Gap:** The intra-round drift issue (pattern_027) was not documented before gen 11.
Pattern_021 only described between-round drift. exploit_2 had no way to anticipate this.

## 4. experimentator_1 couldn't test at N=30000

The topk_screened_cd helper was tested at N=1000 only because loading the best N=30000
array takes 490s. The helper may have different performance characteristics at the actual
problem scale (e.g., K=30 screening effectiveness depends on plateau structure).

**Gap:** Same as #1 — no baked best array available.

## 5. Recurring operator-level issues (8th generation)

The Architect flagged these for the 8th time:
- `population/summary.md` shows "Best fitness: 0.000000" (invalid solution ranked first)
- `score_progression.md` stopped updating at gen 7
- `helpers/README.md` still says "none yet" (only .py files are deployed by orchestrator)
- `fact_002` still lists target C ≤ 1.5053 as unbeaten

**Gap:** These are orchestrator code bugs, not agent issues. No agent can fix them.
The system critic has flagged them repeatedly. They require manual intervention in
`orchestrator.py` or the relevant files.

## 6. Knowledge gap: non-IP pair mechanism not fully understood

explore_1 discovered the amplification effect (pattern_025) but only had time for
Phase 2b (high-sensitivity random pairs, 15k trials). Key questions remain:
- Are neighboring pairs (Phase 2a) or random pairs (Phase 2b) more effective?
- What is the optimal number of pair trials before switching to CD?
- Do non-IP triplets provide additional amplification over pairs?
- Does the amplification effect compound across multiple pair→CD cycles?

**Gap:** Single observation. Needs independent replication and parameter tuning.

## 7. No convergence criterion implemented

The Architect raised the question: should we declare convergence when gen-over-gen
improvement drops below 5e-11 for 3 consecutive generations? Gen 11's 3.24e-9
improvement would reset any such counter. But the question remains unresolved.
