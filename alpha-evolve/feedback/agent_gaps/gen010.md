# Agent Gaps — Generation 10

## Knowledge Gaps

1. **batch_trial_evaluator.py documentation is misleading.** The "46x speedup" claim assumes W≈601 (1 tight index at eps_rel=1e-5). The current best solution has 15 tight positions spread across indices 20632–49704, giving W≈9693 and effectively 1x speedup. explore_2 flagged this. The helper needs a documentation update or diagnostic function.

2. **State of Affairs recommended obsolete protocol.** The "standard CD → triplets → quadruplets → ultra-fine CD" protocol was wrong. Gen 10 A/B test and multiple null results confirm the correct protocol is ultra-fine CD only. State of Affairs needs update.

3. **Starting point confusion in briefs.** explore_2 noted the brief recommended triplet search based on the premise that the starting point had only standard CD applied. In fact, the gen9 exploit_1 baseline already had ultra-fine CD. This mismatch led to predictably null triplet/quad phases wasting ~73 seconds.

4. **No static checkpoint of best solution.** experimentator_1 could not verify plateau structure directly because best.py runs a live optimization. A static .npy checkpoint would help helpers and experiments.

## Pipeline Issues

5. **Eval time concern.** explore_1 and explore_2 took ~490-496 seconds for evaluation (they run optimization during entrypoint()). exploit_1 and exploit_2 baked their arrays, taking 0.1-0.3s. Long eval times risk timeout. Solutions that optimize during entrypoint() are fragile — if evaluation time limit were enforced strictly, they'd fail.

6. **Different starting points, different results.** All 4 agents started from gen9_exploit_1/sol01.py, but their independent random trajectories through the CD landscape produced different final scores (spread of ~1.06e-10). This suggests multi-trajectory competition could improve results.

## Missing Knowledge

7. **CD mechanism not documented before gen 10.** The distinction between integral-preserving and non-integral-preserving moves was never explicitly documented. explore_1 discovered this mid-session. Would have saved time if documented in State of Affairs.

8. **Incremental drift rate never measured before gen 10.** exploit_1 was the first to quantify this. All prior CD implementations may have had drift issues without knowing it. Should be documented in helpers/README.md.

## Contradictions

9. **Pattern_012 (exponential decay) vs pattern_023 (no convergence).** Pattern_012 says CD improvements decay exponentially across generations. Pattern_023 says improvement COUNT is stable at ~5000/round with no decay. Both are correct but for different metrics: COUNT is stable, but REAL C IMPROVEMENT per round decays. These patterns need clarification to avoid confusion.

10. **Pattern_014 (higher-order unlocking) vs pattern_020 (subsumption).** Pattern_014 says multi-element moves unlock new single-element directions. Pattern_020 says ultra-fine CD subsumes multi-element moves. Resolution: both are true at different stages. At standard deltas, the interleaving effect is real. At ultra-fine deltas, CD already captures everything. The patterns should be cross-referenced.

## Experimentator Feedback

11. **plateau_analyzer helper built and validated.** 8 tests passed. Performance: 6.7ms at N=30k. Gradient formula is simple: 2*dx*f_padded[(n-m)%M]. However, this helper was not used by any optimization agent this generation (built too late in the pipeline). Should be integrated in gen 11 briefs.

12. **Helpers README was outdated.** Listed "none yet" for experimentator-created helpers despite 8 existing ones. Fixed by experimentator_1. Highlights that the helpers documentation lags behind actual deployment.
