# Agent Gaps — Generation 5

## Critical Gap: Float64 Helper Missing

Both exploit agents independently discovered that the float32/float64 precision mismatch
between helpers and validate.py is the single biggest obstacle to micro-optimization.
exploit_2 had to reimplement compute_c in numpy float64 from scratch, wasting 30+ minutes.

**Recommendation:** Create `helpers/compute_c_f64.py` — a numpy float64 version of compute_c
matching validate.py exactly. This is the #1 priority helper request.

## Gap: No Way to Load Cached Solution Arrays

explore_1 flagged: there is no way to load a solution's evaluated numpy array without
re-running the entrypoint. exploit_2's solution takes 13 minutes to evaluate because it
re-runs coordinate descent at evaluation time instead of baking the final array.

**Recommendation:** Create `helpers/load_solution.py` — loads and caches the numpy array
from a solution file. Also recommend that exploit agents ALWAYS bake final arrays into
solutions instead of re-running optimization.

## Gap: Step-Time Benchmark Helper

explore_1 requested `benchmark_step_time(N, n_steps=100)` — returns ms/step for gradient
steps at a given grid size. Would immediately flag budget issues before wasting turns.

## Gap: Autoconvolution Analysis Helper

exploit_1 wrote a custom helper to compute the autoconvolution peak and identify contributing
element pairs. This analysis (which (i,j) pairs produce the peak, what the tight constraints
are) is fundamental to LP-based refinement and should be a standard helper.

## Gap: Sensitivity Helper Uses Float32

`helpers/sensitivity.py` produces wrong rankings for well-optimized solutions (pattern_008).
exploit_2 confirmed the top-20 most sensitive elements are completely different between float32
and float64. This helper needs a float64 mode or should default to float64.

## Gap: State of Affairs Stale

The architect correctly noted that the State of Affairs (gen 3) is stale. It still recommends
warm-start smooth-max Adam as Priority 1 — a strategy that gen 4 definitively closed. The
Consistency Reviewer should have run. All gen 5 agents worked around this by reading their
briefs carefully, but a stale SoA wastes agent turns on incorrect priorities.

## Gap: Solution Eval Time

exploit_2/sol01 takes 792.6 seconds to evaluate (re-runs coordinate descent). This will slow
down all future evaluations if the solution isn't replaced with a baked-array version. The
pipeline should flag solutions with eval_time > 60s for array-baking.
