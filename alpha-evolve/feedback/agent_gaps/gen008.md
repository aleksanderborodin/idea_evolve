# Agent Gaps — Generation 8

## Gap 1: Interleaved multi-order cycle never completed

The highest-priority experiment from gen 7 coverage matrix — interleaved coord descent +
triplet cycles — was attempted by exploit_1 but not completed due to performance issues.
exploit_1 only ran a single coord descent round before timeout. The full protocol
(coord → triplet → quadruplet → repeat) has never been tested end-to-end.

**Impact:** Medium. Both interleaving directions (triplet → coord, quadruplet → triplet)
are confirmed independently, but the full cycle including its convergence behavior is unknown.

## Gap 2: Momentum triplets tested only Strategy 1

exploit_2 tested 30k momentum-enhanced triplet trials but only ran Strategy 1 (mass
redistribution). Strategies 0, 2, and 3 were not tested. It's possible that the exhaustion
is strategy-specific rather than total. Gen 7 rotated all 4 strategies without per-strategy
logging, so we don't know which strategies were most exhausted.

**Impact:** Low. Even if other strategies have residual headroom, the total improvement
from triplets alone is bounded by the unlocking effect (pattern_014). Higher-order methods
are more productive.

## Gap 3: Safe-set margin documentation

exploit_1 discovered that safe-set margin=1e-4 includes all 60k autoconv positions. The
working margin from gen 7 (which reported 28k positions) was not documented. This caused
exploit_1 to waste time discovering that 1e-8 or tighter is needed.

**Recommendation:** Document the effective safe-set margin in pattern_012 or as a fact.
Useful margin: 1e-8 to 1e-9 for filtering near-plateau positions.

## Gap 4: coordinate_descent.py validation incomplete

The experimentator built coordinate_descent.py but large-array (N=30k) tests were not completed
due to timeout. The accept criterion bug (compare full C vs just max(autoconv)) may or may
not matter at N=30k — the experimentator noted it only manifests on small random arrays.

**Recommendation:** Next exploit agent should validate coordinate_descent.py on gen 4's
TTT-Discover array (known improvements expected) before using it in production.

## Gap 5: helpers/README.md still outdated

The experimentator ran out of time before updating the README to document all 8 deployed
helpers. Agents discovering helpers by reading the README will see incomplete information.

**Recommendation:** Priority task for next experimentator or housekeeping.

## Gap 6: explore_2 couldn't answer the LP plateau question

The LP plateau analysis at intermediate N was the key experiment for explore_2, but it
requires fresh optimization at N=5000 from scratch (30-60 min compute). This exceeds
a single agent session. The question remains: is LP tractable at near-optimal N=5000?

**Recommendation:** Either (a) dedicate a long-running agent session to N=5000 optimization,
or (b) accept that LP refinement is a dead end at all accessible resolutions and archive
idea_020.

## Gap 7: Quadruplet per-strategy time-resolved data missing

explore_1 logged total per-strategy improvement counts (S0:2388, S1:2356, S2:1135, S3:2136)
but not time-resolved improvement rates. We don't know if S2 exhausts faster (was weak from
the start) or just has lower density. This distinction matters for strategy selection in
future runs.
