# Agent Gaps — Generation 2

## Gap 1: full_1 agent produced no scored solution

full_1 wrote a single solution (sol01.py) that timed out during evaluation. The solution combines ALL recommended techniques (coarse-to-fine + smooth-max + 16 restarts + L-BFGS + gradient clipping + float64), making it compute-heavy (~10–20 min on CPU). The agent ran out of time before getting a single score.

**Implication:** The agent did not receive any feedback from its own solutions. No learning occurred.

**Recommendation:** Agents need runtime estimates before committing to heavy pipelines. A "profile first, then scale" instruction should be added to full.md. Brief should specify approximate per-step latency estimates.

## Gap 2: explore_1/sol03 was marked TIMEOUT but is valid

The explore_1 agent marked sol03 as TIMEOUT in its report and did not produce a .score file. However, the code is valid and evaluates to C=1.5091 (new best). The agent timed out before evaluation completed, but the code was written correctly. The evaluator ran evaluate.py and recovered this result.

**Implication:** The current timeout recovery mechanism may be abandoning valid code with unreported scores. The Evaluator should always run evaluate.py on solutions with TIMEOUT or missing .score files.

**Important:** explore_1/sol03 = 1.5091 is the NEW BEST and should be the primary warm-start for gen 3.

## Gap 3: SA hyperparameter blindness

explore_2's SA implementation could not measure acceptance rates or diagnose whether sigma was too large or too small. Without acceptance rate monitoring, SA tuning is guesswork. The agent recommended targeting ~40% acceptance rate but had no way to measure it.

**Recommendation:** SA implementations should log acceptance rate per 10 SA iterations.

## Gap 4: No function shape visualization

All three agents noted they couldn't reason about the optimized function's shape. The best solution (1.5091) has a specific structure that likely differs from the 1.5185 basin. Understanding this structure would guide initialization design for gen 3.

**Recommendation:** Add a matplotlib/JAX visualization snippet to the problem helpers or agent templates, or add a `visualize.py` to problem/.

## Gap 5: SA applied at wrong scale

explore_2 applied SA at N=600 (fine grid). Boyer et al. used SA at N=23 (coarse grid). This is a fundamental difference — coarse SA is cheap and explores a low-dimensional landscape, while fine-grid SA is expensive and faces the same sticky-basin problem that kills other approaches.

**No agent tested coarse-scale SA.** The coverage matrix shows this as the highest-priority unexplored combination for gen 3.

## Gap 6: L-BFGS evidence needs updating

idea_010's evidence base (explore_1/sol05, 1.5155) was obtained WITHOUT smooth-max. Gen 2 provides multiple confirmations that L-BFGS has zero effect after smooth-max. The idea should be downgraded. The State of Affairs and cluster_001 description still mention L-BFGS + smooth-max as an unexplored priority — this is now tested and confirmed ineffective.
