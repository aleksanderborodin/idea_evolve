# Agent Gaps — Generation 6

## 1. explore_1 Produced Nothing

explore_1 was interrupted before any work began. Its directive was to warm-start smooth-max
Adam from N=600 arrays and fall back to coordinate descent — both are valid experiments.
The warm-start would have added another data point for pattern_007 (though exploit_2 already
confirmed it). The coordinate descent on N=600 arrays remains UNTESTED and is a gap.

**Gap:** Float64 coordinate descent on AlphaEvolve N=600 arrays (C=1.5040, C=1.5053) has
never been attempted. These arrays are lower-dimensional (600 elements vs 30000) so each
element has more influence. This should be assigned in gen 7.

## 2. LP Implementation Needs Engineering Expertise

full_1's LP attempt was mathematically sound but failed due to naive Python loop construction
of the constraint matrix. The debrief identifies 4 specific fixes (reduced resolution,
batched FFT, minimal LP, column generation). None of these are exotic — they require
competent numerical programming, not mathematical insight.

**Gap:** The LP experiment needs a brief that explicitly addresses the engineering bottleneck
and provides pseudocode for batched FFT construction. A future full_1 or experimentator
should be briefed to start at reduced resolution (N=2000) as a proof-of-concept.

## 3. Architect Repeatedly Overrides Stale State of Affairs

The architect report notes this is the 4th consecutive generation where the SoA (stuck at
gen 3) has been manually overridden in every brief. This creates duplicated context that
consumes brief tokens and risks inconsistency. The consistency review MUST run before gen 7.

**Gap:** State of Affairs is 3 generations stale. Current SoA recommends "warm-start
smooth-max Adam from the 1.5032 array" — a strategy debunked in gen 4 and confirmed dead
in gen 6. Agents reading the SoA without briefs would pursue dead-end strategies.

## 4. Precision Display Hides Real Progress

The architect flagged that score progression rounds to 4 decimals, hiding gen 5's 1e-8
improvement. At the current frontier (improvements of 1e-8 to 1e-9), the pipeline's display
granularity conceals all progress. metrics.yaml shows `decimals: 6` but the progression
display uses fewer.

**Gap:** Either increase display precision in progression tables or add a "delta from
previous best" column that preserves full precision.

## 5. compute_c_f64 Unavailable During Gen 6

The architect correctly noted that all 4 solution agents needed float64 compute_c but the
experimentator creating it ran in parallel. Each agent reimplemented it independently.
exploit_1 spent 30+ minutes on derivation. The helper is now available for gen 7 but the
inefficiency was significant.

**Gap (resolved):** compute_c_f64 and updated sensitivity.py are now in the helpers pipeline
and should be deployed by the orchestrator before gen 7 agents launch.

## 6. Missing Helper: Incremental Autoconvolution Update

exploit_1 derived and implemented an O(N) incremental autoconvolution update formula that
gives 28x speedup over full FFT recomputation when changing a single element. This is
critical for coordinate descent feasibility at N=30000 and was derived from scratch.

**Gap:** This formula should be captured as a helper in `problem/helpers/` to save future
coordinate descent agents significant derivation time. exploit_1's report contains the
formula: `autoconv_new[n] = autoconv_old[n] + dx*(2*delta*f_padded[(n-idx)%M] + delta^2*(n==2*idx%M))`.

## 7. Missing Helper: Cross-Convolution and Tightness Analysis

full_1's LP work needed cross-convolution (f★g via FFT) and near-tight constraint
identification (indices where autoconv is within epsilon of max). These are core building
blocks for any LP or constraint-based approach and would save significant implementation time.

**Gap:** Add cross-convolution and tightness analysis helpers for LP refinement experiments.

## 8. inv_softplus_safe Default clip_min Bug

exploit_2 discovered that the `inv_softplus_safe` helper with default `clip_min=-10` causes
+5.66e-04 round-trip error for near-zero arrays. Fixed by using `clip_min=-20`. The default
should be changed in the helper to prevent future agents from hitting this confound.

**Gap:** Update `helpers/inv_softplus.py` default `clip_min` from -10 to -20, and add a
docstring warning about round-trip error for sparse arrays.
