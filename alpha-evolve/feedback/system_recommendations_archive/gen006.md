## Priority 4 — LP Brief Must Specify Batched FFT Construction with Pseudocode

**What to change:** The gen 7 LP brief must include explicit implementation guidance:

```
IMPLEMENTATION: Do NOT build constraint matrix in Python loop.
Use batched FFT approach:
1. Downsample f_30k to N=2000 via linear interpolation.
2. For constraint matrix A_ub[j, k] = 2 * f[j-k]:
   - Compute FFT(f) once.
   - For each tight index j: A_ub[j, :] = real(IFFT(FFT(f) * FFT(e_k))[j])
   - Alternative: A_ub[:, k] = circular convolution of f with impulse at k, evaluated at tight indices
   - Using numpy: np.fft.ifft(np.fft.fft(f) * np.fft.fft(impulse_k)).real[tight_indices]
3. At N=2000 with 100 tight constraints: 100 FFTs of length 4000 = <0.1 seconds.
4. Once proof-of-concept works at N=2000, scale up using same batched construction.
VALIDATION: If matrix construction takes >10 minutes, STOP and use reduced resolution.
```

**Why:** full_1 implemented the mathematically correct LP but failed on naive construction.
The fix is well-known (batched FFT, reduced resolution) and documented in full_1's debrief.
The same failure will repeat in gen 7 unless the brief contains this guidance.

**Expected impact:** Enables first successful LP proof-of-concept. LP is the method that
produced TTT-Discover (1.5029) — if it works for our pipeline, it could be transformative.
