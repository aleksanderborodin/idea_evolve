## Priority 4 — Build Vectorized Batch Trial Evaluator Helper (EXPERIMENTATOR TASK)

**What to change:** Assign an experimentator task in gen 9 (running before solution agents)
to build:

```python
def batch_trial_evaluator(autoconv, f_padded, dx, M_fft, candidate_indices, candidate_deltas):
    """
    Evaluate K trial moves simultaneously.
    candidate_indices: (K, k) array of index sets (k=2 for pairs, 3 for triplets, etc.)
    candidate_deltas: (K, k) array of delta values (must satisfy sum=0 constraint)
    Returns: array of predicted new C values, shape (K,)
    Uses first-order approximation (linear delta in autoconv).
    """
```

This allows the Python loop bottleneck to be bypassed for trial selection:
1. Sample K=100 candidates
2. Vectorized evaluation returns all K predicted improvements
3. Accept the best improving candidate
4. Apply exact incremental_update only for accepted moves

**Why:** The Python loop at 100–220 trials/s is the bottleneck for ALL current perturbation
methods. exploit_1 gen 8's full interleaved protocol was abandoned because allocation
overhead made it infeasible (19 min/round estimated). At 1000+ trials/s (conservative for
vectorized numpy), the same round takes <2 min.

**Expected impact:** 5–10x throughput improvement for quadruplet search. Enables full
interleaved cycles within session budget. This is the single change with the highest
expected impact on solution quality per session.
