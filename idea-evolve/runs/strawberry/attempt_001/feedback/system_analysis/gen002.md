# System Analysis — Generation 2

## Executive Summary

Gen 2 did not improve the best score (gen 1 best: 0.8328 remains unbeaten). However, it produced critical negative results that redirect the search: TTA is non-functional, imgsz=832 fine-tuning is catastrophic, and fine-tuning from a converged checkpoint provides marginal benefit. The pipeline itself has a critical bug: the finalize phase was skipped for gen 2, leaving persistent state files stale and causing the orchestrator to believe gen 2 is still in progress.

## Category 1: Pipeline Problems

### CRITICAL: Finalize phase skipped for gen 2

**Evidence:**
- `all_scores.json` contains only 2 gen-1 entries; gen-2 scores (0.8087, 0.8103, 0.5453, 0.8271) are absent
- `score_progression.md` shows only gen 1 (best: 0.8328)
- `run_state.json` shows `"completed_gens": [1]` — gen 2 not recorded as complete
- `run_state.json` shows `"current_phase": "system_critic"` and `"current_gen": 2` — orchestrator thinks gen 2 is still running the system critic phase
- `timing.json` has no `system_critic` entry for gen_002, confirming the phase was never recorded
- `run_state.json.last_updated` is 18:01 but system critic started after that

**Impact:** High. Rankings, dashboard, and orchestrator crash-recovery all rely on these files being current. The orchestrator is in an inconsistent state. If it crashes now, gen 2 will be re-run from agents (skipping evaluator and system critic), losing all the knowledge created this generation.

**Root cause:** The orchestrator's finalize phase (`run_finalize()`) appears to have been skipped or exited early. The `history/generations/gen002.md` was written by the evaluator, but `all_scores.json`, `score_progression.md`, and `run_state.json` were not updated.

### CRITICAL: State of Affairs not updated for gen 2

**Evidence:**
- `knowledge/state_of_affairs.md` is titled "Generation 1 (Rewrite)" and contains only gen-1 data
- Gen 2 evaluator created 4 new ideas (idea_009, 010, 011, 012), updated 4 existing ideas, created 3 patterns, and updated 3 clusters
- Config has `consistency_review_interval: 1` — should run every generation
- No `feedback/consistency_reviews/gen002.md` exists
- The staleness flag `lifecycle_counts` in the dashboard API would show 2-generation-old knowledge

**Impact:** The Architect for gen 3 will read a stale State of Affairs and plan based on wrong priorities. The coverage matrix says TTA is debunked, but the State of Affairs still lists it as "top priority" for gen 2. The Architect will waste cycles on closed directions.

**Root cause:** The consistency reviewer ran for gen 1 (timing shows 255s) but not for gen 2. The `emergency_review_on_strategic_shift: true` config should have triggered a review given the strategic landscape changes (3 major directions closed), but the trigger was not evaluated or the review did not run.
