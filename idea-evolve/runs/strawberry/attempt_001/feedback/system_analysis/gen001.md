# System Analysis — Generation 1

## Pipeline Problems

### CRITICAL: `train_and_eval()` silently overrides explicit lr0 via optimizer='auto'

**Evidence:** `helpers/core.py:148-161` — `model.train()` is called with `**train_kwargs` but no explicit `optimizer=` override. full_1's debrief (reports/gen001/full_1.md:21) shows the training log explicitly printed: `optimizer: 'optimizer=auto' found, ignoring 'lr0=0.005' and 'momentum=0.937'`. The intended experiment (lr0=0.005) was completely compromised. The model used lr=0.000909 instead.

**Severity:** Critical. Experiment results are invalid when lr0 is a controlled variable. All future agents using `train_and_eval()` will hit this unless they explicitly pass `optimizer='AdamW'`.

**Root cause:** The docstring (core.py:118-125) shows `lr0=0.001` as an example kwarg but never mentions that the default `optimizer='auto'` silently overrides it. The docstring is misleading — it implies `lr0` will be respected.

---

### CRITICAL: No training logs available to diagnose crashes

**Evidence:** explore_2's only solution returned `is_valid=0` with `[Errno 32] Broken pipe` (population/gen001/explore_2/observations.md:14). No training logs exist anywhere — `train_and_eval()` cleans up `RUN_DIR` after every run (core.py:144-145, 170-171), even on error. agents cannot determine whether the crash was caused by `copy_paste=0.65`, a memory issue, or a random failure.

**Severity:** Critical. One of three agents produced zero useful data. Future agents cannot learn from this failure.

**Severity:** Moderate. The pipeline lost 33% of exploration bandwidth in gen 1. The broken pipe may or may not have produced a valid solution at a different copy_paste value (e.g., 0.6).

## Missing Capabilities

### HIGH: No per-class performance visibility

**Evidence:** All agents (explore_1, explore_2, full_1, research_1) report only aggregate mAP50. evaluator.md:94 explicitly states "No per-class mAP — I cannot tell which disease classes are the bottleneck." The 15x class imbalance between Leaf Spot and Anthracnose means aggregate mAP50 is dominated by the majority class.

**Impact:** Without per-class mAP, the pipeline cannot diagnose whether improvements are coming from better Leaf Spot detection (already strong) or rare-class detection (the actual bottleneck). All agents are flying blind on the central challenge.

**Recommendation:** Add per-class mAP to `evaluate_on_test()` in helpers/core.py. YOLO's `model.val()` returns per-class metrics via `m.seg.cp` (class precision) and `m.seg.cr` (class recall).

---

### HIGH: No diagnostic tool for test predictions

**Evidence:** full_1 debrief (full_1.md:15): "No test set images to visually inspect — cannot diagnose whether failures are due to small objects, occlusions, or class confusion."

**Impact:** Agents cannot verify hypotheses like "imgsz=832 helps because small lesions are the bottleneck." Without seeing what's being missed, agents guess.

---

### HIGH: No zero-shot baseline for the val-test gap question

**Evidence:** state_of_affairs.md:58 — "Is the val-test gap a property of the fine-tuning regime? If exp5 is already overfit to val, 20 epochs of fine-tuning might be actively harmful on test. We need a zero-shot baseline (exp5 best.pt evaluated directly on test)." evaluator_debrief.md:32 confirms this is still open.

**Impact:** The entire fine-tuning strategy might be counterproductive. Without knowing exp5's zero-shot test score, every fine-tune result is uninterpretable.

## Prompt Problems

### HIGH: No agent was warned about optimizer='auto' trap

**Evidence:** No agent report mentions being pre-warned about the lr0 override. All agents discovered it reactively. The `train_and_eval()` docstring actively misleads by showing `lr0=0.001` as a usage example without a warning.

**Impact:** full_1 wasted an entire experiment on a compromised configuration. If the architect or evaluator had flagged this in agent briefings, it would have been avoided.

## Resource Issues

### HIGH: TTA never applied despite being zero-cost

**Evidence:** evaluator_debrief.md:27 — "TTA not applied: No solution applied Test-Time Augmentation to any model — this is the easiest immediate win, completely missed." All 6 techniques in research_1's report are untested. coverage_matrix.md:13-17 lists idea_002, idea_003, idea_006, idea_007 as zero-coverage.

**Impact:** The pipeline has a known free improvement sitting idle. Every comparison in gen 1 was evaluated without TTA, so scores are systematically pessimistic. The fitness signal for ALL decisions is degraded.

---

### MODERATE: copy_paste stability boundary not mapped

**Evidence:** explore_2 jumped from 0.5 (safe) to 0.65 (crash). The actual ceiling is somewhere between. The efficient mapping would be 0.55 → 0.6 → 0.65, but the pipeline jumped the intermediate values. agent_gaps/gen001.md:43 recommends testing 0.55 and 0.6 but this was never done.

**Impact:** The pipeline knows copy_paste=0.5 is safe and 0.65 crashes, but has no data for 0.55–0.64. If 0.55 or 0.6 is stable and beneficial, this entire range is wasted exploration.

## Experiment Gaps

The coverage matrix (coverage_matrix.md:12-17) correctly identifies the untested space:

1. **TTA (idea_003):** Zero attempts. research_1 provided complete implementation. This is a pure evaluation-time change — no retraining needed. Apply `augment=True` to `model.val()`.
2. **imgsz=832 (idea_002):** Zero attempts. Higher resolution hypothesis completely unexplored despite being the top recommendation from full_1 and explore_1.
3. **yolo11s from exp5 (idea_001 variant):** The best gen_1 result (0.8328) came from COCO, not exp5. Combining the best model scale with the best starting point is the logical next step and hasn't been tried.
4. **copy_paste=0.55, 0.6:** Between the safe (0.5) and crashed (0.65) values.
5. **Progressive resizing (idea_006):** Zero attempts despite being a native Ultralytics technique.
6. **Label smoothing, NMS tuning, class weighting:** All untested.

---

## Strategic Assessment

**Gen 1 efficiency was low.** 3 agents ran but only 2 produced valid data, and one of those was compromised by the optimizer bug. The best score (0.8328) is a from-scratch COCO training — the wrong starting point for a fine-tuning pipeline. The core fine-tuning track (full_1, 0.8137) regressed to baseline.

**The pipeline is early-stage.** The search space is vast and mostly untouched. Most "findings" from gen 1 are actually restatements of the initial conditions (copy_paste=0.5 is good, class imbalance is the challenge) rather than new discoveries.

**TTA is the single highest-priority experiment.** It's free, implementable in one line of code change, and would improve the accuracy of every subsequent fitness measurement.

**The val-test gap is the central mystery.** Without resolving it, all fine-tuning results are uninterpretable. A single zero-shot evaluation of exp5 best.pt on test would answer this.
