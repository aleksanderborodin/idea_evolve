# System Analysis — Generation 1

## Pipeline Problems

### CRITICAL: yolo11s eval crashes silently — BrokenPipeError in GPU lock cleanup

**Evidence**: `population/gen001/explore_2/observations.md` — Training completed 40/50 epochs successfully with mAP50 trending ~0.81, but evaluation crashed with `BrokenPipeError` during GPU lock cleanup. Solution scored 0.0 (sentinel/invalid).

**Severity**: Critical

**Impact**: The larger model (yolo11s-seg.pt) was producing valid results but evaluation never completed. The pipeline cannot measure the potential of larger models. This is a kill-contract/evaluate.py bug, not a model limitation — training logs show no divergence or instability.

**Root cause**: `evaluate.py` GPU lock cleanup code has a process communication issue. The BrokenPipe suggests a pipe/FD problem between the orchestrator's kill mechanism and the eval subprocess.

---

### CRITICAL: TTA is silently ignored on YOLO11n-seg

**Evidence**: Multiple agents (`explore_1_sol03`, `full_1_sol01`, `full_1_sol02`) explicitly tried `tta=True` expecting the documented 0.5-2% boost. The YOLO model logged `"Model does not support augment=True"` and reverted to single-scale inference. No error, no warning before evaluation — just silently ignored.

**Severity**: Critical

**Impact**: Agents wasted time on a non-functional feature and may have made suboptimal comparisons (e.g., `full_1_sol02` at 0.8209 might have scored higher with working TTA). The description.md claims TTA adds 0.5-2% — if YOLO11n-seg doesn't support it, this should be removed from documentation OR implemented manually via multiple predict() calls.

**Root cause**: `tta=True` in ultralytics 8.4.37's `val()` method is not supported for YOLO11n-seg. The feature exists for detection models but not segmentation models in this version.

## Missing Capabilities

### CRITICAL: No per-class mAP50 baseline for WEIGHTS_EXP5

**Evidence**: `agent_gaps/gen001.md` gap 1: "Agents did not know the per-class mAP50 for WEIGHTS_EXP5." Research agent specifically cited this as critical missing information (research_1.md line 24). Evaluator (evaluator.md line 38) confirms "We don't know how much each class improved from the 100-epoch training."

**Severity**: Critical

**Impact**: All agents optimized blindly for overall mAP50 without knowing which classes have headroom for improvement. The bottleneck classes (Angular Leafspot, Leaf Spot) are identified but without per-class baseline, no agent can tell if a change helps or hurts a specific class.

**Required action**: Run `evaluate_on_test(WEIGHTS_EXP5)` as the first step in gen 2 to establish per-class baseline. Store results in a machine-readable form accessible via a helper function.

**Evidence**: `research_1.md` line 98-100: "The helpers don't document how to access per-class metrics after evaluation in a machine-readable form... A `read_last_per_class_metrics()` function would be convenient."

**Severity**: Moderate

**Impact**: Agents must use Bash + JSON parsing to read per-class metrics. A `get_per_class_metrics()` helper would save turns and make per-class analysis more accessible.

**Required action**: Add `get_per_class_metrics()` to `helpers/core.py` that reads `LAST_PER_CLASS_METRICS` and returns a structured dict.
