# System Recommendations — Generation 1

Prioritized by expected impact on pipeline effectiveness.

---

## P0 — Fix immediately, affects all future generations

### REC-1: Fix `train_and_eval()` optimizer default

**What:** Change `train_and_eval()` to default to `optimizer='AdamW'` (or `'SGD'`) instead of relying on `optimizer='auto'`. Alternatively, add an explicit note in the docstring warning that `optimizer='auto'` ignores `lr0`.

**Why:** Every agent using `train_and_eval()` with an explicit `lr0` is getting silently overridden. full_1's entire experiment was compromised. This affects every future generation until fixed.

**How:** In `helpers/core.py:148`, add `optimizer=optimizer if 'optimizer' in train_kwargs else 'AdamW'` or similar. Update the docstring to warn about the auto-optimizer behavior.

**Expected impact:** All future lr0 experiments are valid. Prevents wasted generations on compromised configurations.

---

### REC-2: Add per-class mAP to `evaluate_on_test()`

**What:** Modify `evaluate_on_test()` in `helpers/core.py` to return per-class precision, recall, and mAP50. YOLO's `model.val()` returns these via `m.seg.cp` (per-class precision), `m.seg.cr` (per-class recall), and `m.seg.ap50` (per-class AP50).

**Why:** The 15x class imbalance means aggregate mAP50 is dominated by Leaf Spot. Without per-class metrics, the pipeline cannot diagnose whether improvements target the bottleneck (rare classes) or the already-strong majority class. Every agent report cited this as the #1 information gap.

**How:**
```python
def evaluate_on_test(weights_path: str, imgsz: int = 640, device: int = 0) -> dict:
    ...
    m = model.val(data=DATA_V1, split="test", imgsz=imgsz, device=device, ...)
    return {
        "mAP50": round(float(m.seg.map50), 4),
        "mAP50_95": round(float(m.seg.map), 4),
        "F1": round(2*mp*mr/(mp+mr+1e-9), 4),
        "precision": round(mp, 4),
        "recall": round(mr, 4),
        "per_class": {
            "precision": [float(x) for x in m.seg.cp],
            "recall": [float(x) for x in m.seg.cr],
            "mAP50": [float(x) for x in m.seg.ap50],
        }
    }
```

**Expected impact:** Agents can now target rare-class improvements specifically. The fitness signal becomes much more informative for the central challenge.

## P1 — High value, low effort

### REC-3: Apply TTA to best model immediately (no agent needed)

**What:** The orchestrator or a one-off script should evaluate `WEIGHTS_EXP5` and/or `population/gen001/explore_1/sol01.py` with `augment=True` and record the result. This is a pure evaluation change — no retraining.

**Why:** TTA consistently provides 0.5-2% mAP50 lift in YOLO segmentation at zero training cost. Every fitness measurement in gen 1 was taken without TTA, making all scores systematically ~1% below their true potential. The Evaluator's debrief (evaluator.md:109) explicitly recommends this as the first experiment.

**How:** One line change to `evaluate_on_test()`: add `augment=True` as a kwarg. Or run a standalone eval with TTA on the best existing checkpoint.

**Expected impact:** Better fitness signal for all downstream decisions. If TTA gives +1%, the pipeline learns faster from each comparison.

---

### REC-4: Run a zero-shot evaluation of exp5 best.pt on test

**What:** Evaluate `WEIGHTS_EXP5` (the best 100-epoch checkpoint) directly on the test split WITHOUT any fine-tuning, using `evaluate_on_test(WEIGHTS_EXP5)`.

**Why:** full_1's 20-epoch fine-tune from exp5 scored 0.8137 — identical to the gen-0 baseline that used the same exp5 start. If exp5 already scores 0.8137 zero-shot, then fine-tuning is actively harmful. If exp5 scores lower, then 20-epoch fine-tuning is providing positive transfer. Either way, this resolves the central uncertainty about the val-test gap.

**Expected impact:** Changes the entire fine-tuning strategy. If fine-tuning from exp5 is neutral or harmful, the pipeline should explore other directions (higher resolution, TTA, ensembles) rather than more fine-tuning experiments.

---

### REC-5: Preserve training logs on crash

**What:** Modify `train_and_eval()` to save training logs to a persistent location before cleanup, especially on error. At minimum, print or save the last 50 lines of the training log when a crash occurs.

**Why:** explore_2's crash (broken pipe) produced zero diagnostic information. The pipeline cannot distinguish between a copy_paste=0.65 specific crash and a random failure. With logs, the next agent could adjust strategy rather than blindly retrying.

**How:** Before `shutil.rmtree(_run)` in core.py, check for a crash (best.pt doesn't exist after training) and copy or print the YOLO training output.

**Expected impact:** Agents learn from failures instead of repeating them.

## P2 — Medium effort, significant strategic value

### REC-6: Convert all research findings to idea files systematically

**What:** The orchestrator should scan `research_*/` output directories and automatically create idea files for any technique that has a name, description, and "why it matters" but no corresponding idea file.

**Why:** research_1 identified 6 techniques but only TTA became an idea. The other 5 are trapped in a report the Architect may not fully process. This is a pipeline routing failure — knowledge produced but not routed into the idea system.

**Expected impact:** The Architect sees the full landscape of unexplored directions. Better allocation of agent effort across technique families.

---

### REC-7: Architects should assign specific copy_paste values to avoid gaps

**What:** When the Architect assigns an agent to explore "higher copy_paste values," it should specify the exact value (e.g., 0.6) rather than leaving it to the agent to choose. The Architect should consult the coverage matrix to avoid duplicating failed experiments.

**Why:** explore_2 jumped from 0.5 to 0.65, skipping 0.55 and 0.6. If 0.65 crashes and 0.5 is safe, the pipeline has no data for the middle range. Systematic exploration requires coordination.

**Expected impact:** The coverage matrix fills in more efficiently. No wasted attempts on already-known-failing values.

---

## P3 — Longer-term improvements

### REC-8: Add test prediction visualizer

**What:** A helper that saves model predictions on test images to a directory — predicted masks overlaid on images, organized by class and confidence. This lets agents visually diagnose failure modes.

**Why:** Multiple agents cited "no test image visibility" as a key gap. Without seeing what's being missed, agents cannot form hypotheses about whether small objects, occlusions, or class confusion is the bottleneck.

**Expected impact:** Faster iteration. Agents can form and test specific hypotheses rather than guessing.

---

### REC-9: Add TTA to `evaluate_on_test()` as an optional parameter

**What:** Make `augment=True` available as a parameter in `evaluate_on_test()` so agents can easily compare TTA vs non-TTA scores. Default to `augment=False` for backward compatibility.

**Why:** TTA is a universal improvement technique. Making it a simple kwarg in the standard evaluation path means every agent automatically benefits from more accurate fitness measurements.

**Expected impact:** All future scores include the TTA boost. Enables fair comparison across generations.
