# Agent Gaps — Generation 2

## Missing Information Across Agents

### 1. Per-class mAP breakdown unavailable
All agents are working with aggregate mAP50 scores. The class imbalance (15x ratio between Leaf Spot and Anthracnose) means:
- We don't know which classes are driving the aggregate score
- We don't know which classes are the actual bottleneck
- Strategies targeting "improvement" may be inadvertently targeting dominant classes while rare classes lag

**Who mentioned it:** research_1, explore_1
**Impact:** HIGH — without per-class metrics, all improvement strategies are blind

### 2. yolo11s + longer training question unanswered
Two agents attempted to test yolo11s with 40-50 epochs (explore_1 sol02, full_1 sol01). Both timed out before producing scores. The most important question (does the larger model benefit from more training?) remains unanswered.

**Who mentioned it:** full_1, explore_1
**Impact:** HIGH — yolo11s is the best-performing model but we only have one data point at 20 epochs

### 3. exp5 training config unknown
Agents fine-tuning from exp5 don't know: learning rate schedule, augmentation settings, resolution during training, or number of epochs. This makes it impossible to design optimal fine-tuning continuation.

**Who mentioned it:** research_1
**Impact:** MEDIUM — limits ability to design optimal fine-tuning strategies

### 4. Class-weighted loss / rare class handling unexplored
The extreme class imbalance (89 Anthracnose vs 1365 Leaf Spot instances) is identified as a potential bottleneck, but no agent has implemented class-weighted loss or targeted oversampling for rare classes.

**Who mentioned it:** explore_1
**Impact:** MEDIUM — could be the actual bottleneck limiting progress to 0.92+

### 5. Training logs not preserved
Training logs and per-epoch val curves are cleaned up by `cleanup=True` before agents can analyze them. Agents cannot determine if models were still improving at epoch 20 or had already plateaued.

**Who mentioned it:** explore_1
**Impact:** MEDIUM — limits diagnostic capability

### 6. Evaluate.py timeout handling
Long-running evaluations (50 epochs) keep getting interrupted. Agents don't know if this is a timeout in the harness, the GPU lock, or the evaluation script itself.

**Who mentioned it:** full_1
**Impact:** MEDIUM — blocks expensive but potentially valuable experiments

### 7. TTA compatibility investigation incomplete
research_1 confirmed TTA is non-functional but didn't investigate WHY or whether retraining could fix it. The open question (EXP-3: does a freshly trained model support TTA?) was not answered.

**Who mentioned it:** research_1
**Impact:** LOW-MEDIUM — would require dedicated experiment

## Pipeline-Level Issues

### 8. Solutions written but never evaluated
explore_1 sol02 and full_1 sol01 were written but timed out before evaluation. These represent real experimental work that produced no scored result. The system should either:
- Give these agents more time to complete evaluation, or
- Have a mechanism to resume interrupted evaluations on restart

### 9. Helper documentation gaps
- `evaluate_on_test` doesn't document that it doesn't support `augment=True`
- `model_name` is NOT a valid kwarg but no error message guides agents
- `PROXY_EPOCHS_SCRATCH = 50` exceeds the epoch constraints documented elsewhere

**Who mentioned it:** research_1, explore_1

### 10. Experiment request routing unclear
Multiple agents identified the same high-value experiments (yolo11s from exp5, progressive resizing, per-class metrics) but it's unclear whether these will be prioritized in gen_3.

## Disputed Claims Requiring Resolution

### imgsz=832 hypothesis
explore_1's result (0.5453 regression) contradicts the hypothesis that higher resolution improves small-lesion detection. But the result was from a specific approach (fine-tuning from converged 640 checkpoint). The hypothesis itself (imgsz=832 helps small lesions) may still be valid if approached differently (from-scratch training or progressive resizing).

### Val-test gap cause
Is the gap caused by:
- Resolution mismatch (train 640, test has smaller lesions)?
- Distribution shift (val vs test have different characteristics)?
- Fine-tuning adaptation to val (20 epochs adapts to val without generalizing)?
- All of the above?

No agent has designed an experiment to isolate the cause.
