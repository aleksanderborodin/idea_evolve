# Agent Gaps — Generation 1

## Knowledge Gaps Identified Across Agent Reports

### 1. Per-Class Performance Baseline Missing

**Gap**: Agents did not know the per-class mAP50 for WEIGHTS_EXP5 (the best known checkpoint). Without this, they cannot identify which classes have headroom for improvement.

**Impact**: Research agent identified this as critical but could not obtain it. All agents optimized blindly for overall mAP50 without knowing which classes to target.

**Recommendation**: First action in gen2 should be `evaluate_on_test(WEIGHTS_EXP5)` to establish per-class baseline.

### 2. YOLO Loss Injection API Unknown

**Gap**: Research identified BCE-Dice-Lovász composite loss as promising for class imbalance, but no agent knows how to inject custom loss into YOLO11's training loop.

**Impact**: Agents spent turns discovering that cls_pw is invalid. A working code snippet for loss injection would save significant exploration time.

**Recommendation**: Document YOLO11 loss injection in helpers/README.md, or provide a `train_with_custom_loss()` helper.

### 3. TTA Behavior Is Misleading

**Gap**: description.md claims TTA adds ~0.5-2% mAP50, but YOLO11n-seg silently ignores augment=True in val(). Agents (explore_1_sol03, full_1_sol01, full_1_sol02) all tried TTA expecting benefit.

**Impact**: Wasted evaluation time and misleading score comparisons.

**Recommendation**: Fix documentation or implement manual TTA via multiple predict() calls.

### 4. yolo11s BrokenPipe Is Undiagnosed

**Gap**: explore_2's yolo11s-seg.pt from-scratch training was progressing well (40/50 epochs, mAP50~0.81), but eval crashed with BrokenPipeError in GPU lock cleanup.

**Impact**: The larger model potential is unknown. Was it training toward a better score? We can't tell.

**Recommendation**: Debug the GPU lock cleanup code in evaluate.py. The crash is NOT a model capacity issue — training was healthy.

### 5. Val Split Instance Counts Unknown

**Gap**: Agents don't know how many instances of each class exist in the val split (307 images). Research agent noted this would help estimate whether inverse-frequency weighting during training would balance val performance.

**Impact**: Harder to design targeted class balancing strategies.

### 6. Exploration Was Narrow

**Gap**: All agents explored variations of copy_paste/mixup/mosaic hyperparameters. No agent attempted:
- WEIGHTS_EXP6 as starting point
- Progressive resolution training
- Custom class weights via YAML
- Staged fine-tuning (freeze/unfreeze)
- Larger image size (imgsz=832)

**Impact**: The knowledge frontier for gen1 is limited to augmentation hyperparameter space.

**Recommendation**: Architect should direct gen2 agents toward unexplored regions (WEIGHTS_EXP6, resolution, staged fine-tuning) rather than more copy_paste sweeps.

## Pipeline Gaps

### 7. Research Findings Not Persisted

**Gap**: research_1's output/report.md (literature findings) was not saved to the knowledge directory. The knowledge/research/gen001/research_1/ directory exists but is empty.

**Impact**: Research insights are lost between generations.

**Recommendation**: Verify orchestrator correctly moves research outputs to knowledge/research/genNNN/.

### 8. No Experiments Conducted

**Gap**: Despite being listed as an agent type, no experiment results were saved to knowledge/experiments/gen001/. The directory exists but is empty.

**Impact**: The experiment consolidation step cannot find any experiments to consolidate.

**Recommendation**: Ensure experimentator agents persist results correctly.
