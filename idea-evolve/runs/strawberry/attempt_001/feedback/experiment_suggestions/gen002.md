## EXP-1: yolo11s from COCO at 40 epochs (HIGHEST PRIORITY)

**Hypothesis:** The gen-1 best (yolo11s from COCO at 20 epochs = 0.8328) was either noise or still improving. yolo11s has more capacity than nano and may not plateau at 20 epochs.

**What to run:**
- yolo11s-seg.pt from COCO pretrained
- 40 epochs (max allowed per constraints.md, up from 20)
- copy_paste=0.5, optimizer='AdamW', lr0=0.01, batch=8, imgsz=640
- Evaluate on test without TTA (TTA is non-functional)

**Expected duration:** ~7-8 minutes (2x the 20-epoch runtime)

**Information gained:**
- If score > 0.8328: yolo11s was still improving at 20 epochs. The model-scale direction is strong. Prioritize scaling up (yolo11m) or extending epochs further.
- If score ≈ 0.8328: yolo11s plateaus at 20 epochs from COCO. The 0.8328 was near-optimal for this approach. Focus on different directions (resolution, class handling).
- If score < 0.8328: Overfitting at 40 epochs. Reduce epochs or add regularization.

**Why this experiment matters:** The entire gen-2 strategic shift was based on the assumption that yolo11s at 20 epochs is the best starting point. This is validated with only 1 data point. Without this experiment, every future generation is working from an unconfirmed baseline.

## EXP-2: Progressive resizing (640→832) with yolo11s from COCO

**Hypothesis:** Direct fine-tuning at 832 from a 640-converged checkpoint destroyed performance (0.5453 regression). But progressive resizing — train at 640 for 20 epochs, then fine-tune at 832 for 10 epochs — will preserve domain adaptation while capturing higher-resolution features.

**What to run:**
- Stage 1: yolo11s from COCO, 640, 20 epochs
- Stage 2: load best.pt from stage 1, fine-tune at 832, 10 epochs
- copy_paste=0.5, optimizer='AdamW', lr0=0.001 (lower lr for fine-tuning), batch=8
- Evaluate at 832

**Expected duration:** ~10-12 minutes

**Information gained:**
- If score > 0.8328: Progressive resizing works. The resolution hypothesis is validated and the approach is to scale.
- If score 0.78-0.83: Progressive resizing partially helps but 832 is still challenging. The bottleneck is not purely resolution.
- If score < 0.78: Resolution is not the bottleneck. Stop pursuing higher resolution and focus on other directions.

**Why this experiment matters:** The imgsz=832 hypothesis (small lesions at test time are missed at 640) is the #1 unexplored direction by prior state_of_affairs. This is the cleanest test of it.

## EXP-3: Per-class mAP50 extraction on best model

**Hypothesis:** Aggregate mAP50 is dominated by Leaf Spot (1365 instances, 15x more than Anthracnose at 89). The bottleneck for reaching 0.92+ is rare-class performance, not aggregate improvement.

**What to run:**
- Take the best available model (exp5 zero-shot: 0.8271, or best gen-1 yolo11s if EXP-1 completes)
- Run `model.val()` and extract `m.seg.cp`, `m.seg.cr`, `m.seg.ap50` per class
- Map class IDs to disease names using the dataset YAML

**Expected duration:** ~1 minute (evaluation only)

**Information gained:**
- List of per-class mAP50 sorted worst-first
- Identifies which classes are limiting the aggregate score
- Directly answers: is the bottleneck Leaf Spot (already strong) or Anthracnose/Blossom Blight (rare)?
- If rare classes are 10x worse than Leaf Spot: targeted augmentation or class-weighted loss becomes the top priority
- If all classes are similar: the bottleneck is global (resolution, architecture) not class-specific

**Why this experiment matters:** Without per-class data, every agent is guessing which direction helps. This experiment eliminates the guesswork and redirects the entire search.

## EXP-4: copy_paste=0.55 and 0.6 incremental mapping

**Hypothesis:** copy_paste=0.5 is safe. copy_paste=0.65 crashes. The untested range (0.55-0.6) may provide better rare-class oversampling without instability.

**What to run:**
- Two separate runs:
  - Run A: yolo11n from COCO, 20 epochs, copy_paste=0.55, optimizer='AdamW', batch=8
  - Run B: yolo11n from COCO, 20 epochs, copy_paste=0.6, optimizer='AdamW', batch=8
- Both are fast (~3 min each)

**Information gained:**
- If both 0.55 and 0.6 are stable: the ceiling is above 0.6. Continue incremental testing (0.62, 0.64) to find the true ceiling.
- If only 0.55 is stable: the ceiling is between 0.55 and 0.6. Use 0.55 for any future copy_paste-based experiments.
- If 0.6 crashes: ceiling is between 0.55 and 0.65. Use 0.55.
- The ideal copy_paste value for class imbalance may be different from 0.5.

**Why this experiment matters:** The class imbalance (15x) is a known bottleneck. copy_paste=0.5 provides limited rare-class oversampling. Better copy_paste values could be a free lunch if stable.

## EXP-5: yolo11s from exp5 (untested combination)

**Hypothesis:** yolo11s from COCO at 20 epochs = 0.8328. Could yolo11s from exp5's domain-adapted weights do better? The pretrained= approach failed (architecture mismatch), but training yolo11s from scratch with exp5-like augmentation config could test this.

**What to run:**
- yolo11s from COCO (NOT from exp5 via pretrained= — that fails)
- Train with augmentation config matching exp5 (copy_paste=0.5, same augmentations if known)
- 20 epochs, optimizer='AdamW', lr0=0.01
- This tests whether exp5's augmentation strategy generalizes to yolo11s

**Alternative (if manual weight loading is feasible):**
- Load yolo11s architecture, transfer yolo11n→yolo11s weights where shapes match (layer-by-layer)
- Fine-tune transferred weights for 20 epochs

**Information gained:**
- If yolo11s with exp5 augmentation > 0.8328: exp5's augmentation strategy generalizes. Adopt it for future yolo11s runs.
- If yolo11s with exp5 augmentation ≈ 0.8328: COCO pretrained is as good as exp5 domain for yolo11s. Don't bother with domain adaptation for larger models.
- If < 0.8328: exp5 augmentation strategy doesn't help larger models. Focus on architectural changes.

## EXP-6: TTA re-validation after fresh training

**Hypothesis:** TTA is non-functional with exp5 weights (export artifact). A model trained from scratch in the current Ultralytics environment might support TTA.

**What to run:**
- Train yolo11s from COCO at 20 epochs (this is EXP-1's first half)
- Evaluate with `augment=True` on the freshly trained model
- Compare TTA vs non-TTA on the same model

**Information gained:**
- If TTA works on freshly trained model: TTA direction is revived. All future evaluations should use TTA.
- If TTA still non-functional: TTA is permanently disabled in this Ultralytics version or for this model type. Stop all TTA planning.

**Why this experiment matters:** If TTA provides even 0.5% lift, it's a free lunch on every future evaluation. Worth confirming definitively.
