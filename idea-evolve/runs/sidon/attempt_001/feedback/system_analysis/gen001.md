# System Analysis — Generation 1

## Executive Summary

Generation 1 was a spectacular success in solution quality (+33 from baseline in one generation), but exposed several structural pipeline inefficiencies that will compound as future generations build on this foundation. The core issues are: parallel agent isolation wasting compute on inferior strategies, missing helper infrastructure that all agents independently requested, stale initial knowledge, and no mechanism to save and reuse the explicit best solution for future agents.

---

## Pipeline Problems

### [MODERATE] Parallel agent isolation caused redundant inferior work

**Evidence**: explore_2 and full_1 spent their entire sessions working from the greedy-66 baseline. explore_1's Singer discovery was simultaneous, so they couldn't benefit. explore_2's best was 68 (vs 99 from Singer). full_1 stayed at 66.

**Root cause**: Parallel execution is intentional and necessary for throughput, but the briefing didn't pre-load the Singer construction as the known starting point. research_1's findings (Singer = 98 guaranteed) were available only post-generation.

**Impact**: ~1/3 of agent compute produced no useful results this generation. More importantly, if this pattern repeats in gen 2 (agents working from greedy instead of Singer-99), the same waste recurs.

**Severity**: Moderate. The Singer breakthrough came from explore_1 regardless, so gen 1 still succeeded. But efficiency was poor.

---

### [MODERATE] full_1 implemented the wrong algebraic construction

**Evidence**: full_1's debrief notes it tried `{i*p + i²%p}` (parabola construction) for p=101, getting 312 violations. This construction is mathematically incorrect for large primes. The Singer construction was available in initial ideas (idea_004) and the research brief.

**Root cause**: The brief for full_1 described the Singer construction at a vague level ("modular arithmetic structure") without clearly naming it or providing the algorithm. The research agent's concrete pseudocode wasn't available in time.

**Impact**: full_1's session produced zero improvement (stayed at 66 = baseline).

**Severity**: Moderate. Briefs need to name constructions explicitly and provide concrete starting code, not just conceptual hints.

---

### [MODERATE] 99-element solution never persisted as a reusable artifact

**Evidence**: explore_1's debrief: "I know sol02-04 found it but didn't print/save it for future agents to start from." The 99-element set exists only encoded inside sol02-04 Python code, requiring 55-115 seconds of re-execution to extract. The evaluator's agent_gaps file also flags this as Gap 1.

**Impact**: Generation 2 agents who want to start from the 99-element set must either re-run the 55-second search or implement Singer perturbation from scratch. This is a avoidable 55-second penalty per agent, and risks the 99-element set being re-discovered rather than exploited.

**Severity**: Moderate. Should be fixed before gen 2 launches exploit agents.

---

### [MINOR] explore_1 sol03 and sol04 were redundant with sol02

**Evidence**: sol02 found 99 in 55s. sol03 searched for 115s with "larger perturbations" and also got 99. sol04 did "targeted 99→100 push" for 115s and also got 99. Total: 285 seconds of search in explore_1 without improvement over the first perturbed result.

**Root cause**: The agent continued trying variations after hitting the apparent ceiling, without making a qualitatively different move. Each subsequent solution was essentially the same strategy with different parameters.

**Severity**: Minor. Indicates the 99→100 barrier is real, but the time was not well spent (same strategy repeated with more iterations).

## Missing Capabilities

### [CRITICAL] Missing helper infrastructure — 3 helpers requested by 4 agents independently

**Evidence**: Four separate agents requested the same 3 helpers, indicating a real gap:
- `greedy_sidon(candidates)` — requested by explore_1 ("reimplemented 4 times")
- `build_diff_counts(S, N)` / `fast_greedy_fill(S_minus, excluded)` — requested by full_1 ("reimplemented 3 times") and explore_2
- `find_singer_set(q)` — requested by research_1 and noted by the evaluator

**Impact**: Each agent is wasting 3-15 turns reimplementing the same boilerplate. Worse, agents make different tradeoffs (speed vs clarity), introducing inconsistency and bugs. explore_2's sol02 and sol06 had validity bugs likely arising from complex, re-implemented greedy logic.

**Severity**: Critical. These are the 3 most-used operations in the entire solution space. Adding them as helpers will: (a) reduce agent boilerplate by 20-50 lines per solution, (b) reduce bugs from incorrect custom implementations, (c) free turns for actual optimization. This is the single highest-ROI infrastructure investment for gen 2.

---

### [MODERATE] No mechanism to persist the best known explicit solution between generations

**Evidence**: The best known solution (99-element set from explore_1/sol02) exists only as executable Python code requiring 55 seconds to reproduce. No `best_known.txt` or `seeds/best_solution.py` artifact exists with the explicit element list.

**Recommendation**: Establish a convention: after each generation, the evaluator or finalize phase should extract and save the explicit set (as a JSON list or plain text) alongside the `.py` file.

## Prompt Problems

### [MODERATE] full_1 brief lacked Singer construction specificity

**Evidence**: full_1 tried the parabola construction despite Singer being referenced in initial ideas. The brief's treatment of "Modular Arithmetic Structure" (idea_004) was apparently too vague to convey that Singer via GF(p³) was the correct implementation.

**Root cause**: idea_004 was written at gen 0 with vague description. The research agent's concrete pseudocode came too late.

**Action**: For gen 2+, the Architect's briefs for all agents should include: "The Singer q=97 set (98 elements) is the established baseline — use `find_singer_set(97)` from helpers. Do NOT reimplement algebraic constructions from scratch."

---

### [MINOR] explore_2 brief did not mention Singer as a fallback starting point

**Evidence**: explore_2 was assigned "metaheuristic optimization" and worked exclusively from greedy-66. Its brief apparently didn't say "if algebraic construction succeeds, seed your SA from that instead."

**Severity**: Minor. Gen 1 was a cold start; this was unavoidable. But gen 2 briefs must specify Singer-99 as the mandatory starting point for all agents.

## Resource Issues

### [MODERATE] explore_2 high bug rate (2/6 solutions invalid = 33%)

**Evidence**: sol02 and sol06 from explore_2 were invalid (1 violation each). Both bugs were in 2-opt logic: sol02 had incorrect blocking computation; sol06 had incorrect exclusion in greedy re-fill. The evaluator notes these as "wasted compute."

**Root cause**: 2-opt for Sidon sets is subtle — the "exclude removed elements during greedy refill" invariant is easy to violate. Without a helper that enforces this invariant, agents must implement it correctly under time pressure.

**Impact**: 2 of 6 explore_2 solutions produced zero useful output. The agent also noted it ran out of time before fixing the 2-opt correctly.

**Severity**: Moderate. A `greedy_fill(S_partial, excluded)` helper would directly prevent this class of bug.

---

### [MINOR] Research agent's findings not available to solution agents in real time

**Evidence**: research_1 identified Singer q=101 truncation as the primary path to 100+, but this finding was only available after gen 1 completed. explore_1 independently discovered Singer q=97 but did not know about the q=101 strategy.

**Severity**: Minor. This is a structural limitation of parallel execution. Mitigate via better Architect briefs that anticipate what research will likely find. For gen 2, Singer q=101 should be in the brief as an explicit assignment.

---

## Knowledge Quality Issues

### [MODERATE] Initial fact_002 had wrong upper bound (102 vs 109)

**Evidence**: research_1 debrief and evaluator debrief both flag: "fact_002 says upper bound ≈ 100-102. The modern upper bound is 109 (Carter, Hunter, O'Bryant 2025)." full_1's debrief also notes this.

**Impact**: An upper bound of 102 makes target=100 look very tight (98% of theoretical max). An upper bound of 109 makes it look achievable (91% of max). Agents reasoning from the wrong bound might prematurely conclude 99 is near-optimal.

**Action**: fact_002 must be updated before gen 2. The evaluator flagged this in its debrief.

---

### [MINOR] fact_004 (violation tolerance) is reportedly outdated

**Evidence**: full_1 debrief: "fact_004 saying violations allow partial scoring is now outdated/wrong." The current sentinel score policy (is_valid=0 → fitness=0) makes any violation-tolerant reasoning incorrect.

**Action**: Update or archive fact_004 before gen 2.

The new State of Affairs produced by the Evaluator is accurate, well-organized, and actionable. It correctly identifies the Singer breakthrough, the 99→100 barrier, and the priority experiments. No issues found.

## Experiment Gaps

### [CRITICAL] Singer q=101 with cyclic shift — highest priority untested strategy

No agent tested Singer q=101 truncation despite research_1 identifying it as the primary path to 100+. The strategy is fully specified. This is the single most important experiment for gen 2.

### [HIGH] Explicit exhaustive search: enumerate all 99-element Singer-perturbation sets

The perturbation approach (remove 1-2 elements, re-extend) consistently finds 99. An exhaustive version that tries ALL removals of 1-2 elements and ALL greedy extensions would determine definitively whether any perturbation yields 100.

### [HIGH] SA or hill-climbing from the 99-element seed

Simulated annealing seeded from the existing 99-element set with slow cooling. This tests whether the 99→100 barrier is a search difficulty or a structural ceiling.

### [MODERATE] Ruzsa and Bose-Chowla constructions

The research agent mentioned these as alternatives to Singer. Untested. Could yield different algebraic starting points with better extension properties.

### [MODERATE] Extract and analyze the 99-element set's structure

What differences does it use? What are the "free" differences? How many candidates can be added if exactly 1, 2, 3 elements are removed? This structural analysis would inform which strategy (cyclic shift, SA, swap) is most likely to succeed.
