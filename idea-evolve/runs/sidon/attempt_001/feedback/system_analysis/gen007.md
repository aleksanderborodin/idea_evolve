## Executive Framing

Generation 7 was the most knowledge-productive generation since gen5, but its primary
execution failure — full_1 producing zero code output — is the second consecutive generation
where the highest-priority CP-SAT experiment was not completed. This is now a systemic pattern,
not an isolated incident.

algebraic constructions are exhausted, and VLNS from the 105-mark set is proven INFEASIBLE

### [CRITICAL] full_1 session wasted — second consecutive generation

**Evidence:** full_1 debrief says "Context reading only. No code was written." The agent read 6
files then was interrupted. The binary variable CP-SAT maximize-k formulation (EXP-5), which has
been the highest-priority untested approach for 2 generations, remains unimplemented.

variable CP-SAT formulation." This is the third generation-level CP-SAT failure:

**Root cause:** The brief told the agent to read `state_of_affairs.md` and prior reports as
initial context. This reading phase consumed enough turns that the session was interrupted.
The brief did NOT provide the CP-SAT formulation inline, forcing the agent to derive it from
reading prior reports.

**Severity:** Critical — two planning cycles consumed by a single missing deliverable.

### [CRITICAL] Stale fact files persist after 5+ generations of flagging

**Evidence:** `knowledge/facts/fact_002.md` still says "upper bound approximately 100-102"
(correct value: ~109, O'Bryant 2022). `knowledge/facts/fact_004.md` still says "validator
extracts largest valid subset" (correct behavior: sentinel score 0 for invalid solutions).
Both files have been WRONG since generation 0 and flagged since generation 2. Corrected
versions exist in `knowledge/ideas/active/`.

The Architect flagged this in gen6 and gen7. The Evaluator flagged it this generation.
The gen6 Consistency Review identified 11 files needing updates. None of the stale files
have been overwritten.

**Root cause (structural):** No agent writes directly to `knowledge/facts/`. The Evaluator
writes to `output/updated_ideas/` which routes to `knowledge/ideas/{lifecycle}/`, not to
`knowledge/facts/`. The orchestrator has no "fact overwrite" routing path. The stale files
persist because no orchestrator workflow can remove them.

**Impact:** Any agent reading `knowledge/facts/` gets wrong upper bound (100-102 instead of ~109)
and wrong scoring behavior (subset extraction instead of sentinel). An agent using fact_002 might
incorrectly believe 105 already exceeds the upper bound.

**Severity:** Critical — data poisoning risk persists indefinitely without structural fix.

## 2. Missing Capabilities

### [CRITICAL] No automated stale-file cleanup mechanism

The pipeline has no mechanism to overwrite files in `knowledge/facts/` or to move files
between directories when they are in the wrong location. The only paths are:
- `output/new_ideas/` → `knowledge/ideas/{lifecycle}/`
- `output/updated_ideas/` → `knowledge/ideas/{lifecycle}/`
- `output/new_patterns/` → `knowledge/patterns/{lifecycle}/`

**Missing:** A mechanism for agents to signal "delete this file" or "overwrite this fact."

**Recommendation:** Add a `to_delete/` directory in evaluator output that the orchestrator
reads and processes as file deletions. OR: give the Evaluator direct write permission to
`knowledge/facts/` for overwrites.

---

### [MODERATE] No exit/convergence criteria defined

The Architect explicitly asked: "Should we set a 'give up' threshold?" The pipeline has
no formal decision rule for when to stop. The evidence for F₂(10000) = 105 is now strong:
- 85+ VLNS trials from BEST_105: all INFEASIBLE at 106
- Literature: no published 106-mark construction found
- Algebraic: all q≤109 exhausted, ceiling 105
- Perturbation: 27K+ trials, self-healing property

After the binary CP-SAT maximize experiment runs (EXP-5), if it confirms 105, the pipeline
should terminate. There is currently no mechanism or policy for this.

### [MODERATE] Research agent limited to "absence of evidence" conclusions

## 3. Prompt Problems

### [CRITICAL] full.md and exploit.md briefs don't provide CP-SAT formulation inline

**Evidence:** full_1 spent its entire session reading context to derive the formulation it
needed. The brief listed file paths to read. This pattern has caused at least 3 CP-SAT
session failures across gens 6-7.

**What agents need but don't get from briefs:**
- The binary variable CP-SAT formulation for Sidon constraints (pseudocode)
- The key constraint: for each sum s, at-most-one pair (i,j) with i+j=s and x_i=x_j=1
- The warm-start: x_i=1 for i in BEST_105
- The import: `from helpers.cpsat import vlns_sidon, solve_sidon_cpsat`

A brief that says "read gen006/full_1.md for the formulation" is one that guarantees
the agent will spend 5+ turns reading before coding. Briefs should include the 10-line
pseudocode inline.

---

### [MODERATE] VLNS framing carried contradictory characterization across generations

**Evidence:** The gen6 SoA and system recommendations described VLNS as "CRITICAL: Fix
abs-equality domain bug" with high confidence. This framing persisted into gen7 briefs.
In fact, three independent gen7 agents confirmed there was no bug — the infeasibility was
genuine. One generation of compute was spent "fixing" something that wasn't broken.

**Root cause:** The SoA characterized a plausible-but-unverified diagnosis as "CRITICAL"
and "almost certainly a formulation bug." The knowledge system needs a stronger distinction
between:
- `status: diagnosed, confidence: low` — plausible diagnosis, unverified
- `status: confirmed, confidence: high` — verified by multiple agents

**Recommendation:** The SoA should explicitly distinguish "diagnosis proposed" from
"diagnosis confirmed." When an idea is marked CRITICAL, it should require >1 agent
confirmation before that label is trusted.

---

### [MINOR] Brief still references helpers/extend.py which does not exist

**Evidence:** explore_1 debrief confirms this. The Architect who wrote the gen7 brief
did not verify the file exists before including it. This is the second consecutive generation.

**Recommendation:** The brief template should not reference helpers that haven't been
confirmed to exist. Either create the file or remove from template.
