# System Analysis — Generation 3

## Summary

Generation 3 produced no score improvement (best: 102, unchanged since gen 2). The major
advances were structural/knowledge: a geometric proof that the Singer ceiling is hard,
establishment of the non-algebraic ceiling at 69, and debunking of SA, perturbation, and
randomized greedy across all tested variants. Three systemic failures compounded: the
research agent failed for the third consecutive time, two agents produced solutions without
debrief reports, and the State of Affairs has never been updated since generation 0. These
infrastructure failures are now the primary bottleneck, not the optimization difficulty.

---

## 1. Pipeline Problems

### [CRITICAL] Research agent has failed 3 consecutive generations

**Evidence**: research_1 was "terminated before completing any web searches" (gen003 gaps #3).
Gen 1 produced partial findings; gen 2 timed out before web search; gen 3 terminated before
any output. Three generations, zero successful literature searches.

**Root cause analysis**: The research task requires 5-10 web fetches with latency, plus
reading/summarizing PDF content. Each round trip is 10-30 seconds. The agent's allocated
time appears insufficient, and the brief does not enforce incremental saving of partial
findings. The agent writes nothing until it has "complete" findings — so a timeout means
total loss.

**System impact**: The single most important strategic question (is 102 state-of-the-art
or decades behind?) has been unanswered for 3 generations. This means the pipeline cannot
calibrate its effort — it might be optimizing a problem already solved in the literature,
or might be state-of-the-art with no published room for improvement.

**Severity: CRITICAL**

---

### [CRITICAL] State of Affairs has never been updated

**Evidence**: `knowledge/state_of_affairs.md` still has `generation: 0`, `best_score: 0`,
`trajectory: starting`, and says "No generations have run yet." This is after 3 complete
generations with a best score of 102 and extensive accumulated knowledge.

**Root cause analysis**: REC-1 from gen 2 explicitly recommended forcing a Consistency
Review before gen 3. This recommendation was apparently not implemented — the Architect
report for gen 3 does not mention having triggered one, and the SoA remains at gen 0.
The Consistency Review fires every 3 generations by default; if gen 3 is the trigger,
it ran AFTER agents completed, meaning all gen 3 agents operated with a completely stale
Layer 0 knowledge artifact.

**System impact**: Every agent that read state_of_affairs.md got "no generations have run
yet" — a lie. Agents that trusted the SoA and skipped reading individual knowledge files
would have had catastrophically wrong context. The knowledge dump (`knowledge_dump.md`)
may have compensated for this in some cases, but agents relying on SoA alone were misled.

**Severity: CRITICAL**

---

### [CRITICAL] Two agents produced solutions but no debrief reports

**Evidence**: exploit_1 produced sol01 (score 102) with no report in `reports/gen003/`.
explore_1 produced sol01 (score 63) and sol02 (score 0) with no report. The evaluator
notes this as gaps #1 and #2. Both agents' reasoning, approaches tried, and strategic
observations are permanently lost.

**Root cause analysis**: The three-phase timeout system should catch missing reports via
debrief recovery (BUG-12 fix). But if the agents wrote their solutions and `.score` files
and exited normally (within time limits), the recovery wouldn't trigger — the orchestrator
has no way to distinguish "agent ran successfully and forgot to write report" from "agent
was killed before writing report."

**System impact**: Recurring — if agents regularly skip debrief reports, knowledge
accumulation degrades. The evaluator cannot do accurate idea-mapping without knowing what
the agent tried. Strategic reasoning from successful agents (exploit_1 scored 102) is
especially valuable and completely lost.

**Severity: CRITICAL**

---

### [MODERATE] Stale fact files in knowledge/facts/ persist

**Evidence**: Architect and evaluator both note fact_002 and fact_004 in `knowledge/facts/`
contain wrong information. Corrected versions exist in `knowledge/ideas/active/` but the
old fact files persist. Three generations have passed since these were identified as wrong.

**Root cause analysis**: No agent has explicit authority to DELETE files from knowledge/.
The Consistency Reviewer is supposed to audit and fix, but hasn't run with an accurate SoA.
The evaluator creates/updates ideas but does not clean up the separate facts/ directory.

**System impact**: Agents reading from `knowledge/facts/` directly (or via the knowledge
dump) receive contradictory information — correct version in ideas/, wrong version in
facts/. This is a knowledge integrity failure.

**Severity: MODERATE**

---

### [MODERATE] ILP has been top priority for 3 generations but is still untested

**Evidence**: ILP rated "HIGHEST PRIORITY" in coverage matrix for 3 consecutive generations.
explore_2 attempted it in gen 3 but used the wrong formulation (quadruple constraints,
661,650 constraints for M=200). No agent has successfully run the correct difference-indicator
ILP formulation even for small N.

**Root cause analysis**: ILP is computationally intensive and requires offline execution
beyond the normal evaluation pipeline. Agents are time-constrained and gravitate toward
approaches they can test within a single session. The Architect does not appear to have
created a dedicated ILP-focused agent brief that explains the correct formulation and
sets up offline execution.

**Severity: MODERATE**

## 2. Missing Capabilities

### [CRITICAL] No incremental output from research agents

Research agents write no partial findings during their session — they accumulate work
internally and write `findings.md` at the end. If the session ends early (timeout,
termination), all work is lost. The research_1 agent's own debrief confirms this:
"The session was interrupted before completing and writing output files."

**What's needed**: The research agent brief must require saving a partial `output/findings.md`
after EACH web fetch / paper download. The brief should say: "After every search result,
immediately update findings.md with what you found. Never wait until the end."

---

### [MODERATE] No ILP idea file despite 3 generations of recommendation

ILP/constraint programming is the most consistently recommended approach across all 3
generations but has no formal idea file in `knowledge/ideas/`. Without an idea file, the
coverage matrix cannot track ILP coverage, and the Evaluator cannot do idea-matching for
ILP-based solutions. Agents also have no canonical reference for what ILP formulations
have been tried vs untried.

---

### [MODERATE] Debrief completion not verified by orchestrator

The orchestrator verifies that solution files and `.score` files exist, but does not
appear to verify that `report.md` was written before marking an agent as "done." Two
agents this generation completed their work (solutions + scores) without writing debriefs.
The debrief recovery path (three-phase timeout) only fires on session failure, not on
"success without report."

## 3. Prompt Problems

### [CRITICAL] Research agent brief does not enforce incremental saving

The research agent brief gives the agent a task and waits for end-of-session output.
There is no instruction to write partial output after each search. Given three consecutive
failures, this prompt pattern is demonstrably insufficient. The agent acknowledges the
problem in its own debrief but cannot self-correct within the current prompt structure.

---

### [MODERATE] Research agent brief doesn't front-load the searches

research_1's debrief states: "The key search targets should be checked in the FIRST 10
minutes of the session, not deferred." The current brief apparently doesn't force immediate
action on the most critical searches. The agent is spending early turns on context
accumulation rather than immediately fetching the two arXiv papers.

---

### [MODERATE] No enforcement of debrief writing at session end

The agent prompt presumably asks for a report, but two agents this generation completed
without writing one. The prompt needs a stronger enforcement mechanism — something like:
"BEFORE YOU EXIT: You must write output/report.md. Check that this file exists. If it
does not, write it now before doing anything else."

## 4. Resource Issues

### [CRITICAL] explore_1/sol02 evaluation consumed 1728 seconds (29 minutes)

**Evidence**: The evaluator notes sol02 took 1728s to evaluate, producing 280,849
violations. The evaluate.py timeout (if any) was not hit — it ran to completion for
29 minutes before returning a catastrophically broken result.

**Root cause**: The min-blocking greedy algorithm doesn't enforce the Sidon property
when adding elements. It uses a heuristic "conflict" array that doesn't track actual
pairwise differences. With no valid elements to add, it adds everything, producing a
775-element "set" with astronomical violations.

**System impact**: 29 minutes of wall clock time blocked this evaluation slot. If
evaluation is done serially or has limited parallelism, this delays the entire generation.
The eval cache will prevent re-running this exact solution, but the pattern of "broken
algorithm runs forever before failing" will recur if not addressed.

**Severity: HIGH** — both as a one-time cost and as a recurring risk.

---

### [MODERATE] Computational infeasibility not caught before evaluation

explore_2/sol02 had a diff-tracking bug producing 7 violations (fast to discover).
explore_1/sol02 had a fundamental algorithm defect that only surfaces after 29 minutes.
Agents should perform a small-N test before submitting solutions for full evaluation.

## 6. Experiment Gaps

### Still untested after 3 generations:

1. **ILP with difference-indicator formulation** (highest priority, 3 consecutive
   generations of failure to test correctly):
   - Variable per candidate, indicator variables per (diff, pair)
   - O(N²) variables but sparse — practically feasible for N≤500 with CBC
   - Should be tested offline with no time constraint on the agent

2. **Literature search for F(10000)** (3 consecutive failures):
   - arXiv:math/0407117 (O'Bryant 2004)
   - arXiv:2310.20032 (Carter/Hunter/O'Bryant 2023)
   - OEIS A143824 b-file

3. **Correct min-blocking greedy (vectorized)**:
   - Must maintain proper `used_diffs` set (not heuristic array)
   - Vectorize with numpy to run at N=10000 scale
   - Expected 70-80 based on theoretical properties

4. **Non-Singer algebraic constructions**:
   - Cilleruelo elliptic curve construction (2011)
   - Algebraic geometry codes over finite fields
   - Never mentioned in current knowledge base

5. **CP-SAT (OR-Tools)** as alternative to PuLP/CBC:
   - OR-Tools CP-SAT is specifically designed for constraint satisfaction
   - Likely faster than CBC for the Sidon problem structure
   - Mentioned once by explore_1 but never attempted
