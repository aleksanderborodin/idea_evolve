## PRIORITY 1 (Critical — Do Before Gen 2 Launches)

### REC-1: Build three helpers — find_singer_set, greedy_sidon, build_diff_counts

**What to change**: Add three helpers to `problems/sidon/helpers/core.py`:

1. `find_singer_set(q)` — linear recurrence over GF(q), returns sorted list of q+1 indices in {0..q²+q}. Include the index-0 check (x[0]=0 is always in the set). The pseudocode from research_1's report is copy-pasteable.

2. `greedy_sidon(candidates)` — given an ordered list of candidate integers, greedily builds the largest Sidon set. Returns the set as a sorted list. Must maintain `used_diffs` incrementally for speed.

3. `build_diff_counts(S, N)` — given a Sidon set S and universe size N, returns a reference-counted numpy array `counts[d] = number of pairs in S with difference d`. Used by local search to check which differences are free after element removal.

**Why**: Four agents independently requested these helpers and reimplemented them 3-4 times each. This wasted ~30 turns total on boilerplate. Buggy custom reimplementations (explore_2's 2-opt bugs) caused 2 invalid solutions. With standardized helpers: agents write less code, make fewer bugs, spend more turns on actual optimization.

**Expected impact**: -20 to -40 lines of boilerplate per solution. -1 to -2 invalid solutions per generation. +5 to +10 turns freed per agent for actual search.

### REC-6: Exploit agent should extract the 99-element structure (blocker analysis)

**What to change**: Assign one exploit agent in gen 2 to:
1. Load the 99-element seed.
2. For each non-member x ∈ {0..10000}, compute which set members "block" x (share a difference with x).
3. Rank non-members by fewest blockers (easiest to add).
4. Rank set members by most blocking (most "expensive" to keep).
5. Try swapping cheapest members for elements they block.

**Why**: This analysis was planned by explore_1 (see debrief item 6.4: "Systematic blocker analysis") but never executed. It provides a principled basis for local search that random perturbation lacks.

**Expected impact**: Either finds path to 100 or precisely characterizes why 99 is a local maximum.
