# System Recommendations — Generation 2

Prioritized from highest to lowest impact.

---

## PRIORITY 1 (Critical — Do Before Gen 3 Launches)

### REC-1: Trigger a Consistency Review / State of Affairs rewrite NOW

**What to change**: Force a Consistency Review before gen 3 launches, regardless of the 3-gen
interval. The State of Affairs currently says best=99, Singer q=101 is "UNTESTED" at #1 priority.
These are now deeply wrong. A gen 3 agent reading the current SoA will waste turns on Singer q=101
implementation that was exhaustively covered in gen 2.

**Why**: The SoA is the L0 knowledge artifact that all agents read first. Stale data here
causes cascading errors in agent planning. The 99→102 improvement plus Singer exhaustion
constitutes a paradigm shift in problem structure — exactly the trigger condition for a full SoA rewrite.

**Expected impact**: Gen 3 agents start with accurate context. No time wasted re-proving
Singer q=101 is exhausted.

**Concrete action**: Set the Consistency Review as a mandatory phase before gen 3 agent
work starts, or have the Architect write a gen 3 SoA update as its first output artifact.

---

### REC-2: Dedicate a research agent in gen 3 exclusively to literature search

**What to change**: Assign one research agent in gen 3 a single task: find the best known
Sidon set size for N=10000 in published computational tables. Specific targets:
- O'Bryant 2004 arXiv:math/0407117 — tables of best known B₂ set sizes
- Helm 2006 database of Sidon set records
- Carter, Hunter, O'Bryant 2025 reference (mentioned in state_of_affairs as source of 109 bound)

**Why**: Two generations have passed without completing this web search. It is the single most
decision-critical piece of missing information. If a 105-element set is published, we need its
construction. If 102 is the published best, our result is state-of-the-art and the strategy
changes (focus on proving optimality, not improving the bound). Either way, the answer changes
the gen 3 strategy fundamentally.

**Expected impact**: Gen 3 strategy calibrated to actual state of the art. No wasted effort
on approaches that are either already known or provably impossible.

**Concrete action**: Research agent brief should explicitly state: "Your ONLY task is the
literature search. Do not write any solution code. Check web resources, then write findings.md."
Include the specific arXiv ID and author names in the brief.

### REC-3: Add "Dead Ends" section to all agent briefs

**What to change**: The Architect must include a "Dead Ends — Do Not Investigate" section in
every agent brief, explicitly listing:
- Singer q=97..109 (all tested, q=101 gives 102 which is the ceiling)
- Local search / SA from Singer seed (SA proved useless in 228 combined seconds)
- Ruzsa ({a·p + a²%p}) and Bose-Chowla ({i·p + g^i%p}) formulas (carry violations for p≥11)
- Perturbation/SA from 102-element set (40+ minimum blockers, local search infeasible)

**Why**: explore_1 wasted turns verifying that Ruzsa/Bose-Chowla don't work — information
already in the state_of_affairs. The dead-end knowledge is buried in prose and overlooked.

**Expected impact**: No agent in gen 3 re-investigates Singer primes, carry-violating formulas,
or SA from 102. Each avoided rediscovery saves 5-15 turns.

## PRIORITY 2 (High — Architect Should Implement in Gen 3 Briefs)

### REC-4: Build `find_optimal_shift(q, N)` helper via Experimentator

**What to change**: Assign experimentator in gen 3 (or add to the existing gen 3 experimentator
brief) the task of building `find_optimal_shift(q, N)` — a helper that takes a Singer set in
Z_{q²+q+1} and returns the cyclic shift maximizing elements ≤ N.

**Why**: Requested by experimentator_1, exploit_2, and research_1 across gen 2. Currently,
every agent that needs this functionality reimplements 10-20 lines of boilerplate. The logic
is simple and well-specified.

**Expected impact**: -10 to -20 lines per agent, eliminates a common source of off-by-one
errors in shift arithmetic.

**What to change**: Add to the research agent brief template (agents/research.md or equivalent)
and to any gen 3 research briefs: "FIRST STEP: Read all .score files in population/gen003/ to
understand what has already been achieved this generation. Do this before any other reading or
analysis."

session earlier toward the critical gap (web search for published records).

**Expected impact**: Research agents spend their time on actual gaps, not re-analyzing what
solution agents are already proving.

### REC-6: Save hardcoded 102-element solution as a JSON seed file

**What to change**: After gen 2 finalize, run exploit_1/sol02.py and extract the element list,
save to `knowledge/seeds/sidon_102.json` with format:
`{"elements": [...], "fitness": 102, "source": "gen002/exploit_1/sol02", "construction": "Singer-101-shift"}`

**Why**: Sol02 has 0.003s eval time but requires running Python to get the element list. Future
gen 3+ agents working on hybrid constructions, ILP warm-starts, or large-k perturbation need the
explicit 102-element list instantly. JSON seed avoids re-derivation and prevents errors in loading
Singer set code.

**Expected impact**: Gen 3 agents start from the confirmed 102-element set without computation.

## PRIORITY 3 (Moderate — Infrastructure / Process)

### REC-7: Set explicit Singer exploitation mandate for exploit agents in gen 3

**What to change**: exploit agent briefs in gen 3 should explicitly state: "Singer constructions
are exhausted at 102. Your task is NOT to reimplement Singer q=101 or try other Singer primes.
Start from the hardcoded 102-element set (knowledge/seeds/sidon_102.json or sol02.py) and
focus exclusively on: [specific assigned strategy]."

**Why**: Without this constraint, exploit agents may default to implementing Singer infrastructure
that is already fully covered. The architect report itself noted this risk ("all eggs in Singer
q=101").

**Expected impact**: No gen 3 agent wastes time on Singer re-implementation.

---

### REC-8: Split exploit work in gen 3 by strategy, not by construction

**What to change**: In gen 2, two exploit agents independently confirmed Singer q=101. In gen 3,
each exploit agent should be assigned a distinct, non-overlapping strategy:
- exploit_1: large-k perturbation (remove 10-20 elements, exhaustive search over remainder)
- exploit_2: correct Bose-Chowla construction (not the carry-violating version)
- exploit_3 (if budget allows): Ruzsa's actual construction via Z_p Sidon sets + lifting

**Why**: Agent coordination is limited to brief-level instructions. Explicit strategy assignment
prevents redundant convergence on the same approach.

**Expected impact**: Three distinct approaches tested in one generation instead of two overlapping
ones.

## PRIORITY 4 (Minor — Monitor)

### REC-9: Consider adding SA early-termination logic in agent prompts

**What to change**: Add to exploit/full agent brief templates: "If SA runs for >30 seconds with
no improvement AND you have already computed that minimum blockers per non-member is >20, terminate
SA and pivot to a different strategy. High blocker counts make SA unlikely to improve even with
more time."

**Why**: exploit_2/sol03 ran SA for 114 seconds from the 102-element seed after already computing
40+ blockers. This was wasted time given available information.

**Expected impact**: Minor. Saves ~60-100 seconds per agent when SA is provably futile.

### REC-10: Evaluate whether a "knowledge seed" for gen 3 agents saves turns

**What to change**: The gen 1 Evaluator noted that having a `knowledge_dump.md` saved many turns
of individual file reads. For gen 3, given Singer exhaustion and the critical strategic shift,
the knowledge dump should prominently feature the "What No Longer Works" section at the top.

**Why**: Gen 3 agents face a harder search problem and must know immediately what not to try.
The knowledge dump format puts all knowledge in a single file, but buried dead-end information
may still be overlooked.

**Expected impact**: Minor. Agents skip known dead ends without reading through everything.
