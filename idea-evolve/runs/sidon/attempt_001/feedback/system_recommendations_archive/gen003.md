## PRIORITY 2 (High — Unlock Next Phase of Optimization)

### REC-5: Create a dedicated ILP agent in gen 4 with a correct formulation and offline budget

**What to change**: Assign one full agent session to ILP with:
- The difference-indicator formulation (not quadruple-constraint)
- Permission to run offline for 10+ minutes without the normal eval timeout
- Starting with small N (50, 100, 200) to verify Singer-optimality, then scale
- Explicit instruction: do NOT use the quadruple-constraint formulation (661,650 constraints)

**Brief excerpt to include**:
```
ILP FORMULATION (correct — use this, not the quadruple-constraint version):
Variables: x_i ∈ {0,1} for i in {0,...,N}, z_{d,a} ∈ {0,1} for d in {1,...,N}, a in {0,...,N-d}
Objective: maximize sum(x_i)
Constraints:
  z_{d,a} <= x_a            # z can only be 1 if a is in set
  z_{d,a} <= x_{a+d}        # z can only be 1 if a+d is in set
  x_a + x_{a+d} - 1 <= z_{d,a}   # z must be 1 if both a and a+d are in set
  sum_{a} z_{d,a} <= 1      # at most one pair per difference

For N=101: ~5000 x variables, ~5050 z variables, ~15250 constraints — manageable with CBC.
Try OR-Tools CP-SAT first; it's faster than PuLP/CBC for this problem structure.
```

**Why**: ILP has been highest priority for 3 generations with no successful test. The one
attempt used the wrong formulation. With a correct formulation, even a partial result for
small N would validate Singer optimality and tell us the ILP ceiling.

**Expected impact**: First successful ILP test. If Singer-102 is optimal at N=101, this
closes the ILP question. If ILP finds 103+ at some N, it opens a new search direction.

## PRIORITY 3 (Moderate — Process Hygiene)

### REC-8: Add a small-N sanity check requirement for all solution agents

**What to change**: Add to explore and exploit agent briefs:
```
BEFORE RUNNING FULL EVALUATION:
Test your algorithm at N=100 for 1-2 seconds. If it produces violations at N=100,
fix the algorithm before running at N=10000. A broken algorithm at N=10000 can block
an evaluation slot for 30+ minutes.
```

**Why**: explore_1/sol02 ran for 1728 seconds and produced 280,849 violations — the
algorithm had a fundamental defect that would have been visible in 2 seconds at N=100.
explore_2/sol02 had a diff-tracking bug (7 violations) that also would have failed fast.

**Expected impact**: Invalid solutions caught in <5 seconds instead of 29 minutes.
