## EXP-2 (HIGH): ILP with difference-indicator formulation, starting small

**What to test**: Implement ILP for Sidon sets using difference-indicator variables.
Test at N=50, 100, 200, 500. Compare optimal ILP result to Singer for each N.

**Hypothesis A**: For small N (50-200), ILP confirms Singer constructions are optimal
or near-optimal. This validates Singer as a ceiling for N=10000 by analogy.
**Hypothesis B**: ILP finds a construction with more elements than Singer for some N
(indicating Singer is not globally optimal and a different algebraic family might beat it).

**Implementation sketch**:
```python
from ortools.sat.python import cp_model  # prefer CP-SAT over PuLP/CBC

def solve_sidon_cpsat(N, time_limit_s=60):
    model = cp_model.CpModel()
    x = [model.NewBoolVar(f'x_{i}') for i in range(N+1)]
    model.Maximize(sum(x))

    # For each difference d, at most one pair (a, a+d) can both be 1
    for d in range(1, N+1):
        for a in range(N+1-d):
            # At most one of x[a], x[a+d] can be in the set for each d
            # More efficient: just add x[a] + x[a+d] <= 1 + z_{d,a} constraint
            # Actually for small N, direct forbidding all pairs:
            pass
    # Simpler encoding: for each difference d, collect all pairs that produce d,
    # add constraint: sum of x[a]*x[a+d] <= 1 (linearized)

    solver = cp_model.CpSolver()
    solver.parameters.max_time_in_seconds = time_limit_s
    status = solver.Solve(model)
    if status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
        return [i for i in range(N+1) if solver.Value(x[i])]
    return None
```

**Expected information gain**: First validated ILP result. Confirms or refutes Singer
optimality. If ILP beats Singer for some N<200, reveals a new construction family.

**Scale**: N=50 should solve in <5s. N=200 in 1-5 minutes. N=500 may require Gurobi.

## EXP-3 (HIGH): Vectorized min-blocking greedy (correct implementation)

**What to test**: Implement min-blocking greedy with proper Sidon checking using numpy
vectorization. Compare to standard greedy (66) and Fibonacci ordering (69).

**Hypothesis**: Min-blocking greedy (pick next element that blocks fewest future
candidates) should give 72-80 elements — better than standard greedy because it
minimizes future constraints, but still well below Singer (102). The gap between 69
(Fibonacci ordering) and 80+ is achievable via smarter candidate selection.

**Algorithm (correct version)**:
```python
import numpy as np

def min_blocking_greedy(N=10000):
    in_set = set()
    used_diffs = set()
    candidates = set(range(N+1))

    while candidates:
        # For each candidate c, compute how many candidates it would block
        # c blocks candidate c' iff |c - c'| is in used_diffs OR
        # |c - c'| would be a new diff that conflicts with existing pairs

        min_blocking = float('inf')
        best_c = None
        cand_list = list(candidates)

        # Vectorize: for each candidate c, count how many other candidates c'
        # would be invalidated by adding c
        # A candidate c' is blocked by adding c if:
        #   abs(c - c') in used_diffs  (c' can no longer be added)

        cand_arr = np.array(cand_list)
        for c in cand_list:
            new_diffs_from_c = {abs(c - s) for s in in_set}
            blocked = sum(1 for cp in cand_list if cp != c and
                         (abs(c - cp) in used_diffs or abs(c - cp) in new_diffs_from_c))
            if blocked < min_blocking:
                min_blocking = blocked
                best_c = c

        # Add best_c (always check valid first)
        new_diffs = {abs(best_c - s) for s in in_set}
        in_set.add(best_c)
        used_diffs.update(new_diffs)
        candidates.discard(best_c)
        # Remove newly blocked candidates
        candidates = {c for c in candidates if
                     not any(abs(c - s) in used_diffs for s in [best_c])}

    return sorted(in_set)
```

Note: The above is pseudocode-level. The actual numpy vectorization should replace the
inner Python loop with array operations.

**Expected information gain**: First valid result from min-blocking greedy. Determines
if the approach has genuine potential (70-80+) or is equivalent to standard greedy.

## EXP-4 (MODERATE): Analyze unused difference spectrum of Singer-102 set

**What to test**: For the 102-element Singer q=101 set, compute:
1. All C(102,2)=5151 pairwise differences (elements currently used)
2. The 4849 "free" differences in {1,...,10000} not currently used
3. Algebraic structure of the free differences (are they clustered? sparse? random?)
4. For each candidate c ∈ {0,...,10000} \ S, count which free differences it would use

**Hypothesis**: The free difference set has algebraic structure inherited from the
Singer construction. Understanding this structure might reveal:
- Why exactly 45 minimum blockers exist (not 40 or 50)
- Whether any algebraic transformation could add one element by "trading" differences
- Whether the free differences form another perfect difference set (enabling hybrid)

**Expected information gain**: Deep structural understanding of why 102 is a ceiling.
May reveal the "trading" mechanism that could theoretically add one element if the
free-difference structure permits it.

deployed to `problem/helpers/` after gen 3 output move).

## EXP-5 (MODERATE): Non-Singer perfect difference sets

**What to test**: Beyond Singer (from GF(q³)), what other cyclic perfect difference set
families exist for v near 10001? Candidates:
- Paley difference sets: v = q ≡ 1 (mod 4) prime, k = (q-1)/2
- Twin-prime construction: v = p(p+2)+1 for twin primes p, p+2
- Hall's sextic residue sets

For each family, find parameters giving v ≈ 10001 and check if truncation to {0,...,10000}
gives a competitive Sidon set.

**Hypothesis**: Other perfect difference set families may truncate more favorably than
Singer at N=10000 — i.e., have better alignment between v and N+1 that allows more
elements to fit.

**Expected information gain**: Either finds a construction that beats 102 (breakthrough)
or confirms Singer is the best-fitting PDS family near N=10001 (closes this direction).

## EXP-6 (LOW): Multi-Singer hybrid test

**What to test**: Take k₁ elements from Singer q=101 and k₂ elements from a completely
different algebraic construction (e.g., ET p=71 gives ~75 elements). Check if any
combination of k₁ + k₂ elements is Sidon.

**Hypothesis**: Algebraic families have different difference sets. Singer q=101 uses
differences in a specific algebraic structure. ET p=71 uses a different structure. If
these structures are "compatible" (minimal overlap in differences used), their elements
can be combined into a larger Sidon set.

**Implementation**:
```python
def test_multi_singer_hybrid(N=10000):
    from helpers.singer import find_singer_set
    from helpers.core import is_sidon

    singer_101 = find_singer_set(101, N)  # 102 elements
    et_71 = erdos_turan_set(71, N)        # ~75 elements

    # Try combining subsets: take top k1 from singer, try adding elements from et
    for k1 in range(102, 70, -5):
        base = singer_101[:k1]
        for et_elem in et_71:
            if et_elem not in set(base):
                candidate = base + [et_elem]
                if is_sidon(candidate):
                    print(f"Added ET element! Base={k1}, new size={len(candidate)}")
```

**Expected information gain**: If the combination yields more than 102 elements, this
is a breakthrough. If it yields zero combinations even for k1=70, confirms algebraic
incompatibility and closes the hybrid direction. Fast experiment (~5 minutes).

**Note**: The experimentator's analysis suggests theoretical promise is weak (only ~47
free differences available), but it's a fast test worth running.
