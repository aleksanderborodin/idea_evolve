## [EXP-1] VLNS with corrected formulation

**Priority:** CRITICAL
**Agent type:** full or exploit
**Compute:** 50 trials × <1s each = ~60s total (after fix)

**What to test:**
Fix the VLNS domain bug identified by full_1 gen6:
1. Change `add_abs_equality(d, y[i] - fv)` domain from `[1, N]` to `[0, N]`
2. Add explicit `model.Add(y[i] != fv)` for each fixed element `fv` BEFORE the abs constraint
3. Run 50 trials: random-5, random-10, random-15, random-20 removals, high-blocker-10, spread-20

**Hypothesis:** The current INFEASIBLE results are formulation artifacts. With correct formulation, at least some trials should find feasible replacements (possibly still size 105, but finding ANY feasible solution validates the approach). If still all INFEASIBLE with correct formulation, this is genuine evidence that 106-element replacements of any 20+ removed elements don't exist.

**Expected outcome:**
- IF trials find 105-element sets: confirms VLNS can find alternative maximal sets; run 500+ trials targeting 106
- IF trials find 106-element set: major breakthrough
- IF still INFEASIBLE after correction: strong evidence for local optimality; archive VLNS

**Information gain:** Extremely high. Resolves the biggest ambiguity from gen 6 in under 5 minutes.

## [EXP-3] CP-SAT with binary variable formulation (different from AllDifferent)

**Priority:** HIGH
**Agent type:** full
**Compute:** 1800s (30 min, 16 workers)

**What to test:**
Instead of "find a set of k integers where all pairwise differences are distinct" (AllDifferent over differences), encode as:
- Binary variables x_i ∈ {0,1} for i in {0,...,N}
- Objective: maximize sum(x_i)
- Constraints: for each triple (i,j,k,l) where i-j = k-l, add constraint x_i + x_j + x_k + x_l ≤ 3
  (equivalently: not all four of i,j,k,l are in the set)
- Add known 105-element set as initial solution (warm start via CP-SAT SolutionHint)
- Run for 1800s with num_workers=16

**Hypothesis:** The AllDifferent formulation requires OR-Tools to reason about 5565 difference variables simultaneously. The binary variable formulation encodes the same constraint as O(N²) forbidden 4-tuples. CP-SAT presolve may handle forbidden-assignment propagation much better than domain-based AllDifferent. The feasible solution hint makes the first incumbent easy to find.

**Expected outcome:**
- Best case: finds 106-element set
- Likely case: finds 105-element set quickly (confirms warm start works), makes slow progress toward 106
- Worst case: UNKNOWN again — at least confirms the problem is hard regardless of formulation

**Information gain:** High. If UNKNOWN, we learn the problem is intrinsically hard for CP-SAT; consider commercial solvers (Gurobi) or fundamentally different approaches.

## [EXP-4] Anti-algebraic CP-SAT

**Priority:** HIGH
**Agent type:** full or exploit
**Compute:** 1800s

**What to test:**
Run CP-SAT with the binary variable formulation (EXP-3) but add an additional constraint:
- Let S₁₀₅ = the 105-element Rokicki-Dogon set
- Add constraint: sum(x_i for i in S₁₀₅) ≤ 52 (solution shares ≤50% with known best)

This forces CP-SAT to search in the non-algebraic region of the solution space.

**Hypothesis:** All CP-SAT runs so far have warm-started from or near the 105-mark set. Small-N analysis (gen5) shows optimal sets share only ~8% of elements with algebraic constructions (at small q). If this generalizes, CP-SAT may be stuck in the wrong basin. The anti-algebraic constraint forces exploration of a completely different region.

**Expected outcome:**
- IF finds 106-element set: proves a non-algebraic path to 106 exists
- IF finds 105-element set: confirms alternative optimal sets exist in non-algebraic region (useful for VLNS seeding)
- IF UNKNOWN: consistent with 106 not existing in either algebraic or non-algebraic region

**Information gain:** High. Tests the "wrong basin" hypothesis that may explain why CP-SAT keeps returning UNKNOWN.

## [EXP-5] Maximize-k CP-SAT formulation

**Priority:** HIGH
**Agent type:** full
**Compute:** 1800s

**What to test:**
Instead of "find exactly k=106 elements", use:
- Binary variable formulation (as EXP-3)
- Objective: MAXIMIZE sum(x_i) (no target k)
- Hint: the 105-element set (incumbent = 105)
- Run for 1800s

**Hypothesis:** "Find exactly k=106" is a feasibility problem — the solver gets no feedback until it finds the target or proves infeasibility. "Maximize k" gives the solver an objective gradient to follow. The solver can first confirm k=105 (easy with hint), then incrementally try to improve. This provides search guidance that feasibility checking lacks.

**Expected outcome:**
- Best case: solver finds 106 incrementally
- Likely: solver confirms 105 quickly, gets stuck at 105
- Information value of "stuck at 105": stronger than UNKNOWN from feasibility problem (objective optimization + UNKNOWN ≈ OPTIMAL at 105)

## [EXP-6] Blocking power-guided VLNS (if EXP-1 succeeds)

**Priority:** MEDIUM (contingent on EXP-1 positive result)
**Agent type:** exploit
**Compute:** 2000s

**What to test:**
Using the blocking power analysis from gen6 experimentator_1 (`blocking_power(BEST_105)`):
1. Sort elements by blocking power (descending)
2. Fix the 85 HIGHEST-blocker elements (keep the elements that block the most candidates)
3. Free the 20 lowest-blocker elements
4. Run VLNS to find replacement 20 elements

**Hypothesis:** Random removal in the gen6 VLNS trials included high-blocker elements, making replacement hard. Removing only low-blocker elements creates a more open neighborhood for CP-SAT to fill.

**Expected outcome:** Higher success rate for VLNS than random removal. If the 20 lowest-blocker elements can be replaced with 21 elements, achieves 106.

## [EXP-7] SA from ET(71)+1-opt 75-element seed

**Priority:** MEDIUM
**Agent type:** explore
**Compute:** 300s

**What to test:**
Start SA at the 75-element ET(71)+1-opt local optimum (not greedy/Singer seed as in prior SA runs):
- Temperature: accept moves that decrease size by 1-2 elements with 20% probability
- Cooling: reduce temperature every 100 iterations
- Run 10 independent restarts with different random seeds

**Hypothesis:** All prior SA runs started from greedy (~66) or algebraic (~102-105) seeds. The 75-element ET local optimum is in a different region of the search space. If SA can escape the 75-plateau, it might find 76-80 range. Unlikely to reach 105, but could validate whether the 75 plateau is a hard barrier or just an SA initialization effect.

**Expected outcome:** Likely stays at 75. If finds 76+, opens a new non-algebraic search direction. Low expected value but low cost.

## [EXP-8] Swap graph enumeration of 105-element sets

**Priority:** LOW
**Agent type:** exploit
**Compute:** indefinite (background task)

**What to test:**
Starting from the 105-mark Bose-Chowla set, perform systematic "swap" moves:
- Remove element e, find all single elements that can replace it (maintaining 104 existing + 1 new = still Sidon)
- BFS/DFS the graph of all 105-element Sidon sets reachable by single swaps
- Count: how many distinct 105-element Sidon sets exist in the swap neighborhood?

**Hypothesis:** The swap graph is finite (combinatorial structure). If only 1 set exists (the algebraic one), this confirms uniqueness and means any improvement requires changing 2+ elements simultaneously. If multiple sets exist, one might be extensible to 106.

**Expected outcome:** Unknown. exploit_1 gen6 found 10 swap-walk sets all greedy-maximal. Full enumeration would determine if the algebraic set is locally isolated or part of a cluster.

**Information gain:** Moderate. Mostly of theoretical interest — self-healing property already suggests 105-mark set is uniquely rigid. Run only if EXP-1 through EXP-5 are completed.
