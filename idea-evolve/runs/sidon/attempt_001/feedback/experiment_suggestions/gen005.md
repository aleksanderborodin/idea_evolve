# Experiment Suggestions — Generation 6

**Context:** Algebraic ceiling confirmed at 105. All greedy/beam search approaches exhausted.
CP-SAT (k≤105, ≤600s/phase) consistently UNKNOWN. The remaining gap is 4-9 elements.
These suggestions focus exclusively on computational search for 106+.

## Tier 1: Highest Priority (assign in gen 6)

### [EXP-1] Remove-k Perturbation on 105-mark Set (k=2-8)

**Hypothesis:** The 105-mark Golomb ruler has structural redundancy — removing k elements
and re-inserting optimally may reveal k+m elements can fit where the greedy path
couldn't see. k=1,2 exhausted (4000 trials). k=3-8 unexplored.

**What to do:**
1. Load the 105-mark set from `population/gen005/experimentator_1/sol01.py` (or the static helper)
2. Implement remove-k perturbation: randomly select k elements to remove, run greedy extension
   from the residual set, check if result > 105
3. Try k=2 (1M trials), k=3 (100K trials), k=4 (10K trials), k=5-8 (1K trials each)
4. Record the distribution of outcomes — even if max stays at 105, the distribution reveals
   how tight the packing is

**What we learn:** Whether the 105-mark set is locally optimal up to k-swaps, or whether
there's a structurally different 106-element neighborhood reachable via perturbation.

**Expected information gain:** HIGH — either we improve past 105 or we confirm it's a
local optimum under k-swap perturbation, narrowing the search.

**Agent:** exploit_1 or full_1. Target: 150 turns.

## Tier 2: High Value (assign if budget permits)

### [EXP-3] HiGHS Solver on k=106

**Hypothesis:** OR-Tools CP-SAT may not be the best solver for Golomb ruler-type problems.
HiGHS is free, fast, and handles 0-1 integer programs. It uses a different LP relaxation
strategy that may close the k=106 gap faster.

**What to do:**
1. Install `highspy` (pip install highspy) or use `scipy.optimize.milp` (uses HiGHS backend)
2. Reformulate the problem as a binary IP: x_i ∈ {0,1} for i ∈ {0,...,10000},
   maximize Σx_i subject to all pairwise difference constraints
3. Run with k=106 as a lower bound hint (add: Σx_i ≥ 106 if trying to prove feasibility)
4. Compare solve time and node count against CP-SAT

**What we learn:** Whether the LP relaxation quality differs between solvers. If HiGHS makes
significantly faster progress, switch primary solver for subsequent runs.

**Expected information gain:** MEDIUM — diagnostic value even if no improvement.

**Agent:** full_1 or experimentator_1.

### [EXP-4] Binary Search on N for k=106 Feasibility

**Hypothesis:** While k=106 in {0,...,10000} may be hard for the solver, the problem becomes
easier for larger N (more room to fit elements). Binary search on the minimum N where k=106
is feasible reveals whether 106 is achievable at all and gives the solver a feasible region
to work from.

**What to do:**
1. Start with N=50000 (roughly 5× our target): verify k=106 is trivially feasible by scaling
   the 105-mark set (multiply all elements by ≈5)
2. Binary search downward: test N=25000, N=15000, N=12000, N=10500, N=10000
3. For each N, run CP-SAT for 60s — FEASIBLE or INFEASIBLE in 60s is enough signal
4. Record the minimum N where k=106 is feasible

**What we learn:** The "span" required for a 106-element Sidon set. If min-N ≈ 10000,
we're very close. If min-N ≈ 12000, we know k=106 for {0,...,10000} is genuinely hard.
This is high-value structural information.

**Expected information gain:** HIGH — concrete bound on how close we are.

**Agent:** explore_1.

### [EXP-5] Greedy Extension from 105-mark Set Using Varied Orderings

**Hypothesis:** The 105-mark set is greedy-maximal under standard ordering (add smallest
valid element first). Other traversal strategies (random order, high-density first, start
from middle) may find different maximal extensions.

**What to do:**
1. Start from the 105-mark set with 1 element removed (the last one, which is likely the
   element whose removal leaves the most "room")
2. Try adding elements back using: (a) standard greedy, (b) random order, (c) backward greedy
3. Run 1000 independent random-order trials and record the distribution of outcomes
4. Check if ANY trial reaches 106+

**What we learn:** Whether the 105-mark set's maximality is an artifact of insertion order
(unlikely but cheap to verify) or structural.

**Expected information gain:** MEDIUM — likely confirms 105 ceiling but rules out an
entire class of trivial improvements.

**Agent:** explore_2. Budget: 50 turns.

analysis. Either confirms this (archived as debunked) or surprises us.
