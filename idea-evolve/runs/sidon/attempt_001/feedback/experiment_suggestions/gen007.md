## EXP-5 (Critical Priority) — Binary Variable CP-SAT Maximize-k

**What:** Solve Sidon set as integer program with binary decision variables x_i ∈ {0,1}
for each candidate position i ∈ {0,...,10000}. Maximize Σx_i subject to: for each sum s,
at most one pair (i,j) with i<j and i+j=s can both have x_i=x_j=1.

**How:** Use `helpers/cpsat.py` (now available as of gen7). Key difference from prior
CP-SAT runs: MAXIMIZE objective, not "find exactly k=106." The maximization gives the
solver a gradient to follow, making it easier to improve incrementally beyond 105.

**Warm-start:** x_i=1 for i in BEST_105, x_i=0 otherwise (provided by rokicki_data.py).

**Time budget:** Minimum 3600s (1h), ideally 4h+. Use 8-16 workers.

**What we expect to learn:**
- If INFEASIBLE: F₂(10000) = 105 is computationally confirmed. Combined with literature
  (no published 106-mark construction) and VLNS evidence, this constitutes a high-confidence
  proof. Pipeline should halt.
- If finds 106+: Major breakthrough. Record the construction, pivot all resources to
  understanding it and pushing further.
- If UNKNOWN after 4h: The formulation may need further refinement (forbidden 4-tuples
  encoding instead of at-most-one-pair; larger time budget; different solver).

**Notes:**
- Do NOT use AllDifferent over differences (confirmed pathological for CP-SAT presolve)
- Do NOT use the decision k=106 formulation (confirmed to return UNKNOWN for 6000s+)
- The maximization formulation is genuinely different; its behavior is unknown

**CRITICAL:** This is the single most important experiment in the pipeline. Agent assigned
to this should start coding immediately without reading context. Formulation pseudocode
should be inline in the brief.

## EXP-NEW2 (Medium Priority) — Tabu Search with Swap-Then-Fill

**What:** Implement a tabu search on the 105-mark set using swap moves: remove one element,
try to add a different element (not any of the removed elements), then greedily extend.
Maintain a tabu list of recently removed positions to prevent returning to BEST_105.

**Key difference from VLNS:** VLNS uses CP-SAT for replacement; tabu uses a greedy heuristic.
VLNS is provably optimal for the replacement; tabu is faster and explores broader configurations.

**Implementation sketch:**
```python
def tabu_step(current_set, tabu_list, N, k_tabu=20):
    # Try each element as removal candidate
    for remove_elem in current_set:
        if remove_elem in tabu_list: continue
        candidate_set = current_set - {remove_elem}
        # Extend greedily
        extended = greedy_extend(candidate_set, N)
        if len(extended) > len(current_set):
            tabu_list.append(remove_elem)
            return extended, tabu_list
    return current_set, tabu_list  # no improvement found

# Run 10000 steps
current = set(BEST_105)
tabu = deque(maxlen=20)
for _ in range(10000):
    current, tabu = tabu_step(current, tabu, N=10000)
```

**What we expect to learn:**
- Whether the tabu list allows escape from the BEST_105 self-healing basin
- Whether any other 105-element configuration exists in [0,10000]
- Time per step to calibrate whether 10K or 100K steps is feasible

**Expected outcome:** Likely still plateaus at 105. But if it finds a DIFFERENT 105-element
set (same size, different elements), that's a valuable structural discovery.

**Time budget:** 1-2h. Should run 100K+ steps in that time.

## EXP-NEW3 (Medium Priority) — Anti-Algebraic CP-SAT (Force Different Basin)

**What:** Binary variable CP-SAT maximize-k with additional constraint forcing the
solution to be "far" from BEST_105: Σ(x_i for i in BEST_105) ≤ 52. This forces the
solver to find a Sidon set sharing at most half its elements with the known 105-mark set.

**How:**
```python
from ortools.sat.python import cp_model
# After setting up standard maximize-k CP-SAT formulation:
model.add(sum(x[i] for i in BEST_105) <= 52)  # Force non-algebraic basin
```

**What we expect to learn:**
- Whether there exists any Sidon set in [0,10000] of size ≥75 that is NOT near BEST_105
- Whether the algebraic basin (Singer/Bose-Chowla/Ruzsa) dominates the entire landscape
- If it finds 105 in a different basin: multiple 105-mark optima exist, search space is larger

**Expected outcome:** Likely finds 75-90 elements in the non-algebraic basin, confirming
the algebraic basin is globally optimal. OR finds another 105-mark set (low probability).

**Time budget:** 2-3h.
