# Agent Gaps — Generation 1

## Gap 1: explore_1 did not save the actual 99-element set for reuse

explore_1 noted in their debrief: "I didn't print/save the actual list for future agents
to start from." The 99-element sets are saved as Python code in sol02-04, but extracting
the explicit list requires running the code (which takes 55-115 seconds). A pre-computed
list in a text file would save future agents significant time.

**Recommendation**: Next generation's exploit agent should start from explore_1/sol02 and
extract + save the explicit 99-element list.

## Gap 2: No agent tested Singer q=101 truncation

The research agent identified Singer q=101 truncation with cyclic shifts as the most
promising path to 100, but no solution agent implemented it. This is the highest-priority
gap — the strategy is well-specified and ready for implementation.

**Recommendation**: Assign a dedicated agent to implement Singer q=101 + cyclic shift
optimization in generation 2.

## Gap 3: full_1 attempted wrong algebraic construction

full_1 tried the parabola construction {i*p + i²%p} which fails for large primes. If
full_1 had known about Singer difference sets (which were in the research brief and idea_004),
it could have achieved 98+ instead of 66. This suggests the brief may not have clearly
communicated the Singer construction priority.

**Recommendation**: Generation 2 briefs should explicitly state "start from Singer q=97
construction (98 elements)" as the baseline for all agents.

## Gap 4: explore_2 spent all time on search from greedy baseline

explore_2 was assigned metaheuristic optimization and worked entirely from the greedy-66
baseline. If it had started from the Singer-98 seed (or known about it), SA might have
reached 100+. The agents operated in parallel and couldn't share the Singer breakthrough.

**Recommendation**: In generation 2, all agents should receive the Singer q=97 set as a
known starting point. No agent should work from the greedy-66 baseline.

## Gap 5: Buggy solutions in explore_2

Two of six solutions from explore_2 were invalid (sol02: 1 violation; sol06: 1 violation).
Both bugs were due to incorrect exclusion logic in the 2-opt implementation. These bugs
wasted compute and produced no useful results.

**Recommendation**: Agents should validate their solutions before submitting (run is_sidon()
or count_violations() as a final check).

## Gap 6: Research findings not available to solution agents in real time

The research agent's finding about Singer q=101 truncation was only available post-generation.
Solution agents could not benefit from it during their work session.

**Recommendation**: This is a structural limitation of parallel execution. Mitigate by
ensuring the Architect's brief includes the most promising untested strategies from research.

## Gap 7: Upper bound correction needed

The initial facts stated the upper bound is approximately 100-102. The research agent found
it is actually ~109 (Carter, Hunter, O'Bryant 2025). This underestimate may cause agents
to prematurely conclude that 99-100 is near the theoretical ceiling.

**Recommendation**: Update fact files to reflect the correct upper bound of ~109.
