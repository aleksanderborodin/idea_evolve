## REC-2 [CRITICAL] Communicate 24 µs Target Infeasibility to User

**What to change:** Write a brief note to the user explaining that experimentator_1's
bandwidth measurements show the physics floor is ~62 µs (geometric mean, optimistic), not 24
µs. The 24 µs target cannot be achieved without a fundamentally different output format or
benchmark model. Propose a revised target of 60–80 µs and ask the user to confirm or clarify.

**Why:** Three agents (exploit_1, research_1, experimentator_1) independently calculated that
the 24 µs target is below the memory bandwidth floor. Continuing to chase it wastes resources
and demoralizes agents that correctly understand the physics. A realistic target (60–80 µs)
would still require a significant breakthrough (row-streaming + NT stores + 8-row int8 kernel)
but is physically achievable.

**If the user intentionally set an infeasible target** (e.g., to test the pipeline's ability
to find non-obvious solutions like compressed output), the pipeline should be told this explicitly.

**Expected impact:** Aligns agent energy with achievable goals. Prevents agents from concluding
"this is impossible" and giving up rather than finding creative solutions.

## REC-6 [HIGH] Assign Aligned-Buffer NT Store Workaround as Top Gen-3 Priority

**What to change:** Brief at least one gen-3 exploit or explore agent with explicit,
step-by-step instructions for the aligned-buffer NT store workaround:

```
Take explore_1/sol01 (row-streaming best, 147.26 µs).
Add to the C++ kernel:
  // For n*m*4 > 8MB (large benchmark only):
  std::unique_ptr<int, decltype(&free)> cbuf(
    (int*)std::aligned_alloc(64, n * m * 4), &free);
  // Compute into cbuf using _mm512_stream_si512
  _mm_sfence();
  std::memcpy(C, cbuf.get(), n * m * 4);
Evaluate and compare to the base solution.
```

**Why:** This is the highest-leverage optimization identified in gen 2 (2.3x on large from
NT stores, verified by experimentator_1). The C alignment problem is a known harness
constraint (fact_006). The workaround was described by the evaluator, experimentator_1,
research_1, and agent_gaps — but nobody built it.

**Expected impact:** If NT store benefit (2.3x on large) survives memcpy overhead, large
drops from ~3900 µs to ~1700-2000 µs. Geomean drops from ~147 µs to ~80-100 µs.

## REC-7 [HIGH] Add 8-Row int8 Kernel as Mandatory Gen-3 Exploit Experiment

**What to change:** Assign one gen-3 agent (exploit or explore) to implement the 8-row int8
kernel as described in idea_016. Provide a concrete starting brief:

```
Start from the 4-row int16 kernel in population best. Modify to:
- Process 8 rows simultaneously (8 zmm accumulators instead of 4×2 for int16)
- Accumulate in int8 (safe for k_bytes ≤ 15, which covers all benchmark sizes)
- Flush int8 → int32 once per k-outer-loop iteration, not per k-byte
Pack 8 A rows instead of 4. Verify correctness before benchmarking.
```

**Why:** experimentator_1 confirmed int8 accumulation gives 11-13% improvement. The 8-row
kernel doubles compute density per B-panel load. Combined, this is the strongest unbuilt
optimization after NT stores. research_1 provided the theoretical foundation. Nobody built it.

**Expected impact:** 20-30% improvement over current best (medium), potentially 3-4x overall
when combined with NT stores for large.
