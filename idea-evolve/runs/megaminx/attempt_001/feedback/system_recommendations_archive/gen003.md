## REC-1: Mandate Incremental Milestone Protocol for Complex Tasks (CRITICAL)

**What to change:** The architect prompt must include a mandatory "Milestone Protocol" section. Every brief for a complex implementation task (predictor training, helper construction, algorithm implementation) MUST include:

1. **Milestone 1 (first 1/3 of session):** Produce a minimal scored solution. For predictor tasks: train on 1000 samples, test on 1 puzzle, save as sol01. For exploration tasks: implement on puzzles with id ≤ 20 only, save as sol01.
2. **Explicit "save NOW" instruction** after milestone 1 is confirmed working.
3. **Milestone 2+ (remaining session):** Scale up, add complexity, iterate.

**Why:** 3/5 agents in gen003 were assigned complex, multi-step tasks with no intermediate checkpoints. All three timed out with zero output. The "all or nothing" failure mode wasted 70% of generation compute.

**Expected impact:** If each agent saves a minimal solution early, the worst case becomes "suboptimal score" instead of "zero output." Agent success rate should improve from 40% to 70%+.

**How to implement:** Add a section to `agents/architect.md`:

```
## Milestone Protocol (MANDATORY for implementation tasks)

For any brief that requires implementing non-trivial code (model training, helper construction, new algorithms):
- Milestone 1: Minimal working version, scored and saved as sol01. Must be achievable in first 1/3 of session time.
- Milestone 2+: Scale up, add complexity, iterate from the scored baseline.
- NEVER attempt the full pipeline in one step without a scored intermediate checkpoint.
```

## REC-4: Reduce Work Session Timeouts for Complex Tasks (HIGH)

**What to change:** Default work session timeout should be 900s (15 min), not 2700s (45 min). Agents that haven't produced a scored solution in 900s are stuck and unlikely to produce one in 2700s.

**Why:** explore_1 consumed 6301s (1h 45min) across three phases with zero output. exploit_1 consumed 3600s with zero output. The current timeout structure rewards stubbornness — an agent that's stuck gets 45 minutes to remain stuck.

**Expected impact:** Faster failure detection, more generations per wall-clock hour, less wasted compute. If an agent needs more time after producing a scored solution, the architect can assign a longer timeout in the manifest.

**How to implement:** Change `DEFAULT_TIMEOUTS` for work sessions from 2700 to 900. Keep wrap-up at 300s and debrief at 300s. Total max session: 1500s (25 min) instead of 6300s (105 min). The architect can override per-agent in manifest.yaml for tasks known to need more time.
