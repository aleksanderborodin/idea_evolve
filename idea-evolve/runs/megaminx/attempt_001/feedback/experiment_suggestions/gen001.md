# Experiment Suggestions — Generation 2

Experiments ranked by expected information gain and cost.

## EXP-1: Hamming predictor baseline (HIGHEST PRIORITY, ZERO COST)

**Hypothesis:** Even the simplest guided search (Hamming-distance predictor) adds value over pure compression on hard/very_hard puzzles.

**Method:**
1. Load graph via `Puzzles.megaminx()`
2. Create predictor via `Predictor(graph, 'hamming')`
3. Run `beam_search(state, predictor=predictor, beam_width=2000, max_steps=200)` on all 101 proxy puzzles
4. Compare fitness (total path length) against compression baseline (46312)

**What to learn:**
- Does ANY predictor-guided search beat compression? (yes/no)
- Which depth buckets benefit most?
- Is hamming predictor good enough, or is trained predictor required?

**Expected time:** <5 minutes. No training data, no training time.

---

## EXP-2: Trained MLP predictor — first measurement (HIGH PRIORITY)

**Hypothesis:** A trained MLP predictor can guide beam search to find paths significantly shorter than compression for hard/very_hard puzzles.

**Method:**
1. Generate 50,000 random walks (length 20) via `graph.random_walks(50000, 20)`
2. Train 3-layer MLP (hidden 256) for 5 epochs on (state, distance) pairs
3. Run `beam_search(predictor=trained_model, beam_width=2000, max_steps=200)` on all 101 proxy puzzles
4. Record fitness, timing, per-bucket breakdown

**What to learn:**
- What fitness does trained predictor-guided beam search achieve?
- Is eval budget (~7 min for 101 puzzles) sufficient for GPU training + beam search?
- Where does the predictor fail (which depth bucket)?

**Expected time:** 5-15 minutes with GPU.

## EXP-3: MITM coverage measurement (MEDIUM PRIORITY)

**Hypothesis:** MITM can solve a meaningful fraction of proxy puzzles optimally or near-optimally.

**Method:**
1. Precompute BFS to depth 5, 6, 7 from solved state
2. For each proxy puzzle (id 0-1000), check if bidirectional BFS with depth limit finds optimal path where optimal distance ≤ 2 × BFS_depth
3. Record coverage fraction per bucket

**What to learn:**
- What fraction of each bucket is solvable via MITM within tractable depth?
- Is MITM useful only for short/medium bucket, or does it help for hard?
- This quantifies MITM's ceiling and informs whether to combine MITM with predictor guidance.

**Expected time:** 10-20 minutes for BFS precomputation + coverage measurement.

---

## EXP-4: Predictor generalization across depth ranges (MEDIUM PRIORITY)

**Hypothesis:** A predictor trained on length-20 random walks generalizes poorly to depth-500+ puzzles.

**Method:**
1. Train predictor on random walks of length 20 only
2. Evaluate on proxy puzzles at varying depths (short/medium/hard/very_hard)
3. Measure whether predicted distance correlates with actual distance across depth ranges
4. Compare beam search results using predictor trained on distribution-matched vs mismatched data

**What to learn:**
- Does training distribution mismatch limit predictor usefulness?
- Is domain randomization (training on varied depths) necessary?
- This informs whether we need depth-targeted training data.

**Expected time:** 15-30 minutes.

## EXP-5: Kaggle notebook replication — fedimser beam search (IF NOTEBOOK ACCESSIBLE)

**Hypothesis:** The `fedimser/beam-search-with-cayleypy` notebook contains beam search tuning insights (beam_width vs max_steps vs restart strategy) applicable to this problem.

**Method:**
1. Fetch notebook via kaggle CLI
2. Extract beam search parameter recommendations
3. Run parameter sweep on proxy puzzles to identify optimal beam configuration
4. Compare against current best (46312)

**What to learn:**
- What beam parameters does top solution use?
- Does restarts strategy matter for deep puzzles?
- Does guided beam search with tuned parameters beat compression + unguided beam search?

**Expected time:** 30-60 minutes if notebook is accessible.

## EXP-6: Long-range cancellation patterns (LOW PRIORITY, COMPLEMENTARY)

**Hypothesis:** Non-adjacent cancellation patterns (e.g., X.Y.-X.-Y) exist in sample_submission paths and could yield additional compression beyond X.-X.

**Method:**
1. Analyze sample_submission paths for cancellation patterns of span 2-5 moves
2. Build a pattern dictionary of cancellable sequences
3. Apply extended compression pass using the dictionary
4. Measure additional compression ratio per bucket

**What to learn:**
- What is the theoretical ceiling for compression-only approaches?
- Are there systematic Megaminx identities exploitable by compression?
- Complementary to predictor approach — may yield 1-3% improvement.

**Expected time:** 10-20 minutes.
