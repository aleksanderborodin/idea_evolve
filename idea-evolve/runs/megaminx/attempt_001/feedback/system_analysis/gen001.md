# System Analysis — Generation 1

## Pipeline Problems

### P1: Helper friction blocked the highest-value direction (CRITICAL)

**Evidence:** `cayleypy_beam_solver` in `helpers/core.py` does not expose the `predictor` kwarg that `graph.beam_search` accepts. Multiple agents (`explore_1`, `explore_2`, `full_1`) tried beam search with unguided parameters and converged to the same ceiling (46312). No solution implemented predictor-guided beam search despite `research_1` confirming the entire ML pipeline works in this environment.

**Root cause:** The recommended entry point (`cayleypy_beam_solver`) is incomplete. Agents using it hit a dead end and didn't know to call the cayleypy API directly because the helper is documented as the primary interface.

**Severity:** Critical — the primary path to the target (predictor-guided search) was confirmed viable but never taken because of friction at the helper layer.

---

### P2: No agent ran the zero-cost hamming predictor baseline (CRITICAL)

**Evidence:** `research_1` discovered `Predictor(graph, 'hamming')` exists as a built-in zero-cost predictor but never ran it. No other agent mentioned it. The evaluator report lists `idea_006` (hamming predictor) as "active, not tried." The entire hamming predictor experiment is untested.

**Root cause:** Research agent ran out of time before running any predictor experiment. No agent was tasked specifically with quick win experiments.

**Severity:** Critical — we don't know if even the simplest guided search adds value over compression. This is the cheapest possible experiment (no training data, no training time) and it's completely untested.

---

### P3: Unguided beam search was exhaustively explored despite mathematical impossibility (MODERATE)

**Evidence:** `full_1` tried beam widths from 512 to 2048 across depth buckets. `explore_2/sol05` tried beam search. `explore_1` tried beam widths 1000-4000, max_steps 150-300. All converged to the same result as compression (46312). The growth function (depth 8 = 3.5B states, depth 9 = 48B) makes it mathematically impossible for unguided beam search to cover the state space for hard/very_hard buckets.

**Root cause:** No agent incorporated the growth function analysis into strategy. Agents kept trying wider beams despite the state-space mathematics being well-documented in `initial_facts.md`.

**Severity:** Moderate — resources wasted on a direction that was mathematically proven impossible before the generation started. However, the total time spent was small (~minutes) so impact is limited.

## Prompt Problems

### P4: `initial_facts.md` has conflicting hardware descriptions (MODERATE)

**Evidence:** Architect report (line 7) noted: one block describes GPU + MPS parallelism; another block says CPU-only. Multiple agents read this file and could have formed incorrect hardware assumptions.

**Severity:** Moderate — causes confusion about whether GPU is available. The RTX 5060 Ti is present and documented in `research_1`'s observations as "available but unused by default."

---

### P5: `helpers/README.md` has wrong `PROXY_SIZE` (MINOR)

**Evidence:** README says `PROXY_SIZE = 100`; actual code and `description.md` say `101` (ids 0,10,20,...,1000). Three agents noted this inconsistency.

**Severity:** Minor — actual code is correct, but agents waste time noting the discrepancy.

### P7: Beam search failures were not diagnosed

**Evidence:** `explore_1` debrief (line 24): "I couldn't see why beam search was failing to find shorter paths. Was it returning None? Returning longer paths?" No solution logged `beam_search` return values in a structured way. `full_1` similarly didn't diagnose beyond "beam search saturates."

**Impact:** Future agents cannot learn from gen 1's beam search failures. The failure mode (beam returns None for deep puzzles, or returns paths no shorter than compression) is established but not recorded in a way that prevents the same diagnosis from being repeated.

---

### P8: Predictor training pipeline timing unknown

**Evidence:** `research_1` (line 17): "timed out at 60s on one test" for beam_search + predictor. GPU timing data is entirely absent. We don't know if predictor-guided beam search is practical within the eval budget (~7 min for 101 puzzles).

## Knowledge Quality Issues

### P9: State of Affairs is accurate but thin (expected for gen 1)

The State of Affairs correctly established the compression baseline, identified the dead ends, and prioritized ideas. No issues with accuracy. The thinness (no clusters, no coverage matrix at gen 0) is expected for a first generation.

---

### P10: `initial_facts.md` growth function implications not incorporated into strategy

`research_1` documented the growth function (depth 8 = 3.5B, depth 9 = 48B) and noted it "makes it crystal clear why single-pass BFS/beam cannot work." Yet none of the solution agents explicitly used this to rule out unguided search. The information was in the facts file but not effectively surfaced in agent prompts or briefs.

**Impact:** Agents spent time on unguided beam search that the growth function proves is futile for hard/very_hard buckets. This is a prompt/brief gap — the growth function implications should have been highlighted in agent briefs.

The manifest had a single parallel group with 4 agents. This was appropriate for gen 1 cold start. No bottleneck issues observed. Timing was reasonable (research_1 ran out of time, but others completed).

**Observation:** `research_1` reported needing "at least one more hour" to finish critical experiments (fetching missing notebooks, running ML pipeline). The 1800s timeout may have been too tight for a research agent doing Kaggle notebook fetching plus API verification.

## Summary

The generation successfully established a compression baseline and confirmed that the ML pipeline works in this environment. However, no agent actually implemented predictor-guided beam search — the primary path to the target — due to helper friction and time constraints. The zero-cost hamming predictor experiment is completely untested. The most impactful fixes for gen 2 are:

1. Remove helper friction so agents can access predictor-guided beam search
2. Task an experimentator with running the hamming predictor baseline immediately
3. Give research agents more time or narrower scope
