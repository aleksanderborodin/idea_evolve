# System Analysis — Gen 004

## Pipeline Problems

### PA-1: Agent failure rate remains at 60% for the second consecutive generation (CRITICAL)

**Evidence:** In gen004, 3/5 agents produced zero scored output (explore_1, explore_2, experimentator_1). In gen003, 3/5 agents also produced zero output (explore_1, exploit_1, experimentator_1). Despite the architect embedding a milestone protocol in every brief and the gen003 system critic flagging this explicitly (REC-1, REC-4), the failure mode persists.

**Root cause analysis:** The problem is NOT brief quality. The architect's gen004 briefs included explicit milestone instructions ("write sol01 first"), concrete time budgets, and compression-only fallbacks. The problem is that LLM agents do not reliably follow multi-step procedural instructions when context reading is available. explore_1's own debrief admits: "Context reading consumed the entire session. The milestone protocol was not followed."

The systemic issue: agents prioritize reading files over writing code, and by the time they finish reading, they've exhausted their turn budget. This is an inherent property of the agent harness — LLMs default to "understand before acting" and the turn budget doesn't force early action.

**Severity:** Critical. Two generations of 60% failure rate = ~80% of GPU compute wasted on agents that produce nothing.

### PA-2: The experimentator role is broken for this problem (CRITICAL)

**Evidence:** The experimentator has failed 3 consecutive generations (gen002, gen003, gen004) on the same task (fix/update the predictor helper). Zero lines of code produced across all three attempts. Total time wasted: gen002 (1831s) + gen003 (6302s) + gen004 (unknown but at least a full work session).

**Root cause:** The task requires implementing a non-trivial ML component (embedding predictor + beam search wrapper + test harness). The experimentator role template apparently encourages over-scoping — every attempt has tried to build the complete helper module from scratch rather than starting with a minimal working version. The experimentator_1 debrief notes "scope creep is how gen003 experimentator timed out."

**Severity:** Critical. Not only is the helper still broken, but 3 generations of experimentator compute were wasted. The broken helper actively misleads agents that use it.

### PA-3: Score regression for the first time in the run (MODERATE)

**Evidence:** Gen004 best = 44111, which is WORSE than gen003 best = 44094. This is the first generation-to-generation regression. The combined recipe (idea_013), which was the #1 priority for 2 generations, produced a score 17 moves worse than the simpler gen003 approach.

**Root cause:** The embedding MLP (idea_011) + random walk training (depth 50) + MITM + beam_width=4096 produced worse results than the raw integer MLP + compression-only-tail-optimization from gen003. The architecture "fix" actually hurt because: (a) the training data is too shallow regardless of architecture, and (b) the better-training-loss model may generalize differently on out-of-distribution deep states.

**Severity:** Moderate. The regression is small (17 moves, 0.04%), but it signals that the pipeline's strategic direction for the past 2 generations (embedding MLP + beam search) may be insufficient.

### PA-4: No debrief from explore_2 (MODERATE)

**Evidence:** There is no `explore_2.md` in `reports/gen004/`. The agent ran for 1830s (work + wrap_up + debrief phases) but produced zero output and no debrief report. The orchestrator's timing shows wrap_up (11.8s) and debrief (14.3s) — both extremely short, suggesting the session may have crashed or been killed immediately.

**Severity:** Moderate. Total knowledge loss from this agent's session. If it tried anything novel, we'll never know.

### PA-5: Knowledge base accumulating outdated/contradicted claims (MODERATE)

**Evidence:**
1. idea_010 still says "strictly superior to random walks" — evaluator corrected this to "useless as sole training source" but the idea file's summary text may still contain the original claim.

**Severity:** Moderate. Future agents reading the knowledge base will encounter contradictory claims and may waste turns resolving them.

## Missing Capabilities

### MC-1: No mechanism to force agents to produce early output (CRITICAL)

The milestone protocol (REC-1 from gen003) was implemented as LLM instructions in agent briefs. Two agents (explore_1, experimentator_1) ignored it. There is no system-level enforcement — no check that sol01.py exists after 1/3 of the session, no automatic compression-only fallback injection, no orchestrator-level kill-and-retry if no output file appears by a deadline.

**What's needed:** Either (a) an orchestrator-level "first milestone deadline" that kills the session if no `.score` file exists by time T1/3, or (b) a pre-written compression-only sol01.py injected into the workspace before the agent starts, so the agent's first action is to evaluate it and immediately has a scored baseline.

### MC-2: No Cayleypy API reference document (HIGH)

Research_1 spent its entire session reading CayleyPy source code and papers. Every agent that needs the predictor API must do the same exploration. The API is not documented in any helper or knowledge file — agents discover it from idea files (which describe concepts, not APIs) or by reading source.

**What's needed:** A `problems/megaminx/docs/cayleypy_api.md` with the key interfaces: `MlpModel`, `Predictor`, `beam_search` parameters, `bfs` options, `random_walks` modes, and known footguns (`max_layer_size_to_store` default, hasher compatibility, beam_mode='advanced' requiring predictor).

### MC-3: No beam_width > 4096 has ever been tested (HIGH)

pattern_009 states that quality scales log-linearly with beam width. The CayleyPy team uses beam_width=2^20 (1M+). Every agent in 4 generations has used ≤4096. No one has tested 8192, 16384, 32768, or 65536. The single most impactful parameter is unexplored.

**Severity:** High. This is likely the biggest missed opportunity — a 16× beam_width increase may produce more improvement than all architectural changes combined.

## Prompt Problems

### PP-1: Agent briefs instruct "write sol01 first" but agents don't comply (CRITICAL)

**Evidence:** The architect's gen004 briefs included explicit milestone protocol language. explore_1's debrief: "Context reading consumed the entire session. The milestone protocol was not followed." The instruction is present but not followed.

**Root cause:** LLM agents default to understanding context before acting. The brief says "write first" but also provides a long list of files to read. The agent reads the files (because they're listed), gets interested, and never stops reading. The instruction competes with the agent's inherent bias toward comprehension-before-action.

**Fix:** Restructure briefs to physically separate milestones. Brief section 1 = "Write this exact code as sol01.py and evaluate it. Do not proceed to section 2 until sol01.score exists." Brief section 2 = "Now read these files to improve."

### PP-2: explore_1 brief told it to avoid beam_mode='advanced' based on outdated info (MODERATE)

**Evidence:** explore_1's debrief says: "My brief said 'off-limits' based on outdated information." research_1 found that advanced mode works WITH a predictor and quadruples success rate. The SoA listed it as broken. The brief propagated stale knowledge.

**Severity:** Moderate. explore_1 may have produced output if it had been allowed to use advanced mode.

## Experiment Gaps

### EG-1: Beam width sweep — the single most impactful untested experiment (CRITICAL)

No agent has tested beam_width > 4096. The CayleyPy paper is explicit: quality scales log-linearly with beam width. The gap between 4096 and 65536 represents potentially 4× better solutions. This is the cheapest, lowest-risk experiment available — no new architecture, no new training pipeline, just increase one parameter.

### EG-2: MlpModel (one-hot) never tested despite being the library's proven model (HIGH)

research_1 identified in gen004 that CayleyPy's `MlpModel` uses one-hot encoding and achieves 98% optimality on Rubik's. No agent has used it. Every agent has either used raw-integer (broken) or custom embedding (unproven).

### EG-3: Non-backtracking beam search never tested (HIGH)

idea_015 is based on strong paper evidence (4× success rate increase). Never tested. Mutually exclusive with MITM — need to determine which is better.

### EG-4: Path-intermediate training data never tested (HIGH)

idea_016 directly addresses the training data depth bottleneck identified by exploit_1. Theoretical reasoning is strong but zero empirical evidence. This is the gen005 #1 priority per the evaluator.

### EG-5: Long random walks (depth 200-500) never tested (MODERATE)

exploit_1 suggested testing `graph.random_walks(length=200)` as an alternative training data source. The current longest random walks tested are depth 50. Depth 200+ would cover the hard puzzle range (101-300) which is 23.9% of the score.

### EG-6: No head-to-head comparison of training data sources (MODERATE)

Three training data sources exist (BFS depth-6, random walks, path intermediates). No agent has compared them on the same model architecture with the same beam settings. We have anecdotal evidence (BFS useless, RW marginal) but no controlled experiment.
