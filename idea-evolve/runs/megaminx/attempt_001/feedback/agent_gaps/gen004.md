# Agent Gaps — Gen 004

## Systemic Issues

### 1. Experimentator role has failed 3 consecutive generations on the same task

The helper `trained_predictor_beam_search.py` remains broken (raw-integer MLP) because
the experimentator has produced zero output in gen002, gen003, and gen004 on the helper-writing
task. The root cause is that the task was scoped too broadly ("write a complete helper module
with training + predictor + beam search"), causing the agent to timeout during implementation
planning without writing any code.

**Recommendation:** Route this work to an exploit or full agent with instructions to
embed the corrected predictor code INLINE in a solution file, not as a reusable helper.
The helper can be extracted from a working solution in a later generation.

### 2. Three of five agents produced zero scored output

Out of 5 agents: only exploit_1 produced a solution. explore_1, explore_2, and
experimentator_1 produced nothing. This is a 60% agent failure rate, same as gen003.

The common failure pattern: agents spend all turns reading context files before writing any code.
The brief consistently says "write sol01 first" but agents consistently read first.

**Recommendation:** The architect should add an even harder constraint to agent briefs:
"Do not read ANY file before writing sol01.py. Use only this brief. You have permission
to write a simple compression fallback as sol01 before reading ANY context."

### 3. Explore_2 has no debrief report in reports/gen004/

No `explore_2.md` was found in the reports directory. The agent either produced no output
at all and did not write a debrief, or the debrief was lost. Either way, zero knowledge
was extracted from this agent's session.

### 4. MlpModel (one-hot) never used in a solution despite being the library's proven model

Research_1 identified in gen003 that the official CayleyPy approach uses one-hot encoding.
In gen004, exploit_1 still used a custom embedding MLP instead of `MlpModel`. The correct
model has been documented for 1+ generations but never tested in a solution.

**Recommendation:** Gen005 exploit agent brief should explicitly say "use `from cayleypy.models
import MlpModel` — do NOT implement a custom model."

### 5. Beam width is identified as dominant parameter but never increased

pattern_009 (confirmed this gen) explicitly states that solution quality scales log-linearly
with beam width. All solution agents have used beam_width ≤4096. Competitive solutions
use beam_width=65536. This 16× gap has been known since gen004 but not acted on.

**Recommendation:** Require beam_width ≥ 8192 as minimum in gen005. The brief should
include: "beam_width=4096 is known to be 16× too small. Use ≥8192, target 65536 with
batch_size=2048."

## Knowledge Gaps

### 6. No empirical comparison of non-backtracking vs MITM

idea_015 (non-backtracking) and idea_012 (MITM) are mutually exclusive. The paper shows
non-backtracking quadruples success rate, but we don't know how this compares to MITM
specifically on Megaminx. Without a head-to-head test, we can't choose the better option.

### 7. Path-intermediate training (idea_016) never tested

This is now the #1 priority but has 0 data points. We have strong theoretical reasoning
(paths cover depths 1–888, labels correlate with true distance) but no empirical evidence
it actually helps beam search guidance on the hard/very_hard buckets.

### 8. BFS layer 6 decode OOM issue needs investigation

exploit_1 found that layer 6 (17.9M states) OOMs during decode on 16 GB GPU, reducing
usable BFS training data from 19.4M to 1.38M samples. This 14× shortfall contradicts
idea_013's estimated 19.4M training samples. An alternative extraction strategy
(chunked decoding, storing only hashes not full states, or using a different data type)
could recover this training data.

## Missing Helper Tools

From multiple agent reports:
- **`full_pipeline_solver()`**: Encapsulates BFS → train MlpModel → beam search → fallback.
  Every agent re-implements this ~100-line boilerplate. A helper would eliminate repeated
  implementation errors and timeout risk.
- **`extract_path_intermediates(compressed_path, graph)`**: Walks a compressed path and
  extracts (state, remaining_depth) training pairs. Core of idea_016.
- **Updated `cayleypy_beam_solver`**: Should expose `predictor`, `beam_mode`, `bfs_result_for_mitm`,
  and `beam_width` parameters. Currently only supports unguided search.

## What the Next Architect Should Prioritize

1. **Route predictor pipeline to exploit or full agents** — not experimentator. Require sol01
   (compression fallback) be written before any other reading or planning.
2. **Mandate path-intermediate training** (idea_016) as the core experiment for gen005.
3. **Mandate large beam_width** (≥8192, target 65536) — explicitly override 4096 default.
4. **Use `MlpModel` from the library** — explicitly ban custom model implementation.
5. **Do NOT assign helper writing to experimentator** — the role is broken for this task.
