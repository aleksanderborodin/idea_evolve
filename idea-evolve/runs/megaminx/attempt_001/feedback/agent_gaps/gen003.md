# Agent Gaps — Gen 003

## explore_1: Complete Failure — Zero Output

**Gap:** The agent was assigned four exploration directions (CFOP-like phased solving,
A* with landmarks, scramble structure exploitation, multi-phase compression). None were
attempted. All four directions remain entirely unexplored after gen003.

**Root cause:** The agent timed out at all three phases (work/wrap-up/debrief) consuming
~1h 45min with zero recoverable output. No proc_log, no workspace artifacts, no observations.

**Impact:** The system has zero knowledge about whether any of these four directions are
viable. The architect's "Track B radical exploration" was a complete loss.

**Recommendation:** Re-assign scramble structure exploitation (the lowest-risk direction)
to an explore agent in gen004 with a highly constrained brief. Specifically: "For puzzles
with id ≤ 20, try to find paths shorter than sample_submission by exploiting that scramble_depth
== initial_state_id."

## exploit_1: Second Consecutive Failure on Predictor Pipeline

**Gap:** The trained predictor pipeline (idea_008) has now failed to execute in both gen002
and gen003. Two different agents, two different failure modes (gen002: state encoding error,
gen003: total timeout).

**Root cause:** The full pipeline (generate walks → train MLP → wrap in Predictor → beam
search 101 puzzles) is too complex for a single agent session. The agent likely got stuck
on cayleypy API integration details without producing a minimal working version first.

**Impact:** After 3 generations, the trained predictor has been tested once (explore_2 sol01)
with a marginal result (44094). The architecture-corrected version (idea_011) has never been
tested.

**Recommendation:** Assign a staged task: (1) Train embedding MLP on BFS data for 5 minutes,
verify Predictor doesn't crash on 1 puzzle, save as sol01. (2) Run on full proxy with
compression fallback, save as sol02. This ensures at least a partial result.

## experimentator_1: Helper Module Still Broken

**Gap:** The `trained_predictor_beam_search.py` helper still has the wrong model architecture
(raw integer MLP instead of embedding-based). The experimentator was supposed to fix this
in gen003 but produced nothing.

**Root cause:** Same as exploit_1 — complex task, no incremental checkpoints, total timeout.

**Impact:** Every future agent that uses the helper will get a suboptimal predictor. The
helper is actively harmful in its current state because it leads agents toward the wrong
architecture.

**Recommendation:** Either (a) have an experimentator update just the model class in the
existing helper (minimal change), or (b) delete the helper and let agents implement the
correct architecture from scratch guided by research_1's findings.

## research_1: Findings Not Yet Exploited

**Gap:** research_1 produced 10 verified findings with a concrete recipe (idea_013), but
none have been tested in a scored solution. The research is potentially the most valuable
output of the entire run, but it's inert until someone implements it.

**Impact:** If gen004 agents don't read and act on research_1's findings, the breakthrough
is wasted.

**Recommendation:** The gen004 architect must prominently reference research_1's findings
and idea_013 in all briefs. The recipe should be the primary task for at least one agent.

## Systemic Gap: Agent Failure Observability

**Gap:** When agents timeout at all three phases with zero output, there is ZERO forensic
evidence. No proc_logs, no workspace artifacts, no stderr capture. The orchestrator marks
the agent as "complete" (outputs_moved: true) because moving zero files is trivially successful.

**Impact:** Three agent failures in one generation with no diagnostic trail. We cannot
determine whether agents crashed, hung, or just ran out of time. This makes it impossible
to fix the root cause.

**Recommendation:** Add workspace snapshotting at timeout boundaries. Before workspace
cleanup, copy the entire workspace to a diagnostic directory. Also capture the last N lines
of stderr from the agent process.

## Systemic Gap: Description.md Missing from Problem Directory

**Gap:** The problem description file (`problem/description.md`) referenced in the evaluator
prompt does not exist at the expected path. This means the evaluator cannot reference the
official problem specification.

**Impact:** Low — the evaluator has sufficient context from the knowledge base and agent
reports. But agents in previous generations may also have been unable to read the description,
which could explain some implementation errors.

**Recommendation:** Verify the description.md path and ensure it exists for future generations.

## Cross-Agent Knowledge Inconsistency

**Gap:** research_1 found that the cayleypy library has capabilities (MITM, interactive BFS,
nbt random walks) that no other agent or helper module was aware of. The state of affairs
from gen002 didn't mention any of these. Agents were writing beam search code from scratch
when built-in support existed.

**Impact:** Significant — at least 2 generations of agents wasted effort reimplementing
what cayleypy already provides (MITM, Predictor batching, model architecture). The knowledge
lag between research discovery and agent awareness is at least 1 generation.

**Recommendation:** research_1's findings should be rapidly propagated to idea files and
the state of affairs. The gen004 architect must read the updated state of affairs that
includes ideas 010–013.
