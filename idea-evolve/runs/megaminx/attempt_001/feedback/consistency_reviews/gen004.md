## Phase 2: Agent-Reported Doubts

### Doubt 1: "The correct architecture scored WORSE than the wrong architecture"
**Source:** System Critic gen004, exploit_1 gen004

**Investigation:** gen003 raw integer MLP → 44094, gen004 embedding MLP → 44111. The 17-move
regression is real but the explanation is NOT that embedding is worse. The two experiments
differed in multiple dimensions: (1) search strategy (gen003 used tail-only beam search,
gen004 used full-path beam search), (2) training data (gen003 depth-20 random walks, gen004
depth-50 random walks), (3) MITM (gen004 had it, gen003 didn't). The regression is
attributable to different search strategies, not architecture quality.

**Resolution:** RESOLVED. Architecture is not the cause of the regression. Training data
depth and search strategy are the dominant factors.

### Doubt 2: "Path-intermediate training data — explore_2 gen003 got loss ~6000"
**Source:** explore_2 gen003 debrief

**Investigation:** gen003 explore_2 tried training on path intermediate states with raw
integer MLP. Loss was ~6000 (useless). This was before the architecture fix. With correct
encoding (one-hot or embedding), the loss should be much lower. However, the approximate
labels (compressed path length ≠ optimal distance) may still cause issues.

**Resolution:** UNRESOLVED. idea_016's viability depends on whether correct architecture
solves the loss-6000 problem. The raw integer encoding was the primary failure cause, but
approximate labels add noise. **Flagged in Open Questions.** The experiment MUST be re-run
with MlpModel or embedding architecture before drawing conclusions.

### Doubt 3: "idea_010 (BFS superiority) was actively misleading for 2 generations"
**Source:** System Critic gen004

**Investigation:** The claim was based on theoretical reasoning (exact labels > noisy labels)
without empirical validation. When tested (gen004 exploit_1), BFS-only data produced a
predictor that predicts every state as ~4. The theoretical reasoning failed because it
didn't account for distribution coverage (BFS covers depth 0-6, puzzles need depth 0-1000).

**Resolution:** RESOLVED. idea_010 file already updated with the refutation. Confidence
needs adjustment (see above).

### Doubt 4: "Experimentator has failed 3 consecutive generations — role is broken"
**Source:** System Critic gen004, experimentator_1 gen004, evaluator gen004

**Investigation:** gen002 experimentator → zero output. gen003 experimentator → zero output.
gen004 experimentator → zero output. The task (write embedding_predictor_beam.py helper)
has been assigned 3 times and failed 3 times. The brief quality improved each time (more
detailed, milestone protocol) but the outcome didn't change.

**Resolution:** RESOLVED. This is a systemic pipeline problem, not a brief problem. The
architect must stop assigning helper-writing to the experimentator role. Either assign to
a full/explore agent (with inline code), or skip the helper entirely and have agents write
the predictor code inline in solutions.

### Doubt 5: "Non-backtracking beam search may be incompatible with MITM"
**Source:** research_1 gen004, idea_015

**Investigation:** idea_015 states they are mutually exclusive in CayleyPy's implementation.
idea_012 documents the MITM approach. Both are well-documented.

**Resolution:** RESOLVED (documented constraint). Agents must choose one. Priority question:
which provides more benefit for very_hard puzzles? Flagged as an open question.

### Doubt 6: "beam_mode='advanced' was listed as broken in SoA but actually works with predictor"
**Source:** explore_1 gen004

**Investigation:** Previous SoA listed advanced mode as problematic (returns path=None).
research_1 gen004 analyzed source code and found it requires a predictor. Without one, it
silently fails. With a predictor, it implements non-backtracking with 4x success rate.

**Resolution:** RESOLVED. Previous understanding was incomplete (not broken, just requires
predictor). idea_015 captures the corrected understanding.
