## 2. Contradictions and Inconsistencies

### 2.1 Brief vs reality: target score discrepancy
- **Report**: explore_1, explore_2
- **Issue**: The brief mentions target 624, but the theoretical upper bound is 926 and the known lower bound is 616. The brief's target is unmotivated.
- **Impact**: Low — agents correctly identified the true situation.
- **Resolution needed**: Update brief template to clarify the gap between known bounds.

### 2.2 GA crossover operator is fundamentally destructive
- **Report**: explore_2 (sol03 crashed), evaluator analysis
- **Issue**: The union+prune crossover loses too many codewords due to pairwise incompatibility. This is not just an implementation bug — the operator design is flawed.
- **Impact**: High for genetic approach — current GA cannot work.
- **Resolution needed**: Redesign crossover at orbit level or use a compatibility-preserving operator.

### 2.3 compatible_mask naming confusion
- **Report**: explore_1
- **Issue**: The compat.py docstring example shows a function named `compatible_with_code` but the actual function is `compatible_mask`. The docstring is misleading.
- **Impact**: Low — agents found and used the correct function anyway.
- **Resolution needed**: Fix docstring example to match actual function name.

## 4. Pipeline Issues

### 4.1 Two solutions crashed due to bugs
- **Report**: evaluator
- **Issue**: GA crashed (dtype error in `np.array([])` indices), ILNS timed out (greedy logic error returning all 40320 perms).
- **Impact**: Wasted evaluation cycles.
- **Resolution needed**: Agents should do basic sanity checks (code size sanity test) before submitting.

### 4.2 No feedback loop from evaluator to agents
- **Report**: All agents
- **Issue**: Agents produced solutions without knowing what other agents tried. No shared knowledge during the generation.
- **Impact**: Some redundant experiments (multiple AGL baseline implementations).
- **Resolution needed**: The orchestrator's knowledge dump should include current generation's partial results.

### 4.3 GA implementation lacked robustness
- **Report**: explore_2
- **Issue**: `np.array([])` defaulting to float64 dtype caused IndexError. No validation before evaluation.
- **Impact**: One solution completely wasted.
- **Resolution needed**: Add dtype specification in array construction.

## 5. Helper Tool Issues

### 5.1 Missing: find_codeword_indices helper
- **Report**: research_1
- **Issue**: `fast_compatible_mask` requires indices into `all_perms`, but no helper exists to map a code back to those indices. Agents had to build custom workarounds.
- **Action needed**: Add `find_codeword_indices(code, all_perms)` helper or make `fast_compatible_mask` accept code arrays directly.

### 5.2 GA crash on empty list
- **Report**: explore_2, evaluator
- **Issue**: `make_code_compatible` received `[]` → `np.array([])` → dtype=float64 → used as indices → crash.
- **Action needed**: Add `dtype=int` to all `np.array()` calls where the result may be empty and is used as indices.
