## E1 (CRITICAL): PGL(2,7) Orbit Clique Search

**What**: Implement PGL(2,7) as permutations of {0,...,7} using Möbius transformations over GF(7)∪{∞}: x → (ax+b)/(cx+d) for a,b,c,d ∈ GF(7), ad-bc ≠ 0. This gives 336 distinct transformations. Partition S₈ into 120 orbits of 336 perms each. Build 120×120 compatibility graph. Run max-clique search.

**Why**: AGL(1,8) is at its limit (11 orbits = 616). PGL(2,7) is a different 2-transitive action on 8 points with fundamentally different orbit structure (120 orbits vs 720). If PGL's orbit compatibility graph yields a clique of >11 orbits, we beat 616 with a new construction.

**How to implement**:
```python
# PGL(2,7) elements as permutations
def pgl27_elements():
    GF7 = list(range(7))
    infinity = 7
    elements = []
    for a in GF7:
        for b in GF7:
            for c in GF7:
                for d in GF7:
                    if a*d - b*c != 0:  # ad - bc ≠ 0
                        # Möbius transformation: x → (ax+b)/(cx+d)
                        perm = []
                        for x in GF7 + [infinity]:
                            if c*x + d == 0:
                                perm.append(a/c)  # → ∞ when cx+d=0
                            else:
                                perm.append((a*x + b) / (c*x + d))
                        elements.append(tuple(perm))
    return list(set(elements))  # dedupe — should be 336
```

**Expected time**: <10 minutes for full pipeline.

**Expected information gain**:
- If max clique > 11 orbits: new lower bound > 616, immediate improvement, path to 926 visible
- If max clique ≤ 11 orbits: PGL orbit structure is not helpful alone; cross-group becomes more interesting
- Either way: eliminates PGL as unknown, informs next strategic decision

**Assigned to**: full or experimentator agent. Not research — research completed in gen 1.

## E2 (CRITICAL): Compatible Permutation Count for 616-Code

**What**: Run `fast_compatible_mask()` on the full 616-code to count how many of the 39,704 non-orbit permutations are compatible with all 616 codewords.

```python
code = agl18_max_clique_code()  # 616 codewords
all_perms = build_all_perms(8)
bids = build_bucket_ids(all_perms)
# Find indices of code in all_perms (needs helper or workaround)
code_indices = find_codeword_indices(code, all_perms)
compatible_mask = fast_compatible_mask(code_indices, bids)
extra_count = compatible_mask.sum() - 616
print(f"Extra compatible permutations: {extra_count}")
```

**Why**: This is the single most important binary fact for strategy selection. If there are extendable permutations, SA/VNS approaches from the 616-seed are viable. If zero, those approaches are waste of time and PGL is mandatory.

**Expected time**: <5 seconds.

**Expected information gain**:
- If extra_count > 0: SA/VNS have something to work with. The 616-code is not a dead end.
- If extra_count = 0: the 616-code is truly isolated. SA/VNS will not help. PGL is the only path.

**Assigned to**: Any agent as a prerequisite experiment before running SA/VNS. Also serves as diagnostic for the entire search space structure.

## E3 (HIGH): Cross-Group PGL × AGL Clique Search

**What**: Build a mixed compatibility matrix between 120 PGL orbit representatives and 720 AGL orbit representatives. Run max-clique search on this mixed graph — selecting orbits from both groups simultaneously.

**Why**: Even if PGL alone maxes at ≤11 orbits, a mixed clique combining PGL and AGL orbits could be larger than either group's standalone maximum. The compatibility between groups is unknown and could be favorable.

**Expected time**: <30 minutes (the cross-group compat matrix is 120×720 = 86,400 pairs to check, each check is 336×56 Hamming distances, but the bucket method makes it fast).

**Expected information gain**:
- If mixed clique > max(PGL-only, AGL-only): proof that multi-group construction dominates single-group
- If mixed clique = max of either: cross-group doesn't help; PGL structure is key
- Either way: informs whether to pursue combined group constructions

## E4 (HIGH): VNS from 616-Code Seed

**What**: Variable Neighborhood Search with structured removal neighborhoods:
1. Start from 616-code
2. Remove k% of codewords (k ∈ {1, 5, 10, 20, 50})
3. Run greedy clique extension on residual compatible set
4. Accept improvement if found, otherwise try next k
5. Iterate 100 times

**Why**: Systematic neighborhood search. The 500-iteration perturbation in gen 1 used random destroy fractions. VNS uses predefined structured neighborhoods that may find what random perturbation missed.

**Expected time**: <30 minutes.

**Expected information gain**:
- If VNS finds code > 616: first improvement over known lower bound, proof that the 616-code is not a global optimum in the full permutation space
- If VNS consistently returns 616: confirms the 616-code is extremely robust, no "nearby" improvement exists without changing group structure

## E5 (MEDIUM): Bron–Kerbosch on AGL Orbit Graph (Optimality Proof)

**What**: Implement Bron–Kerbosch with degeneracy ordering on the 720-vertex AGL orbit graph to prove 11 is the maximum clique size.

**Why**: Greedy found 11 orbits consistently. But greedy doesn't prove optimality. If we want to know whether 616 is truly the AGL bound or whether a larger AGL clique exists, we need an exact algorithm. The 720-vertex graph with degree 138 is challenging but manageable for branch-and-bound.

**Expected time**: Unknown — could be seconds or hours depending on graph structure. The regularity (all vertices degree 138) suggests the bound might be provable quickly.

**Expected information gain**:
- If 11 is proven maximum: AGL direction is fully closed. No more compute should go to AGL orbit search.
- If >11 found: immediate improvement to known lower bound. (Unlikely given 720/720 exhaustive search, but worth confirming.)

## E6 (MEDIUM): Simulated Annealing from 616-Code

**What**: SA with swap-move operator starting from 616-code:
- Move operator: swap one codeword for a compatible permutation (not add/remove — stability)
- Temperature schedule: geometric cooling from T₀ ≈ 0.1-0.5, factor 0.995-0.999
- Acceptance: exp(-delta/T) for worse solutions
- Run for fixed time budget (e.g., 5 minutes), track best found

**Why**: SA can escape local optima that VNS/ILNS miss. The 616-code is a strong local optimum; SA's probabilistic acceptance of worse solutions may find paths out.

**Expected time**: <10 minutes.

**Expected information gain**:
- If SA finds > 616: confirmation that the orbit-clique optimum is not the global optimum in full space
- If SA stays at 616: further confirmation that group structure change (PGL) is necessary
