# Megaminx — solve 1001 scrambled states optimally

Kaggle competition: [`cayley-py-megaminx`](https://www.kaggle.com/competitions/cayley-py-megaminx)
(Class A — see [docs/problem_design_guide.md §13](../../../docs/problem_design_guide.md)).
Local score = Kaggle score (self-checking metric).

## Task

Given 1001 scrambled Megaminx states (length-120 permutations), produce a
sequence of moves that returns each state to the solved (central) state.
Score = sum of path lengths over all puzzles. **Lower is better.**

**Important structural fact** (validated on downloaded data): `test.csv` was
generated by random walks from the solved state. The notebook `cayleypy-
megaminx-first-steps.ipynb` confirms, and data inspection verifies, that
**scramble depth equals `initial_state_id`** for ids 1..1000 (id 0 is a
special 72-move outlier). This is a massive prior — agents don't need to
estimate scramble depth, they can read it off the id.

Every `sample_submission.csv` path is the inverse of the walk that generated
the scramble, so it is a **guaranteed-valid** (not optimal) path. Submitting
sample_submission verbatim is the free floor: valid everywhere, but path
length == depth on every row.

Anchors (full-set scores):

- sample_submission submitted verbatim: **500,572** (the zero-search floor).
- baseline_cayleypy (unguided beam search): ~400k–500k; fails on deep rows.
- Our target: **150,000** (≈ 10× improvement over sample_submission).
- Kaggle top-3: **80,499** (≈ 80 moves/puzzle — stretch, requires trained predictor).

## Puzzle representation

A Megaminx state is a tuple of 120 ints, each in `0..119`. The solved state
is `(0, 1, 2, ..., 119)`. A move is a named permutation; applying a move to
state `s` produces `s' = (s[perm[0]], s[perm[1]], ..., s[perm[119]])`.

24 generators: `U, -U, D, -D, F, -F, B, -B, L, -L, R, -R, DR, -DR, DL, -DL,
FR, -FR, FL, -FL, BR, -BR, BL, -BL`. `-X` is the inverse of `X`. The
authoritative list is `helpers.core.GENERATOR_NAMES`.

A path is a dot-joined string of move names: `"U.F.-R.DL"`. Empty string =
no moves.

## Solution format

```python
def entrypoint() -> dict[int, str]:
    from helpers.core import load_test, cayleypy_beam_solver
    tests = load_test(proxy=True)
    return {
        sid: (cayleypy_beam_solver(state, beam_width=512, max_steps=80) or "")
        for sid, state in tests.items()
    }
```

`entrypoint()` returns `{initial_state_id: dot_joined_path}`. Missing keys
or paths that don't actually solve the puzzle contribute the per-row sentinel
(1,000,000) to fitness; one bad row drops `is_valid` to 0 and adds 1e6 to
the total.

## Local evaluation

`evaluate.py` does:

1. AST validate that `entrypoint` exists.
2. SHA-256 the solution file → cache lookup. Same bytes = same score
   (instant return).
3. Call `entrypoint()` → get `{sid: path}`.
4. For each test puzzle: validate every move name; apply path; check final
   state == solved. Score the row.
5. Sum per-row scores → primary fitness. Aux metrics:
   `avg_path_length, solved_count, expected_count, invalid_count`.

```
python3 evaluate.py path/to/solution.py            # default: proxy 100 puzzles
python3 evaluate.py --full path/to/solution.py     # operator-only: full 1001
```

## Proxy vs full

- **Proxy** (`load_test(proxy=True)`, the default): **stratified 1/10 slice** —
  every 10th id from 0 to 1000, so ids `[0, 10, 20, ..., 1000]` (101 puzzles).
  Because depth == id, this preserves the full depth distribution at 1/10
  scale (50 very_hard, 40 hard, 8 medium, 2 short, plus id 0).
  Proxy fitness extrapolates to full by ~10×.
  **Previous "first-100" proxy was replaced** — it contained zero depth > 99
  puzzles, masking the actual failure regime.
- **Full** (`load_test(proxy=False)`): all 1001 puzzles. What Kaggle scores.

Baseline eval times (beam_width=512, max_steps=80 cayleypy on 5060 Ti):

| Mode | Puzzles | Approx wall-clock |
|---|---:|---:|
| Proxy | 101 | ~7 min |
| Full | 1001 | ~70 min |

The solution itself picks the mode by passing `proxy=True/False` to
`load_test`. `evaluate.py` exposes `--full` as an operator override (the
cache key incorporates the mode so proxy and full results don't collide).

**Score scale.** All `metrics.yaml` numbers (`target_score`, `lower_bound`,
`upper_bound`, `significant_change`) are in **proxy units**. Proxy ≈ full/10
by construction (not the bogus ×10.01 linear extrapolation that the previous
first-100 proxy assumed — that was off by an order of magnitude).

## Metrics reported per eval

Every evaluation writes a `.score` sidecar with:

**Primary**

- `fitness` — sum of path lengths on the evaluated subset. Missing/invalid rows
  contribute `SENTINEL_ROW_SCORE = 1,000,000` each. **Lower is better.**
- `is_valid` — 1 iff every expected row has a valid solving path.

**Core counts**

- `solved_count`, `expected_count`, `invalid_count`, `avg_path_length`.

**Diagnostic distribution stats** (over *solved* rows only, to avoid
sentinel pollution):

- `compression_ratio` — `fitness / sum(sample_submission lengths)` on the
  same subset. **The single-number KPI**: 1.0 = echoing the zero-search
  freebie, <1.0 = real optimization, Kaggle top-3 ≈ 0.16.
- `improved_count` — rows where our path is strictly shorter than
  `sample_submission[sid]` (which equals depth for ids 1..1000).
- `max_path_length`, `p50_path_length`, `p95_path_length` — distribution
  shape. `max_path_length` of 1000 means we're falling back to the freebie
  on the deepest row; a bounded max means search has a real horizon.

**Per-depth-bucket breakdowns.** Five buckets mirror the full-set depth
distribution:

| Bucket | IDs | Full #puzzles | Proxy #puzzles | What it tests |
|---|---|---:|---:|---|
| `special` | 0 | 1 | 1 | The 72-move outlier |
| `short` | 1–25 | 25 | 2 | Shallow — any predictor should ace these |
| `medium` | 26–100 | 75 | 8 | Unguided beam's sweet spot |
| `hard` | 101–500 | 400 | 40 | Requires a learned predictor or MITM |
| `very_hard` | 501–1000 | 500 | 50 | Dominates the score |

Each bucket records `count`, `fitness`, `solved`, `invalid`. In prompts, the
four non-special buckets surface `fitness` + `solved` so agents see *where*
they're losing score. All bucket fields land in the `.score` sidecar for
dashboards regardless.

**Timing.** `eval_time_s`, `eval_started_at`, `eval_ended_at` are always
written (see CLAUDE.md "Evaluation time tracking — always on").

## Reproducing a scored solution

This problem has no stochastic training, so **the cache hash IS reproduction**.
Identical bytes → identical score, deterministically. To re-verify a
specific solution:

```
rm runs/megaminx/<attempt>/history/eval_cache.json   # or just delete the one entry
python3 evaluate.py path/to/solution.py
```

If a solution's `entrypoint()` uses non-deterministic randomness (e.g.
`random.choice` without a seed), score will drift between runs — agents must
seed RNGs explicitly.

## Available helpers

See [`helpers/README.md`](helpers/README.md). Key symbols:

- `load_puzzle_info()` — parse `data/puzzle_info.json`.
- `load_test(proxy: bool)` — return `{sid: state_tuple}` (stratified 101 or full 1001).
- `load_sample_submission_lengths()` → `{sid: int}` — Kaggle's free-baseline path
  lengths (cached). Equals scramble depth for ids 1..1000.
- `load_sample_submission_paths()` → `{sid: dot_joined_path}` — the actual free
  baseline move strings. Use as a guaranteed-valid fallback.
- `solved_state()`, `is_solved(state)`.
- `apply_move(state, name)`, `apply_path(state, path)`.
- `score_path(initial, path)` → `(length, valid)`.
- `score_predictions(predictions, proxy=True)` → `(fitness, is_valid, aux)`.
  `aux` now includes the per-bucket breakdown and all diagnostic stats —
  see "Metrics reported per eval" above.
- `depth_bucket(sid)` → `"special" | "short" | "medium" | "hard" | "very_hard"`.
- `cayleypy_beam_solver(state, beam_width, max_steps)` — lazy-imports
  cayleypy + torch; no pretrained predictor exists, so the search is unguided.
- `GENERATOR_NAMES`, `STATE_SIZE`, `PROXY_SIZE` (101), `PROXY_STRIDE` (10),
  `FULL_SIZE` (1001), `SENTINEL_ROW_SCORE`, `BUCKETS`, `BUCKET_NAMES`.

## Hardware + concurrency

- GPU available (RTX 5060 Ti, CUDA 12.8 via torch 2.11.0+cu128) with NVIDIA MPS
  daemon enabled so concurrent evals share the device without time-slicing.
- `metrics.yaml: concurrency: 3` — up to 3 agents may evaluate simultaneously.
  The architect sizes `parallel_groups` to ≤ 3; the orchestrator auto-splits
  anything larger. No physical GPU lock in evaluate.py — memory-bound sharing
  is enforced by MPS, and the numeric budget prevents over-subscription.
- cayleypy requires torch; CPU torch is fine. Install:
  `pip install torch --index-url https://download.pytorch.org/whl/cpu` then
  `pip install cayleypy`.
- If a solution wants GPU-trained predictors, that needs DESIGN-18 (resource
  pools) to land first — see CLAUDE.md.

## Sentinels

- Per-row: `SENTINEL_ROW_SCORE = 1_000_000` (in `helpers.core`).
- Overall: `metrics.yaml:fitness.sentinel_value = 1_000_000_000` (1e9).
  Used when `evaluate.py` itself raises (import error, syntax error, etc.)
  rather than per-row. Filter in `orchestrator.update_rankings` is
  `score >= sentinel * 0.9` so 1e9 leaves a 3-orders buffer above any real score.
