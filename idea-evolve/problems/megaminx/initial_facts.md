# Megaminx puzzle basics

- The puzzle is a dodecahedron (12 pentagonal faces, 11 cells each minus the
  center, encoded as a length-120 permutation of `0..119`).
- 24 named generators, declared in `helpers.core.GENERATOR_NAMES`:
  `U, -U, D, -D, F, -F, B, -B, L, -L, DR, -DR, BL, -BL, FR, -FR, BR, -BR, FL, -FL, R, -R, DL, -DL`.
- `-X` is the inverse of `X`. Kaggle's puzzle_info.json defines both as
  separate generators (so search graphs use 24-out branching, not 12).
- Solved (central) state is `(0, 1, 2, ..., 119)`.
- A path is a dot-joined string of move names: `"U.F.-R.D"`. Empty string =
  no moves applied.

# Kaggle competition `cayley-py-megaminx`

- 1001 test puzzles (`initial_state_id` 0..1000). Score = sum of path lengths.
- **Lower is better.**
- Public leaderboard top: **80,499** (Vladislav Kuznetsov, 2026-04-15) ≈
  80.4 moves/puzzle average. Top-3: 80499, 89670, 93606. Then a gap to
  ~413k (greedy/baseline tier), then ~500k (random-walk floor).
- Class A: test set is downloaded; metric is self-checking (apply path,
  compare to central state). Local score = Kaggle score perfectly.
- No pretrained predictor exists in cayleypy 0.1.0 for the Megaminx graph.
  `Predictor.pretrained(graph)` raises `KeyError`. Top scores were achieved
  with custom predictors trained on random-walk data, hand-tuned heuristics,
  or meet-in-the-middle.
- **cayleypy version pinning.** `requirements.txt` pins `cayleypy>=0.1,<1.0`.
  Helpers assume the 0.1.x API (`Puzzles.megaminx()` returns a `CayleyGraphDef`,
  `CayleyGraph(gdef).beam_search(...)` accepts the kwargs in `helpers.core.cayleypy_beam_solver`).
  If a 0.2.x release changes signatures, re-test before bumping.

# Search complexity

- Naive BFS branching factor: 24. Depth-D BFS visits ≤ 24^D states.
  D=10 ≈ 6e13. D=15 ≈ 2e20. Untenable past depth ~7.
- God's number for Megaminx is unknown. Conjectured upper bound ~45 in the
  half-turn metric (literature varies; treat as approximate).

(Solution approaches that exploit these limits — beam search, meet-in-the-middle,
pattern databases — live in `initial_ideas.md`, not here.)

# Scramble depth == initial_state_id

The Kaggle `test.csv` was generated by random walks of length `N` from the
solved state, stored under `initial_state_id = N`. Equivalently, the
corresponding `sample_submission.csv[sid]` is the *inverse* of the walk
used to scramble row `sid`, so `len(sample_submission[sid].split(".")) ==
scramble_depth(sid)` exactly. Verified against the downloaded data:

- For ids `1..1000`: `sample_submission_len(id) == id` for all 1000 rows.
- `id == 0` is the special outlier: 72-move scramble.

**Implications for agents:**

1. No need to *estimate* scramble depth — read the id.
2. Any puzzle whose depth > your search's reach should fall back to
   `sample_submission[sid]` (always valid, length = depth = id).
3. The proxy is **every 10th id** — so each depth bucket is 1/10 populated
   vs the full set, and proxy scores extrapolate to full by ~10×.
4. A random-walk scramble of length N has expected true optimal distance
   ≤ N (often strictly less due to cancellations). So sample_submission is
   an *upper bound* on the optimum, never tight. There's always headroom.

Helper: `helpers.core.load_sample_submission_lengths()` returns `{sid: len}`
(cached); `load_sample_submission_paths()` returns `{sid: dot_joined_path}`
for the full strings.

# Scoring + sentinels

- Per-row score: `len(path.split("."))` if the path applied to `initial_state`
  reaches `solved_state`. Otherwise `SENTINEL_ROW_SCORE = 1_000_000`.
- Overall sentinel (whole solution failed): `1_000_000_000` (1e9). See
  `metrics.yaml:fitness.sentinel_value` and `docs/problem_design_guide.md` §13.10.
- `is_valid = 1` only if EVERY expected row had a valid solving path. One bad
  row → `is_valid = 0` AND fitness gets penalized per-row, NOT clamped to
  the overall sentinel.
- Auxiliaries in `.score` sidecars (also visible in dashboard):
  - **Core:** `avg_path_length`, `solved_count`, `expected_count`, `invalid_count`.
  - **Diagnostics:** `compression_ratio` (`fitness` / `sum(sample_submission)`
    on the same subset; 1.0 = echoing the freebie, < 1.0 = real search gain),
    `improved_count` (rows strictly shorter than sample_submission),
    `max_path_length`, `p50_path_length`, `p95_path_length` (all over
    SOLVED rows only — sentinels don't pollute the distribution stats).
  - **Per-bucket** (`{special, short, medium, hard, very_hard}`):
    `bucket_<name>_{count, fitness, solved, invalid}`. Buckets split by id
    range; see `helpers.core.BUCKETS`.

# Score anchors (what's easy, what's ambitious)

Validated on the downloaded data (Apr 2026). Numbers in **proxy units**;
multiply by ~10 for the full Kaggle-set equivalent.

| Solution | Proxy fitness | Full fitness | Notes |
|---|---:|---:|---|
| `baseline_random` | 101,000,000 | 1,001,000,000 | Sentinel everywhere. Our floor. |
| `sample_submission` verbatim | **50,572** | **500,572** | Zero-search freebie. Valid everywhere. `compression_ratio = 1.0`. |
| `baseline_cayleypy` (unguided beam, width 512, steps 80) | ~40,000–50,000 | ~400k–500k | Solves shallow, sentinels deep. Beats sample_submission only narrowly. |
| Reasonable improvement | 20,000 | 200,000 | `compression_ratio ≈ 0.4`. Requires actual search working on medium/hard buckets. |
| **Target (ambitious)** | **15,000** | **150,000** | `compression_ratio ≈ 0.3`. Realistic with a trained predictor. |
| Stretch (top-10 Kaggle) | 9,000 | 90,000 | `compression_ratio ≈ 0.18`. Predictor + MITM territory. |
| Kaggle top-3 | 8,050 | 80,499 | Hand-tuned, state-of-the-art. |

Any solution scoring > 50,572 proxy is worse than doing nothing. Every
evaluation should include a sanity check: if you can't beat sample_submission,
return sample_submission (preserves the floor).

# Hardware + concurrency (current env: 2026-04-16)

- **GPU**: NVIDIA RTX 5060 Ti (Blackwell, 16 GB VRAM, CUDA 12.8 via
  torch 2.11.0+cu128). cayleypy's beam search offloads to CUDA when available.
- **MPS** (Multi-Process Service) is enabled: multiple `evaluate.py` processes
  share the GPU with true kernel concurrency, no time-slicing overhead.
  `CUDA_MPS_PIPE_DIRECTORY=/tmp/nvidia-mps` must be in the launch env (loaded
  from `.env` before the orchestrator starts).
- `metrics.yaml: concurrency: parallel` — agents may call `evaluate.py`
  simultaneously without a GPU lock.
- **Per-eval budget** (proxy, stratified 101 puzzles): ~7 min with the
  cayleypy baseline; varies widely with beam_width × max_steps. Full-set
  (`--full`) eval is ~70 min.
- If a solution wants to train its own predictor, staying under the eval
  wall-clock budget is the solution's problem — spend most of the budget on
  very_hard rows, not short ones.
