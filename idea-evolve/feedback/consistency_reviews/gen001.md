## Phase 2: Agent-Reported Doubts

### Doubt 1: vpternlogd truth table discrepancy (Evaluator, Research)
**Issue:** Research agent derived 0xCA/0xAC, explore_1 used 0xD8/0xE4. Both pass correctness checks.
**Investigation:** The difference is operand order in `_mm512_ternarylogic_epi64(a, b, c, imm8)`.
If you swap which operand is a_pos vs a_neg vs b, the truth table changes accordingly. Both
are correct for their respective operand orderings.
**Resolution:** RESOLVED — not a bug, just different conventions. However, this remains a
footgun for future agents mixing conventions. Noted in idea_011 and surfaced in Open Questions
as a documentation priority.

### Doubt 2: Baseline score accuracy (System Critic, Evaluator)
**Issue:** Baseline ~770 µs but first AVX-512 solutions already beat it significantly.
**Investigation:** The baseline uses AVX2 with a 6-instruction LUT popcount. AVX-512 with
hardware `vpopcntb` is a fundamentally different instruction set. A 1.2-5x improvement from
ISA upgrade is expected. The baseline score is the V14opt AVX2 score, not the theoretical
minimum — there's no contradiction.
**Resolution:** RESOLVED — baseline is correct. The large improvement reflects the magnitude
of the AVX2→AVX-512 upgrade for this workload, not a measurement error.

### Doubt 3: explore_2 timeout/failure (System Critic)
**Issue:** explore_2 produced 0 solutions, spent entire session reading files.
**Investigation:** This is a pipeline efficiency issue, not a knowledge consistency issue.
The agent's debrief confirms it had enough information to write code but ran out of time.
**Resolution:** NOTED — not a knowledge error. Recommend explore agents start writing code
earlier. The State of Affairs should note that 25% of gen 1 agent capacity was wasted.

### Doubt 4: fact_004 instruction latencies (Evaluator, full_1, Research)
**Issue:** `vpmovzxbd` 3c latency and other values may be inaccurate for Tiger Lake.
**Investigation:** These are from user-provided facts, not empirically measured. Solutions
work correctly regardless because the values are used for reasoning, not computation.
**Resolution:** UNRESOLVED — needs `perf stat` measurement to verify. Surfaced in Open Questions.

### Doubt 5: NC=512 regression root cause (All agents)
**Issue:** NC=512 consistently slower but nobody knows why.
**Investigation:** This is the most consistently flagged open question across all reports.
5 data points confirming the pattern, 0 explanations. Cache conflicts, TLB pressure, and
alignment issues are hypothesized but unverified.
**Resolution:** UNRESOLVED — needs hardware profiling (`perf stat` with cache/TLB counters).
Surfaced in Open Questions as top priority for gen 2.
